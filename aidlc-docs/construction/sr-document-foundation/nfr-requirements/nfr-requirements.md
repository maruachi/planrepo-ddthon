# U1 비기능 요구사항

상태: NFR 산출물 Q1 B 승인 완료. 사용자 채팅 “승인 후 진행”으로 승인했다. 아래 구체 설정·용량은 이번 NFR 검토에서 승인된 제안이다. 구현·성능 실측 결과가 아니다.

근거: [원본 NFR-01–06](../../../inception/requirements/requirements.md), [U1 업무 규칙](../functional-design/business-rules.md), [화면 설계](../functional-design/frontend-components.md), [평가 계획](../../plans/sr-document-foundation-nfr-requirements-plan.md), [기술 선택](tech-stack-decisions.md).

## 실행 환경과 범위

로컬 macOS에서 한 사용자가 브라우저와 앱 서버를 실행한다. 작성자·리뷰어는 동일 사용자의 시연 역할이다. 앱 서버 하나가 SQLite 저장소 하나와 UI를 제공하며 후속 CLI는 같은 장비에서 기존 인증으로 실행한다. 외부 네트워크 없이 U1의 입력·문서·이력 기능을 사용할 수 있어야 한다. 최초 의존성 설치와 U2 AI 생성은 별도의 네트워크 의존이다.

이번 조사에서 Node v24.7.0과 npm 11.5.1, claude 실행 파일 경로를 확인했다. 브라우저 버전, 패키지 설치, SQLite 바인딩, CLI 인증·호출 성공은 미검증이다. 앱의 실행 기준은 Node 24 계열로 제안하고 실제 호환 버전은 구현 시 기록한다.

## 지원 용량과 성능의 제안

다음 값은 사용자가 과거에 합의한 수치가 아니라 MVP에서 예측 가능한 입력 처리를 위한 이번 NFR 제안이다.

| 항목 | 제안 | 동작·검증 |
|---|---|---|
| SR 제목·문서 표시 제목 | UTF-8 기준 각각 최대 4 KiB | 제목 필수 규칙 유지, 초과 시 명시적 오류 |
| 요구 설명·선택 첨부·문서 본문 | UTF-8 기준 각각 최대 1 MiB | 한글·끝 개행 보존, 빈 첨부/사람 편집의 빈 본문 허용 유지 |
| U1 JSON 요청 본문 | 최대 16 MiB | 설명과 첨부의 JSON 이스케이프 팽창을 포함할 여유. 파싱 후 개별 필드 상한도 검사 |
| 저장 SR·버전·사건 개수 | 인위적 삭제/보존 기간 제한 없음 | 실제 로컬 디스크 용량에 의존. 용량 부족은 저장 실패이며 기록 자동 삭제 없음 |
| 성능 점검용 데이터 | SR 20개, 각 문서 5개, 문서별 버전 10개, 일반 본문 약 10 KiB | 관찰용 준비 데이터 규모이며 보장 한도·실측 성능 아님 |
| 큰 본문 점검 | 허용 상한 본문 2개, 반복 줄·전체 변경·끝 개행 | 저장·재열람·비교를 확인. 긴 비교의 완료/대기 및 앱 조작성 기록 |

수치 지연시간·처리량·uptime SLA는 합의하지 않았으므로 새 보장으로 만들지 않는다. 구현 시 점검 입력과 실행 환경, 보드/상세/저장/비교에서 관찰한 지연을 기록하고 사용 흐름을 막는 정지·누락을 해결한다. 장시간 CLI 때문에 서버 응답이나 저장 트랜잭션을 붙잡는 방식은 허용하지 않는다.

동기식 SQLite 작업은 작은 조회/짧은 커밋에 제한한다. 큰 비교의 계산 제한과 비동기 처리 방법은 NFR Design에서 정한다. 상세 diff가 계산 한도를 넘으면 전체 왼쪽 줄 삭제/오른쪽 줄 추가를 표시하는 보수적 비교로 완료할 수 있으나 “간략 비교”임을 알리고 본문을 누락하지 않는다. 변경 없음이나 잘린 diff를 완전한 결과처럼 반환하지 않는다. 검증에서 이 방식도 사용 흐름을 막으면 처리 방식을 개선한다.

이력은 자동 삭제하지 않는다. 데이터가 늘 때는 해당 문서·버전만 읽고, 목록을 나누어 읽는 방법을 NFR Design에서 정한다. 목록의 일부만 읽었으면 추가 조회를 제공하고 전체 목록인 것처럼 표시하지 않는다.

## 가용성·복구·저장 위치

제안 기본 DB는 앱 루트 기준 .planrepo/planrepo.sqlite이다. 실행 위치가 달라도 같은 앱 루트를 기준으로 해석해야 한다. 개발/빌드 산출물 정리가 DB를 삭제하지 않아야 하며 테스트는 별도 임시 DB를 사용한다. 대체 위치는 서버 설정으로만 지정하고 브라우저 요청에서 경로를 받지 않는다.

앱 재시작 후 이미 커밋한 기록은 유지한다. 실패한 커밋은 일부만 노출하지 않는다. 응답을 받지 못해 결과가 불확실하면 현재 SR/버전/사건을 다시 확인하고 동일 저장을 무조건 자동 반복하지 않는다. 요청 추적과 재조회 표시는 NFR Design에서 구체화한다.

손상된 기존 DB를 빈 DB로 교체하거나 데이터 디렉터리를 초기화해 실행을 성공시키지 않는다. 원인을 표시하고 원본을 유지한다. 고가용성·자동 장애조치·원격 백업·RTO/RPO 보장은 범위 밖이며, Build and Test의 로컬 실행 지침에 정상 종료·데이터 위치·수동 보관 방법을 설명한다.

## 사용자 경험과 콘텐츠

업무 UI는 한국어를 기본으로 하고 Inception/Construction 및 버전 식별자를 일관되게 표시한다. 한글 입력, 줄바꿈, 마크다운 표·코드 블록의 열람을 확인한다. 원본 보기와 렌더링을 구분하며 렌더러가 표현하지 못하는 콘텐츠도 원본으로 확인 가능하게 한다. 원격 이미지는 자동 요청하지 않고 대체 텍스트로 표시하는 방식을 제안한다.

주요 브라우저의 현대 표준 기능을 사용하고 구현에 사용한 로컬 브라우저·버전으로 핵심 흐름을 검증한다. 모든 브라우저/모바일 호환이나 접근성 인증을 주장하지 않는다. 여러 역할은 같은 사용자의 시연 문맥이며 계정 인증을 추가하지 않는다.
