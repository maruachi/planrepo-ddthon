# U1 업무 규칙과 오류

상태: 기능 설계 Q1 B 승인 완료. [도메인 모델](domain-entities.md)과 [승인된 요구사항](../../../inception/requirements/requirements.md)을 구체화한다. 규칙 ID는 후속 구현 검증에 사용한다.

## 입력·조회

| ID | 규칙 | 근거 |
|---|---|---|
| U1-BR01 | 제목은 앞뒤 공백 제거 후 비어 있으면 거절한다. 설명은 공백만 있는지 검사하되 유효한 본문 자체의 줄바꿈·공백은 보존한다. | US-01-AC1/2 |
| U1-BR02 | 선택 마크다운은 없거나 문자열이어야 한다. 빈 문자열도 명시적 첨부로 저장 가능하다. 업로드 시 마크다운 텍스트로 읽을 수 없으면 첨부 오류로 표시한다. 본문을 조용히 잘라 저장하지 않는다. 크기 제한은 NFR에서 정한다. | US-01-AC3 |
| U1-BR03 | SR·초기 workflow·sr_created 사건을 함께 저장한 뒤에만 생성 성공과 카드를 표시한다. 초기 column은 sr_list이다. 같은 제목의 SR은 허용한다. | FR-01/05 |
| U1-BR04 | 보드는 sr_list, requirements_analysis, inception, construction, implementation_ready, implemented의 고정 순서를 사용한다. 표시명은 SR 목록, 요구사항 분석, Inception, Construction, 구현 대기, 구현 완료이다. 회차/리뷰는 별도 표시 값이다. | US-02 기반 |
| U1-BR05 | VersionRef와 documentId를 사용하는 모든 조회·변경에서 SR→문서→버전 소속을 확인한다. 일부 ID가 유효해도 다른 소속이면 처리하지 않는다. | FR-06, 공통 계약 |
| U1-BR06 | 존재하는 SR의 빈 문서·이력 필터 결과는 정상 빈 목록이다. 존재하지 않는 SR/문서/버전은 빈 목록으로 숨기지 않고 대상 없음 오류를 반환한다. | US-06/08 |

파일 업로드 표현은 UI 어댑터가 SRDraft로 바꾼다. C10은 파일 시스템을 읽거나 Jira에 연결하지 않는 직접 입력 정규화 경계이다. 입력 title/description/attachment 수정·삭제 기능을 추가하지 않는다.

## 편집·버전·복원

| ID | 규칙 | 근거 |
|---|---|---|
| U1-BR07 | 문서 본문·제목·출처를 버전별 스냅샷으로 보존한다. 저장된 버전을 수정/삭제하지 않는다. 새 버전 번호·포인터·사건은 같은 commit에서 확정한다. | FR-05/06 |
| U1-BR08 | edit의 target은 편집 기준이며 최신 버전과 같아야 한다. 오래된 기준이면 VERSION_CONFLICT로 거절하고 현재 최신 참조를 반환한다. 초안은 UI에 유지한다. | US-07, 원본 보존 |
| U1-BR09 | 유효한 최신 기준의 편집에서 본문이 정확히 같으면 기존 DocumentView와 변경 없음 결과를 반환한다. 새 버전/편집 사건을 만들지 않는다. 본문을 바꾸지 않는 결정·수정 요청 사건은 이 규칙과 별도로 항상 저장한다. | FR-06 구체화 |
| U1-BR10 | 사람 편집은 빈 본문도 허용한다. 이는 기존 내용을 비우는 명시적 수정이며 과거 버전은 유지된다. 서버에서 마크다운을 재작성하거나 공백을 정규화하지 않는다. | US-07/09 |
| U1-BR11 | restore는 선택 원본과 같은 본문으로 새 버전을 만든다. 제목도 원본 버전의 제목으로 복원한다. 원본·복원 전 최신·새 버전을 사건에 연결한다. | US-10 |
| U1-BR12 | 원본이 이미 최신이거나 본문이 같아도 명시적 복원은 새 버전과 복원 사건을 남긴다. 화면에서 복원 대상과 새 버전 생성 사실을 확인시킨다. | 복원 의미 구체화 |
| U1-BR13 | 복원 처리 시작 때 현재 최신을 읽어 변경 전제로 둔다. commit 전에 최신이 달라지면 거절하고 재확인을 요청한다. 이미 처리 시작 전에 저장된 변경은 복원 전 최신으로 보존한다. | 일관된 저장 |

이력에서 과거 버전을 열람할 수 있으나 그 화면의 기본 동작은 읽기·비교·복원이다. 편집은 최신 열람 화면에서 시작한다. 오래 열어 둔 최신 편집 화면도 U1-BR08 검사를 받는다. 서버의 기존 restore(source, actor) 계약은 유지하며, 복원은 특정 현재 버전의 수정이 아닌 선택 과거 내용의 재채택이라는 의미이다.

## 비교·사건·생성 연결

| ID | 규칙 | 근거 |
|---|---|---|
| U1-BR14 | compare는 같은 SR·같은 문서의 두 버전만 허용한다. 왼쪽→오른쪽 방향과 정확한 버전 식별 정보를 표시한다. 같은 버전 비교는 변경 없음이다. | US-09 |
| U1-BR15 | 비교는 저장·사건 생성·최신 포인터 변경을 하지 않는다. 줄 단위 동일/추가/삭제를 표시하며 치환은 삭제와 추가로 표현할 수 있다. 줄바꿈과 마지막 개행 차이를 숨기지 않는다. | US-09-AC2 |
| U1-BR16 | SR 전체 사건은 모든 종류를 포함한다. 문서 필터는 versionRefs에 해당 documentId가 포함된 사건을 고른다. 사건 sequence 역순, 버전 번호 역순으로 이력을 표시한다. | US-08 |
| U1-BR17 | 사건은 본문 버전 없이도 저장 가능하다. 버전이 지정되면 같은 SR 소속이어야 한다. U2 문서 결정·U3 리뷰는 정확한 버전 참조를 요구하며 과거 사건을 새 버전으로 옮기지 않는다. | US-05/08/12 연결 |
| U1-BR18 | prepareGenerated는 SR·실행 참조·결과 문서의 키/소속/형식을 검증한다. 제목·logicalKey는 비어 있지 않아야 하고 AI 본문은 공백만이면 결과 오류이다. 한 결과 묶음에서 같은 문서 키/ID 중복은 오류이다. | FR-03, C04 계약 |
| U1-BR19 | 문서 목록이 빈 AI 결과는 빈 DocumentChanges를 반환할 수 있다. 질문만 있는 결과의 유효성은 U2가 판단한다. prepareGenerated 성공만으로 실행 성공·단계 완료를 표시하지 않는다. | C05.finishRun 계약 |
| U1-BR20 | AI 생성 시 본문이 이전과 같아도 실행에 따른 새 버전과 생성 사건을 준비한다. 실제 커밋 전에는 공개하지 않으며 runId와 연결한다. | AI 생성 이력 보존 |
| U1-BR21 | 준비부터 저장까지 최신 참조·문서 키·SR 소속 전제를 재검증한다. 실행 입력 버전과 준비 시점 최신이 다른지 판단하고 결과를 채택하는 정책은 U2 책임이다. | 늦은 결과 U1/U2 경계 |
| U1-BR22 | commit은 모든 레코드·참조·포인터·사건을 함께 반영한다. 실패·전제조건 불충족 시 일부 성공을 반환하지 않는다. 저장 방식과 응답 유실 처리 세부는 NFR에서 정의한다. | NFR-04 |

U1-BR21은 준비 이후의 저장 경합을 다룬다. 실행 도중 편집되어 이미 최신이 달라진 경우는 U2가 입력 스냅샷과 대조해야 하며, U1 검사만으로 전체 늦은 결과 문제가 해결되었다고 주장하지 않는다. 현재 유효한 기존 편집·복원 동작을 유지하는 범위에서 후속 설계를 확장한다.

## 오류와 사용자 회복

| 코드 | 조건 | 사용자 표시·데이터 효과 |
|---|---|---|
| VALIDATION_ERROR | 필수값 누락·입력 타입/첨부 오류 | 필드와 이유 표시, 입력 유지, 저장 없음 |
| NOT_FOUND | SR/문서/버전 없음 | 대상을 찾을 수 없음과 목록 이동 제공, 임의 대체 버전 표시 금지 |
| REFERENCE_MISMATCH | SR·문서·버전·실행 소속 불일치 | 올바른 대상을 다시 열도록 안내, 저장 없음 |
| VERSION_CONFLICT | 편집 기준 또는 commit 전제가 바뀜 | 최신 버전 열기·비교 제공, 미저장 초안 유지, 자동 덮어쓰기 없음 |
| INVALID_GENERATED_ARTIFACT | AI 결과 키/제목/본문/중복 오류 | U2에 결과 검증 실패 반환, 문서 저장 없음 |
| READ_FAILED | 저장 데이터 조회 불가 | 오류와 다시 읽기 제공, 빈 데이터로 성공 표시 금지 |
| STORAGE_FAILED | 변경 저장 실패 | 완료되지 않았음을 표시, 편집 초안 유지, 성공 포인터/버전 표시 없음 |

물리적 손상·서버 응답 유실처럼 저장 여부를 즉시 확인할 수 없는 경우에는 성공/미저장을 단정하지 않고 재조회로 확인한다. 자동 재시도·중복 진행 방지 패키지를 추가 요구로 만들지 않는다. 구체 HTTP 상태 코드는 U1 NFR/Code Generation에서 매핑한다.

## 후속 검증 예시

1. v1에서 v2 편집 후 v1을 복원하면 v3가 최신이고 v1/v2는 그대로 읽힌다.
2. v2를 기준으로 편집 중 다른 저장으로 v3가 생기면 해당 초안 저장은 충돌이며 v3가 유지된다.
3. 같은 본문 편집에는 버전이 늘지 않지만 U2의 승인 사건은 본문 없이 추가된다.
4. 준비된 생성 변경 중 일부 참조가 잘못되면 전체 commit이 실패하며 신규 문서도 보이지 않는다.
5. 비교 전후 저장 레코드와 사건 수가 동일하고 왼쪽/오른쪽 및 끝 개행 차이를 확인할 수 있다.

이는 설계 검증 시나리오이며 테스트 실행 결과가 아니다. U2/U3 실제 사건 생산·CLI 연결은 해당 단위 구현 후 확인한다.

## 확장 준수

Security Baseline, Resiliency Baseline, Property-Based Testing: Enabled No, 모두 N/A. 전체 규칙과 적용을 생략한다. 제품의 저장·기본 사용성 제약은 계속 적용한다.
