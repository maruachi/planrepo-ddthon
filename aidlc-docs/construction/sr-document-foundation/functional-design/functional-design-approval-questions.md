# U1 기능 설계 검토

검토 대상: [도메인 모델](domain-entities.md), [업무 규칙](business-rules.md), [업무 처리 모델](business-logic-model.md), [화면 구성](frontend-components.md).

U1 담당 메서드 18개, 업무 규칙 22개 및 관련 스토리·수용 기준을 연결했다. SR·문서·버전·사건과 저장 전 변경 모델, 새 버전 편집·복원, 비교, 화면 입력과 서비스 연결을 정의했다.

주요 설계 제안은 다음과 같다.

- 생성 시 첨부는 원본 SR 입력으로 보관하고 편집 가능한 계획 문서와 구분한다.
- 최신과 같은 본문을 편집 저장하면 변경 없음으로 알린다. 명시적 복원과 AI 생성은 내용이 같아도 새 버전·사건을 기록한다. 본문 없는 결정은 별도 사건으로 보존한다.
- 오래된 기준의 편집은 충돌을 알리고 초안을 유지한다. 복원은 처리 시작 시 최신을 기준으로 새 버전을 만들며 저장 직전 경합을 확인한다.
- U1은 문서 변경 준비·저장 전제조건을 제공한다. 늦은 AI 결과의 채택 정책과 단계/회차는 U2, 리뷰·수동 완료는 U3가 구체화한다.
- 기술 스택·DB·실행 경로는 U1 NFR Requirements/Design에서 결정한다. 이번에는 앱 코드나 CLI 실행 검증을 수행하지 않았다.

문서 링크·표 구조·담당 메서드 배정·참조 및 저장 불변 조건을 검증했다. Security/Resiliency/Property-Based Testing은 기존 결정대로 비활성화하여 모두 N/A이다.

## Question 1 — 기능 설계 검토 결과

위 네 산출물과 설계 제안에 대한 검토 결과를 기록해 주세요. 이 질문은 construction/functional-design.md의 두 가지 검토 행동을 따른다.

A) Request Changes — 변경할 모델·규칙·흐름·화면과 원하는 동작을 설명

B) Continue to Next Stage — 기능 설계를 승인하고 U1 NFR Requirements로 진행

[Answer]: B
