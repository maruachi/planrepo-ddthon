# PlanRepo 단계별 프로토타입 구현 계획

**목표:** 처음 사용하는 사람이 제목과 초안으로 등록한 뒤, 단계 안에서 필요한 문서·질문·검토를 처리합니다.

**범위 조정:** 2026-09-09 사용자가 프로토타입과 핵심 기능을 우선하고 새 TDD는 추후로 미루도록 지시했습니다. 기존 승인된 개발 범위 안에서 구현 순서를 조정합니다. 추가 설계 승인 대기는 두지 않습니다. 전체 제품 요구 충족이나 운영 준비 완료로 판정하지 않습니다.

## 설계 결정

기존 객체별 탭 유지, 모든 기능을 새로 만드는 단일 마법사, 기존 명령을 단계별 화면에 묶는 방식 중 세 번째를 선택합니다. 현재 API와 데이터를 재사용하므로 구현 시간을 줄이고 저장·권한 규칙을 유지합니다.

등록은 제목과 초안을 기본 입력으로 받습니다. 관리용 키와 원문·요구사항 연결은 시스템이 준비합니다. 부분 저장 실패 시 진행 상태를 보여 주고 실패 단계부터 재시도합니다. 원문과 사람이 수정한 문서는 구분합니다.

상세 화면은 초안 등록, 요구사항 정리, 계획·설계, 구현 준비로 묶습니다. 실제 업무 단계보다 뒤에 있는 그룹은 탭이나 링크로 제공하지 않습니다. 이전 단계는 열람하고 현재 단계로 돌아갈 수 있습니다. 계획 검토는 계획·설계 그룹 안에 둡니다. 질문·결정, AI 제안, 문서, 단계별 검토를 해당 단계 안에서 찾습니다. 자료가 없으면 만들기 행동을 제공합니다. 내부 ID·fingerprint·epoch는 일반 흐름에 노출하지 않습니다.

담당자는 단계별 작업 공간에서 다음 행동을 찾습니다. 업무 확인자는 답변할 질문, 결정권자는 결정할 안건, 검토자는 요청받은 검토, 관리자는 배정을 내 할 일에서 찾습니다. 실제 저장과 승인 권한은 기존 서버가 검증합니다.

사용자가 제공한 로컬 참고 브랜치 fix-ydg-01을 읽었습니다. 참고 보드의 단계별 열, 짧은 등록 폼, 등록 후 상세 이동, 단계 안의 AI 질문·문서·검토 대기 구조를 확인했습니다. 현재 제품에는 단계별 보드와 네 작업 그룹을 반영합니다. 참고 제품의 두 역할 대신 승인된 다섯 페르소나를 유지합니다. 실행 시 외부 저장소 의존성은 없습니다.

## 검증 기준

- 제목과 초안으로 등록하면 원문과 요구사항이 저장됩니다. 같은 SR의 등록 내용을 확인한 뒤 담당자가 요구사항 정리를 시작합니다.
- 단계 이동은 화면 탐색과 공식 승인에 따른 업무 단계 전환을 구분합니다.
- 역할을 바꾸면 해당 역할의 실제 할 일이 표시되고 클릭한 대상이 있는 화면으로 이동합니다.
- AI 결과는 제안으로 표시합니다. 문서 반영·답변·결정·승인은 사람이 수행합니다.
- 기존 로컬 사용자 데이터에는 검증용 SR을 추가하거나 시드를 다시 넣지 않습니다.
- 실행한 명령과 결과, 생략한 새 TDD 및 전체 수용성·성능 검증을 보고합니다.
