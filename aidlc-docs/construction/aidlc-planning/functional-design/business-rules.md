# U2 업무 규칙

1. 계획 단계는 요구사항 분석, 사용자 스토리, 워크플로우 계획, 앱 설계, 작업 단위, 기능 설계, NFR 요구사항, NFR 설계, 코드 구현 계획 순이다. 각 단계는 해당 규칙을 적용하되 간단한 SR의 조건부 항목은 문서에서 N/A 근거로 다룬다. 최종 단계는 코드 생성 Part 1만 수행한다.
2. Inception은 사용자 스토리부터 작업 단위, Construction은 기능 설계부터 코드 구현 계획까지다. 각 열 최초 진입 시 회차 1, 같은 단계 재생성(revise)은 해당 열 회차 +1, 다음 하위 단계(next)는 회차를 유지한다. 실패 재시도(generate)는 회차를 늘리지 않는다.
3. 최초/실패/응답 완료에는 generate, 질문이 해결된 검토 대기·승인·수정 요청에는 revise, 현재 대상 전체가 자체 승인된 경우 next를 허용한다. 실행 중에는 계획 변경을 거절한다. 문서 편집·열람은 허용한다.
4. 유효한 질문만 있는 결과는 성공이며 응답 대기다. 모든 질문에 비어 있지 않은 답을 제출한 뒤 같은 단계에서 생성한다. 빈 문서와 빈 질문으로 이루어진 결과는 실패다.
5. 문서가 생성되면 검토 대기이며 AI는 승인하거나 다음 단계로 자동 전환하지 않는다. 결정은 전체 생성 문서 묶음의 현재 최신 버전에 고정한다. 편집 후에는 최신 묶음을 다시 승인해야 한다. 오래된 승인으로 다음 단계에 갈 수 없다.
6. 마지막 코드 구현 계획을 자체 승인한 뒤 completePlanning으로 구현 대기로만 이동한다. 코드 실행·빌드·Git·PR은 호출하지 않는다. 피어 리뷰 상태는 진행 조건에 포함하지 않는다.
7. Run 시작 시 모든 입력 문서 버전을 저장한다. 실행 중 어떤 입력 문서가 변경되거나 문서 집합이 바뀌면 늦은 결과 전체를 충돌 실패로 처리한다. 기존 편집을 덮어쓰지 않으며 명시적으로 재생성한다.
8. CLI 완료 이후 문서·질문·Run 성공·상태·사건은 같은 원자 저장에 포함한다. 실패 후 이전 문서와 결정 사건은 유지한다. 저장소 장애로 실패 기록도 못 쓰면 조회 오류를 반환한다.
9. 요청 revision과 operation ID로 오래된 폼·중복 변경을 구분한다. 불확실 응답은 결과 조회로 확인하며 자동 재제출하지 않는다. 한 SR의 동시 실행은 거절한다.
10. 서버 시작 시 이전 running Run을 중단 실패로 정리한다. 자동 CLI 재실행은 하지 않는다. 입력·출력 상한 초과는 명시적으로 실패시키고 문맥을 조용히 잘라내지 않는다.

US-02/03/04/05/13 및 US-06/07/08 인계에 대응한다. 비활성 Security/Resiliency/PBT 확장은 모두 N/A이며 승인된 저장·제품 요구는 적용한다.
