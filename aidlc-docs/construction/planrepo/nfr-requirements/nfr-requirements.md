# PlanRepo 비기능 요구사항

버전은 0.1이며 **사용자 승인 완료**입니다. 승인된 Functional Design을 바탕으로 UOW-01의 품질 기준을 정합니다. 사용자 응답 “진행하자”를 2026-09-08T15:27:15Z에 기록했습니다. 아래 수치와 기술 선택을 승인받았습니다. 성능·복구·실제 Claude 실행을 이미 통과했다는 뜻이 아닙니다.

## 1. 기준과 적용 범위

제품 기준은 `aidlc-docs/inception/requirements/requirements.md` 0.4의 NFR-01부터 NFR-08, FR-01부터 FR-23, AC-01부터 AC-19입니다. 상세 동작은 `aidlc-docs/construction/planrepo/functional-design/business-rules.md`와 `aidlc-docs/construction/planrepo/functional-design/business-logic-model.md`를 유지합니다. 데이터·UI는 같은 단계의 `aidlc-docs/construction/planrepo/functional-design/domain-entities.md`, `aidlc-docs/construction/planrepo/functional-design/frontend-components.md`가 기준입니다.

NQ 식별자는 기존 NFR을 측정·검증할 세부 조건이며 새 제품 기능을 추가하지 않습니다. 기술 선택과 근거는 `aidlc-docs/construction/planrepo/nfr-requirements/tech-stack-decisions.md`, 작성 진행은 `aidlc-docs/construction/plans/planrepo-nfr-requirements-plan.md`에 있습니다. 실제 원자성 패턴·프로세스 제어·스키마·실행 명령은 다음 NFR Design·Infrastructure Design에서 구체화합니다.

한 로컬 앱·한 팀·프로젝트·가상 사용자·가상 자료를 대상으로 합니다. 운영 조직 인증·운영 SLA·클라우드 확장·자동 외부 동기화·실제 사내 자료 처리는 포함하지 않습니다. 기능 데모의 입력/오류/권한 검사를 생략하는 근거로 이 제한을 사용하지 않습니다.

## 2. 측정 프로파일과 제한의 뜻

확인 시점은 2026-09-08 UTC입니다. 로컬 환경은 macOS 계열 Darwin 25.6.0 arm64, 물리 메모리 16 GiB, physical CPU 8개입니다. Node v22.23.2·npm 10.9.8·Claude Code 2.1.263의 버전 명령은 exit 0입니다. 정확한 CPU 모델·브라우저 버전·앱 빌드·DB 크기는 실제 성능 측정 기록에 추가합니다. 다른 하드웨어에서 같은 수치를 달성했다고 일반화하지 않습니다.

| 프로파일 | 데이터와 목적 |
|---|---|
| DEMO-4 | PAY-102·AUTH-331·NOTI-028·CAT-093의 승인된 가상 시드 흐름입니다. 기본 사용자 경험과 실제 Claude 연계 검증에 사용합니다. |
| PERF-100 | 100 SR, SR마다 논리 문서 4개·각 5버전, 질문 10개·결정 5개·수정 요청 10개·활동 200개를 갖는 별도 합성 fixture입니다. 본문은 기본 20 KiB이며 대표 SR의 현재 요구사항과 비교 대상은 각각 200 KiB로 둡니다. 유효한 묶음·역할·상태 관계를 유지합니다. |
| BOUNDARY | 단일 본문 1 MiB, 각각의 제한과 1바이트 초과, 악성 Markdown·한국어 UTF-8·늦은 출력·동시 변경을 별도 fixture로 검사합니다. 성능 목표 프로파일과 섞어 평균을 내지 않습니다. |

PERF-100의 문서 버전은 총 2,000개, 질문 1,000개, 결정 500개, 수정 요청 1,000개, 활동 20,000개입니다. 결정 버전·묶음·승인·인계·생성 이력은 유효한 시드 상태를 만드는 데 필요한 수를 fixture manifest에 고정하고 결과에 함께 기록합니다. 측정 반복마다 자료가 계속 늘어나면 같은 프로파일로 비교하지 않습니다. 별도 테스트 저장소를 사용하며 사용자 자료 초기화를 기본 절차로 삼지 않습니다.

성능 표본은 5개 독립 브라우저 context가 각자 최대 한 요청을 진행하는 조건에서 수집합니다. API는 endpoint 동작별 100개를 합산하며 각 context는 20개를 담당합니다. UI는 동작별 20개를 합산합니다. p95는 오름차순 표본의 ceil(0.95×n)번째 값으로 계산합니다. 성공률·p50·p95·최댓값·예상 거절·예기치 않은 오류 수를 함께 기록합니다. 실패를 표본에서 조용히 버리지 않습니다.

생성 전·생성 중의 비AI 경로를 각각 측정합니다. 지연 adapter는 재현 가능한 지연 검증이고 실제 Claude 1개 실행 중의 관찰은 별도 증거입니다. 모델 응답 대기·패키지 다운로드·빌드 시간은 API 응답 p95에 넣지 않지만 실제 사용자 소요 시간 기록에서는 숨기지 않습니다.

### 크기와 시간의 기준

KiB는 1,024 bytes, MiB는 1,048,576 bytes입니다. 문자 수와 바이트 수를 구분합니다. 아래 값은 초기 기본값이며 조정할 때 변경 이유와 기존 검증 영향을 기록합니다. 제품 설정에서 값이 사라지거나 제한 없는 실행으로 변하지 않아야 합니다.

| 항목 | 초기 제한 | 검사 기준 |
|---|---|---|
| 단일 ArtifactVersion 본문 | 1 MiB입니다. | UTF-8 Markdown 본문입니다. 초과 저장은 기존 버전을 유지하고 입력 크기를 안내합니다. |
| 단일 명령 요청 본문 | 8 MiB입니다. | 전송된 직렬화 요청 bytes입니다. 본문 JSON escaping과 부가 참조를 포함합니다. 개별 문서 제한도 따로 검사합니다. |
| Claude 명시적 입력 | 2 MiB입니다. | 서버가 직렬화한 모든 사용자/시스템 입력·참조 내용·로컬 규칙의 합계입니다. CLI의 암묵 입력을 허용한다는 뜻이 아닙니다. 실제 모델 context 제한은 더 작을 수 있습니다. |
| stdout | 4 MiB입니다. | 실행별 누적 raw bytes입니다. JSON/stream envelope를 포함하며 stderr와 별도 상한입니다. |
| stderr | 256 KiB입니다. | 실행별 누적 raw bytes입니다. 두 파이프를 동시에 소비하고 원시 내용을 UI에 보여주지 않습니다. |
| 검증 후 초안 본문 | 2 MiB입니다. | 정규화된 결과의 UTF-8 직렬화 bytes입니다. 문서로 적용할 때는 단일 문서 1 MiB 제한도 적용합니다. |
| 고정 Handoff Markdown | 8 MiB입니다. | 정확한 기준본의 UTF-8 bytes입니다. 초과하면 실패를 표시하며 필수 내용을 잘라 유효 인계로 만들지 않습니다. |
| 생성 실행 | 300초입니다. | 프로세스 시작 시도부터 출력 종료·검증까지이며 대기는 별도입니다. 종료 정리 관찰은 최대 10초 목표로 따로 기록합니다. |

입력 2 MiB는 메모리·전송의 절대 상한입니다. 모든 모델이 이 크기를 지원한다는 약속이 아닙니다. 1 MiB 문서는 수동 저장·검토할 수 있지만 여러 문서와 규칙을 모은 생성 입력이 상한을 넘으면 명시적으로 입력 축소가 필요합니다. 조용한 생략·잘라내기·가짜 성공으로 해결하지 않습니다. 모델별 실제 입력 제한과 형식은 초기 실제 Claude 검증에서 확인합니다.

인계 출력보다 생성 입력의 상한이 작은 이유는 목적이 다르기 때문입니다. 인계는 여러 승인 문서를 그대로 전달하는 기준본이며 AI 호출이 아닙니다. 큰 HTTP 응답의 스트리밍·메모리 사용·렌더링 전략은 NFR Design에서 정하고 이 제한을 준수하는지 검사합니다.

## 3. 세부 품질 기준

### NQ-01 검증 규모

**목표**: 한 팀·프로젝트와 가상 사용자 5명의 독립 브라우저 context를 사용합니다. 기본 시드 4개는 유지하고 별도 PERF-100에서 100 SR을 검증합니다. 100은 제품의 저장 개수 상한이 아닙니다. 동시 브라우저 5개에서 잘못된 SR·사용자 응답 혼합이 없어야 합니다.

**검증**: 고정 fixture manifest와 실제 자료 건수·바이트·시드 식별자를 저장합니다. 동일 fixture를 재사용해 성능 결과를 비교합니다.

**추적**: NFR-06, NFR-07; BR-01, BR-30, BR-32; SCN-23, SCN-24.

### NQ-02 비AI API 응답

**목표**: PERF-100에서 주요 조회 p95 500ms 이하, 업무 쓰기 p95 1,000ms 이하를 목표로 합니다. 긴 Claude 생성은 제외하되 생성 요청 접수·상태 조회·취소 상태 확정은 이 목표에 포함합니다. 성공 응답을 빨리 만들기 위해 저장 확정을 생략하지 않습니다.

**검증**: 동작별 준비 10회 후 정상 표본 100개를 5개 context에서 측정합니다. 서버 요청 수신부터 응답 완료까지 단조 시계로 잽니다. 예상한 거절과 예기치 않은 실패 수·시간을 별도 기록합니다.

**추적**: NFR-01, NFR-06; BR-12, BR-22, BR-30; SCN-14, SCN-23.

### NQ-03 화면 반응

**목표**: 200 KiB 대표 문서에서 보드 진입·상세/탭 열람·원문 비교·저장 결과 표시를 사용자 행동 후 p95 2초 안에 완료하는 목표입니다. 전체 문서 로딩 없이 성공 표시만 먼저 하는 방식은 통과가 아닙니다. 1 MiB 경계 문서는 정확한 표시·편집·비교와 실측 시간을 별도로 기록합니다.

**검증**: Chromium 1440×900과 1280×800에서 동작별 준비 5회·정상 표본 20개를 관찰합니다. 브라우저 행동부터 필요한 내용/저장 결과가 실제 보일 때까지 측정합니다.

**추적**: NFR-05, NFR-06; BR-08, BR-30, BR-31; SCN-23, SCN-24.

### NQ-04 로컬 이용과 시작

**목표**: CLI가 없거나 생성이 실패해도 저장된 문서 열람·사람의 편집·검토는 가능해야 합니다. 이미 설치·빌드한 앱을 PERF-100의 정상 로컬 저장소로 시작하면 10초 안에 저장 자료 조회가 가능해야 합니다. 준비 중·저장소 오류·복구 중을 준비 완료와 구분합니다.

**검증**: 동일 환경에서 시작 5회를 측정합니다. 패키지 설치·빌드·최초 스키마 생성 시간은 별도 기록합니다. 실행 중 Claude 지연/실패와 함께 조회·검토를 확인합니다.

**추적**: NFR-01, NFR-06; BR-24, BR-27, BR-30; SCN-17, SCN-20, SCN-24.

### NQ-05 확정 자료 보존

**목표**: 성공 응답한 SR·답변·결정·문서·승인·인계·활동·receipt의 재접속·앱 재시작 후 누락은 검증 사례에서 0건이어야 합니다. 미저장 브라우저 입력과 확정 서버 자료를 구분합니다.

**검증**: 새로고침·서버 재시작·프로세스 강제 종료를 사용합니다. 응답 전후 저장 식별자와 내용을 비교합니다. 디스크 고장·전원 손실에 대한 운영 복구 보장으로 확대하지 않습니다.

**추적**: NFR-01, NFR-03; BR-02, BR-08, BR-12, BR-32; SCN-14, SCN-24.

### NQ-06 원자성

**목표**: 변경·새 불변 버전·현재 참조·ReviewImpact·단계 복귀·요청 승계·활동·receipt와 작업 생성은 모두 확정되거나 모두 보존돼야 합니다. 일부만 성공한 상태는 검증 사례에서 0건이어야 합니다. Claude 실행은 업무 트랜잭션 밖에 둡니다.

**검증**: 검증 전·변경 저장 중·확정 직전·확정 후 응답 전의 장애를 주입합니다. 실제 SQLite를 다시 열어 자료와 모든 파생 상태를 검사합니다. 모델 호출 지연 중에도 다른 쓰기가 진행돼야 합니다.

**추적**: NFR-01, NFR-03, NFR-08; BR-11, BR-12, BR-20; SCN-09, SCN-11, SCN-14.

### NQ-07 충돌과 현재 조건

**목표**: 같은 버전의 편집 경쟁은 오래된 쓰기를 거절해야 합니다. 승인·게이트·현재 인계의 현재 권한·묶음·epoch·참조를 확정 시 검사합니다. 동일 묶음의 다른 검토자 승인은 서로를 오래된 묶음으로 만들지 않습니다.

**검증**: 두 명령의 읽기·확정 순서를 각각 제어합니다. 이전 화면 승인, 제거된 검토자, 변경 직후 내보내기와 최초 문서 absent 대상 생성 경쟁을 확인합니다.

**추적**: NFR-02, NFR-03, NFR-04; BR-11, BR-15, BR-16, BR-22, BR-28; SCN-05, SCN-08, SCN-12, SCN-14, SCN-15, SCN-21.

### NQ-08 중복 처리

**목표**: 같은 범위·주체·키의 같은 명령·입력 재요청으로 대상·승인·인계·활동이 중복되는 사례는 0건이어야 합니다. 같은 키의 다른 명령/입력은 충돌입니다. 동일 receipt는 현재 권한과 필요한 현재용 유효성 확인 뒤 쓰기 없이 반환합니다.

**검증**: 최소 두 동시 요청과 응답 유실 후 재요청을 수행합니다. 저장 개수·고정 결과·현재 유효성 표시를 확인하며 과거 성공을 새 전환 성공으로 취급하지 않습니다.

**추적**: NFR-02, NFR-03; BR-05, BR-11, BR-12, BR-28; SCN-03, SCN-14, SCN-21.

### NQ-09 이력과 재검토 일관성

**목표**: G1 변경은 종속 G2도 무효화하고 G2 전용 변경은 G1을 유지해야 합니다. 가장 앞선 재검토 단계를 우선합니다. 미해결 차단/비차단 요청과 삭제 섹션 연결, 과거 승인·인계별 외부 사실을 보존해야 합니다.

**검증**: Functional Design의 전파·전이표 전체와 SCN 사례를 검사합니다. H1 완료가 H2나 현재 SR을 잘못 완료시키는 사례는 0건이어야 합니다.

**추적**: NFR-01, NFR-03; BR-18, BR-19, BR-20, BR-21, BR-29, BR-32; SCN-07, SCN-08, SCN-09, SCN-10, SCN-11, SCN-22.

### NQ-10 현재 역할과 범위

**목표**: 화면과 공개 요청에 같은 현재 역할·배정·프로젝트/SR 검사를 적용합니다. 원 요청자의 확인 자격과 역할 겸임을 보존합니다. 내부 runtime 메서드 6개를 일반 사용자 요청으로 호출할 수 없어야 합니다.

**검증**: 정상·거절 권한 행렬, 다른 SR 참조, 옛 배정, 전환 질문 재답변, 클라이언트 승인 문자열과 내부 메서드 호출을 직접 검사합니다. 규칙에 맞지 않는 허용·거절은 모두 실패입니다.

**추적**: NFR-04, NFR-08; BR-01, BR-05, BR-06, BR-10, BR-15; SCN-03, SCN-06, SCN-07, SCN-08, SCN-12.

### NQ-11 안전한 문서 표시

**목표**: 문서·원문 비교·생성 초안·인계에 포함된 실행 HTML·스크립트·위험 URL을 실행하지 않아야 합니다. 출처·확인 여부를 표시하며 렌더링 결과로 업무 승인 상태를 만들지 않습니다.

**검증**: script, 이벤트 속성, javascript URL, iframe 등 고정 공격 fixture를 모든 표시 경로에서 검사합니다. 이 fixture의 스크립트 실행과 임의 탐색은 0건이어야 합니다.

**추적**: NFR-05, NFR-08; BR-03, BR-25, BR-27, BR-31; SCN-20, SCN-24.

### NQ-12 키보드와 입력 보존

**목표**: 메뉴·탭·문서 비교·질문/결정·체크리스트·저장·승인·전환·초안 적용·인계의 주요 행동을 키보드로 실행할 수 있어야 합니다. 초점·필드 이름·오류 연결과 색 외 상태 표기를 제공합니다. 늦은 조회·탭 이동·저장 실패가 작성 중 입력을 덮어쓰지 않아야 합니다.

**검증**: 주요 행동 목록의 키보드 접근/실행 누락 0건을 확인합니다. 가상 사용자·SR 전환, 오류 복귀, 비동기 조회 순서를 바꿔 입력의 대상과 주체를 검사합니다. 접근성 인증 획득을 뜻하지 않습니다.

**추적**: NFR-05, NFR-06; BR-30, BR-31; SCN-12, SCN-23, SCN-24.

### NQ-13 사용성 관찰

**목표**: 대표 사용자가 차단 SR의 차단 이유와 담당자를 10초 안에 찾는 기존 목표를 유지합니다. 다음 행동 찾기·변경점/원문/결정 이유/묶음 버전 확인 후 승인은 별도로 관찰합니다.

**검증**: SR 담당자와 동료 검토자의 과업을 구분하고 실제 관찰 인원·시간·오류·도움 제공 여부를 기록합니다. 사용자 관찰 없이 개발자의 클릭이나 자동 테스트만으로 목표 달성을 선언하지 않습니다.

**추적**: NFR-05, NFR-06; BR-30, BR-31; SCN-23, SCN-24.

### NQ-14 생성 용량과 대기

**목표**: 같은 로컬 앱 저장소에서 실제 생성 프로세스는 동시에 1개로 제한합니다. nonterminal Run은 총 10개입니다. running 레코드가 1개이면 pending은 최대 9개, running 레코드가 없으면 pending은 최대 10개입니다. 실제 프로세스의 종료 미확인과 Run 상태는 별개이므로 종료를 확인하기 전에는 대기 작업을 인수하지 않습니다. 초과 신규 요청은 실행하지 않고 대기열 가득 참을 표시합니다.

**검증**: 11번째 신규 요청·동시 인수·같은 요청 재생을 검사합니다. 조회·취소는 대기열 포화로 막지 않습니다. 종료 미확인 프로세스가 있으면 새 실행을 시작하지 않고 원인을 표시합니다. 별도 DB·별도 앱 사본 전체를 통제한다고 주장하지 않습니다.

**추적**: NFR-03, NFR-06, NFR-08; BR-11, BR-23, BR-24, BR-27; SCN-16, SCN-17, SCN-19, SCN-20.

### NQ-15 생성 시간 제한

**목표**: 초기 기본 실행 제한은 300초입니다. 실행 인수·입력 검증 뒤 프로세스 시작을 시도하는 시점부터 출력 종료·결과 검증까지의 wall-clock 상한입니다. 대기열 시간은 분리합니다. timeout은 실패로 기록하고 부분 결과를 성공 초안으로 만들지 않습니다.

**검증**: 지연·무응답 테스트 adapter로 제한 시각·terminal 결과·정제를 확인합니다. 실제 Claude의 완료 시간은 따로 기록합니다. 300초는 외부 모델 응답 SLA가 아니며 네트워크 실패·모델 입력 제한을 성공으로 바꾸지 않습니다.

**추적**: NFR-06, NFR-08; BR-24, BR-25, BR-27; SCN-16, SCN-17, SCN-20.

### NQ-16 취소와 종료 관찰

**목표**: 취소 상태의 서버 확정은 비AI 쓰기 목표를 따르고 화면에는 2초 안에 반영하는 목표입니다. 실행 중이면 확정 후 1초 안에 종료 신호를 전달하고 10초 안에 실제 종료를 관찰하는 목표입니다. 취소 확정·신호 전달·실제 종료는 다른 사실입니다.

**검증**: 완료 먼저·취소 먼저·오류 먼저·신호 무응답 사례를 나눠 검사합니다. 먼저 확정한 terminal 상태를 보존합니다. 종료를 확인하지 못하면 종료 미확인과 경과 시간을 표시하고 새 실행을 막습니다. 나중에 원 실행의 신뢰 가능한 종료를 확인하면 기존 terminal 상태를 유지하고 실행 슬롯만 해제합니다. 종료 미확인을 정상 종료 통과로 집계하지 않습니다.

**추적**: NFR-03, NFR-06, NFR-08; BR-24, BR-27; SCN-16, SCN-17.

### NQ-17 입출력 크기 제한

**목표**: 본문·모델 입력·프로세스 파이프의 제한을 아래 크기 표대로 각각 검사합니다. 제한 초과는 명확한 입력/실행 오류이며 자료를 조용히 잘라 보내거나 부분 초안을 적용하지 않습니다. 바이트 제한은 특정 모델의 context 지원을 보장하지 않습니다.

**검증**: 각 상한에서 정확히 같은 바이트와 1바이트 초과를 검사합니다. 한국어 UTF-8·JSON escaping·동시 stdout/stderr 출력도 검사하며 기존 저장본과 승인을 보존합니다.

**추적**: NFR-02, NFR-06, NFR-08; BR-08, BR-23, BR-25, BR-27, BR-31; SCN-14, SCN-15, SCN-20, SCN-24.

### NQ-18 입력 고정과 초안 적용

**목표**: 요청 시 입력 내용·버전·확인 상태·로컬 규칙·대상 버전 또는 absent 기준·provider/model 선택을 고정합니다. 완료와 적용 직전에 최신성을 각각 검사합니다. 사람 비교 초안도 현재 입력에 연결하고 같은 초안을 중복 적용하지 않습니다.

**검증**: 입력 변경 시점을 요청 후·완료 후·적용 직전으로 나눕니다. 기본 provider 설정 변경, 다른 SR 참조, 신규 문서 생성 경쟁과 사람의 재검토를 검사합니다. 오래된 결과가 현재 문서·결정·승인을 덮어쓰는 사례는 0건이어야 합니다.

**추적**: NFR-02, NFR-03, NFR-08; BR-23, BR-25, BR-26; SCN-15, SCN-19, SCN-20.

### NQ-19 Claude 실행 경계

**목표**: 제품 호출은 제한된 질문·결정 제안·문서 초안 생성만 수행해야 합니다. 모델의 명령·파일 수정·업무 API·직접 승인·단계 전환을 허용하지 않습니다. 실행마다 다른 SR의 세션·자동 문맥이 섞이지 않아야 합니다. 설치 확인만으로 생성 가능·격리 완료를 표시하지 않습니다.

**검증**: 실제 CLI의 내장 도구·MCP·customization·managed policy·session 경계를 검증합니다. 위험 동작 유도 입력과 별도 가상 canary 자료로 도구 실행·허용 밖 파일 변경·SR 문맥 혼합을 확인합니다. 경계를 확보할 수 없는 환경에서는 생성 시작을 막고 이유를 남깁니다.

**추적**: NFR-07, NFR-08; BR-01, BR-23, BR-25, BR-27; SCN-18, SCN-19, SCN-20.

### NQ-20 실제 실행과 교체 계약

**목표**: 기본 연결은 설치 Claude CLI입니다. 요청/실제 model·CLI 버전·실제/테스트 provider를 구분합니다. AC-17은 실제 질문 생성·사람 답변·후속 문서 생성·사람 적용·G1/G2 검토·Handoff까지 실행해야 합니다. AC-18의 교체 가능성은 테스트 adapter와 같은 계약으로 검증합니다.

**검증**: 2026-09-09의 짧은 실제 호출을 B-02의 초기 연결 증거로 사용하고 B-05에서 AC-17 전체를 확인합니다. 이후 실행의 실제 모델 정보를 확인하지 못하면 미확인으로 기록합니다. 두 번째 실제 모델 서비스나 설정 전용 UI를 추가 요구하지 않습니다.

**추적**: NFR-06, NFR-07, NFR-08; BR-23, BR-26, BR-27, BR-32; SCN-18, SCN-19, SCN-20.

### NQ-21 중단 복구

**목표**: 정상 저장소 준비 후 10초 안에 소유권이 끊긴 running 작업을 판정하고 중단 실패와 종료 확인 상태를 구분하는 목표입니다. 이미 확정한 pending은 보존합니다. 재시도는 사용자의 새 Run이며 옛 실행의 늦은 결과로 현재 시도를 덮어쓰지 않습니다.

**검증**: 인수 전·실행 중·성공 확정 직후 앱 프로세스를 중단하고 다시 시작합니다. 같은 Run의 재인수·옛 ClaimRef의 성공/실패 확정·중복 실행을 거절해야 합니다. M-049/M-050을 통한 원 실행의 신뢰 가능한 종료 사실은 재인수 없이 조회·기록할 수 있습니다. 종료가 확인되면 기존 terminal 상태를 유지하고 실행 슬롯만 해제합니다. 이후 보존된 다른 pending Run을 그 Run의 새 ClaimRef로 인수합니다. 종료 미확인이 남으면 NQ-14의 새 실행 차단을 유지하며 슬롯을 임의 해제하지 않습니다.

**추적**: NFR-01, NFR-03, NFR-06, NFR-08; BR-12, BR-24, BR-27; SCN-14, SCN-16, SCN-17.

### NQ-22 오류와 추적 기록

**목표**: 현재 오류·입력·저장 결과·행위자·버전·Run/receipt 식별자를 구분합니다. 화면·활동·로그·인계에는 비밀 값·소유권 토큰·원시 CLI 출력을 노출하지 않습니다. 오류 분류만으로 실제 인증·모델 실패 이유를 추정하지 않습니다.

**검증**: 가상 비밀 canary를 stdout/stderr·예외·잘못된 출력에 넣고 모든 표시/기록 경로의 비노출을 확인합니다. 업무 이력은 보존하되 raw 진단은 성공 이력이나 사용자 본문으로 보관하지 않습니다. 사용자 입력 전체를 일반 운영 로그에 복제하지 않습니다.

**추적**: NFR-01, NFR-07, NFR-08; BR-01, BR-24, BR-27, BR-32; SCN-16, SCN-17, SCN-20.

### NQ-23 독립 실행과 재현성

**목표**: 프로젝트 내부 소스·규칙·가상 자산·설정·고정 의존성으로 준비·빌드·실행·저장·재접속·내보내기를 재현해야 합니다. Node와 PATH로 찾는 설치 Claude는 명시적 외부 런타임 전제입니다. 다른 프로젝트·개인 고정 경로·전역 개발 도구 상태를 제품 저장소로 사용하지 않습니다.

**검증**: 별도 경로 사본에서 문서화된 설치·타입 검사·테스트·빌드·실행을 확인합니다. lockfile 불일치는 의존성 준비 실패로 명확히 표시합니다. CLI 부재는 실제 생성 요청과 실제 AI 검증만 PROVIDER_UNAVAILABLE로 실패하며 비AI 앱 시작·조회·편집·검토는 가능해야 합니다. 준비 단계의 패키지/브라우저 다운로드와 실제 Claude 통신은 완전 오프라인 실행 보장과 구분합니다.

**추적**: NFR-01, NFR-06, NFR-08; BR-02, BR-23, BR-27, BR-32; SCN-01, SCN-18, SCN-24.

### NQ-24 검증 증거와 유지보수

**목표**: 승인된 34개 스토리·122개 개별 기준·해당 7개 공통 기준과 24개 Functional Design 시나리오를 구현 검증에 연결합니다. 행동 변경은 예상 이유의 RED 후 최소 구현·GREEN을 기록합니다. 기준과 무관한 전체 커버리지 퍼센트·비활성 PBT를 완료 조건으로 추가하지 않습니다.

**검증**: 타입 검사·단위 정책·계약·실제 SQLite 통합·브라우저·실제 Claude 증거를 구분합니다. 정확한 명령·환경·결과·실패·건너뛴 검증을 기록하며 build 성공만으로 승인·저장·모델 경계 통과를 선언하지 않습니다.

**추적**: NFR-01, NFR-02, NFR-03, NFR-04, NFR-05, NFR-06, NFR-07, NFR-08; BR-11, BR-12, BR-16, BR-24, BR-27, BR-31, BR-32; SCN-01, SCN-02, SCN-03, SCN-04, SCN-05, SCN-06, SCN-07, SCN-08, SCN-09, SCN-10, SCN-11, SCN-12, SCN-13, SCN-14, SCN-15, SCN-16, SCN-17, SCN-18, SCN-19, SCN-20, SCN-21, SCN-22, SCN-23, SCN-24.

## 5. Claude 근거와 남은 실행 검증

NFR 승인 시점에 확인한 것은 `claude --version`과 `claude --help`였고 실제 생성·인증·모델은 미검증이었습니다. 2026-09-09의 `aidlc-docs/construction/planrepo/code/claude-execution-decision.md`에서는 기존 설치 환경을 유지한 실제 호출이 exit 0으로 끝났습니다. 요청·actual model은 `global.anthropic.claude-opus-4-8`, canonical model은 `claude-opus-4-8`, provider는 `bedrock`이었습니다. 기본 modelChoice는 explicit이며 이 modelId를 사용합니다. provider와 model을 교체 가능한 계약은 유지합니다.

실제 호출 프로파일에는 safe-mode와 restricted, setting-sources를 추가하지 않습니다. 내장 도구·MCP·hooks·slash command·세션 저장은 각각 명시적으로 제한합니다. 한 옵션이나 작업 폴더 분리만으로 완전한 실행 격리를 보장하지 않으며 새 실행의 문맥 분리는 별도로 검증합니다. [Claude CLI reference](https://code.claude.com/docs/en/cli-reference)

표준 managed 설정 파일은 관찰되지 않았고 Bedrock의 remote managed policy fetch는 비활성으로 보고됐습니다. 이 관찰은 모든 MDM과 전역 문맥의 부재를 입증하지 않습니다. 일반 전역 상태의 부재를 입증하지 못했다는 이유만으로 검증된 기존 연결을 실패로 바꾸지는 않습니다. 실제 managed MCP 충돌이나 자동 명령이 관찰되면 그 실행은 실패로 처리합니다. [Claude 설정 우선순위](https://code.claude.com/docs/en/settings#settings-precedence)

bare 모드는 사용하지 않습니다. 기존 PATH·HOME·인증 환경을 보존하고 credential 값을 읽거나 복사하지 않습니다. 새 API key나 전역 인증 변경을 전제로 삼지 않습니다. [Claude 비대화식 실행](https://code.claude.com/docs/en/headless)

NFR Design과 구현은 2026-09-09에 검증한 호출 프로파일을 기준으로 managed 정책·도구/MCP·hooks·세션·환경·작업 디렉터리·프로세스 정리의 경계를 적용합니다. AC-17 전체 흐름, 취소·timeout·복구·자손 정리와 customization 격리는 아직 별도 검증 대상입니다. 테스트 adapter로 같은 API를 구현했다고 실제 Claude 요건을 통과시키지 않습니다. 실행 파일·버전·모델·argv·출력 schema가 바뀌면 짧은 실제 호출과 provider 확인을 다시 수행합니다.

## 7. 현재 결과와 다음 설계
