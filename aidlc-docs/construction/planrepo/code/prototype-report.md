# PlanRepo 핵심 프로토타입 결과

최신 상태 안내: 이 보고서는 당시 P1~P8 범위의 구현·검증 기록입니다. 이후 사용자가 Plan 문서 리뷰와 사람·AI의 의도 동기화를 핵심으로 명시했습니다. 현재 구현에는 반복적인 이해 확인과 문단별 검토 UI가 부족합니다. 제품 적합성의 새 기준은 aidlc-docs/inception/requirements/plan-centered-intent.md에 기록했습니다.

작성 시각은 2026-09-09T04:29:46Z입니다. 사용자 최신 지시에 따라 새 TDD 사이클과 전체 제품 완성도 작업을 뒤로 미루고 핵심 사용 흐름을 구현했습니다.

## 실행

현재 주소는 http://127.0.0.1:4173 입니다. root 소유 PTY13872에서 실행합니다. 서버와 웹은 같은 포트입니다.

현재 프로젝트 루트에서 같은 사용자 데이터로 재기동할 때 실행하는 명령입니다. 이미 실행 중인 서버를 중복 기동하지 않습니다.

```sh
PLANREPO_DATA_DIR=.planrepo/previews/cg17-20260909/.planrepo/data node dist/server/main.js
```

프로젝트의 일반 새 실행 설정은 config/planrepo.json입니다. 다른 프로젝트의 파일을 import하거나 runtime 입력으로 사용하지 않습니다. 외부 참고 브랜치의 단계별 보드, 짧은 등록, 상세의 단계 묶음 구조를 현 프로젝트에 구현했습니다.

## 변경

- 제목과 초안 또는 Markdown 파일로 등록합니다. 관리용 키와 목적을 제안하고, 원문과 첫 요구사항을 같은 요청에 연결합니다. 부분 저장 실패는 완료한 단계를 유지해 재시도합니다.
- 일반 문장도 입력할 수 있습니다. 원문은 보존하고 파생 요구사항에만 최소 제목 구조를 붙입니다.
- 보드는 접수·요구사항 정리·계획/설계·구현 준비·구현 중·완료로 모읍니다. 상세는 실제 진행한 그룹과 현재 그룹의 문서·질문·검토를 제공합니다. 미래 단계는 탭이나 링크로 노출하지 않습니다.
- 내 할 일은 실제 질문·답변 확인·결정·현재 검토·관리자 배정을 읽습니다. 역할 선택은 상세에서도 유지합니다.
- 요구사항과 계획 단계에서 AI 생성을 요청합니다. 생성 결과 확인과 문서 반영은 사람이 합니다. 설치 Claude CLI 2.1.265와 global.anthropic.claude-opus-4-8을 사용합니다. provider와 model 선택은 기존 교체 가능한 경계를 유지합니다.
- 진행 계획은 요구사항과 검증 방법을 연결합니다. 설계 수행/생략은 사람이 선택합니다. 기존 workflow의 추가 stage는 보존합니다.
- 요구사항·계획 검토를 같은 흐름으로 제공합니다. 승인과 업무 단계 이동은 별개입니다. 화면의 단계 탐색만으로 공식 상태를 바꾸지 않습니다.
- 일반 보드의 GP 코드와 epoch를 숨겼습니다. 동일한 G2 자료가 배열 순서 차이만으로 무효가 되던 판정도 수정했습니다.

## 데이터 보존과 실패 기록

기존 사용자 DB는 시드나 마이그레이션을 다시 실행하지 않았습니다. 재시작 직전에 백업했습니다. 재시작 전후 37개 업무 테이블의 전체 행 hash가 일치하며 integrity_check=ok입니다. 등록·답변·검토 테스트는 별도 TestApp 데이터에서만 실행했습니다. 테스트 전용 서버 PTY83081은 검증 뒤 정상 종료했습니다. TestApp이 자신이 만든 데이터만 정리했습니다.

중간 typecheck는 병행 편집의 미생성 컴포넌트와 props 오류로 실패했으며 최종 빌드 전에 해소했습니다. 기존 UI E2E는 없어진 가상 사용자 선택자와 이전 버튼 이름을 기다리다 실패해 중단했습니다. 이 테스트를 통과했다고 판정하지 않습니다. 새 구조의 주요 행동은 실제 브라우저로 검증했습니다.

빈 제목 제출 때 숨은 required 필드가 focus 오류를 내는 문제를 발견해 보이는 제목 오류로 바꿨습니다. 일반 산문 연결·StrictMode의 응답 수신·기존 workflow stage 보존을 코드 검토로 보완했습니다. 최초 테스트 필터의 artifact.test.ts 오기는 artifact-edit.test.ts로 고친 정확한 네 파일 명령으로 최종 재검증했습니다.

## 현재 단계 중심 UX 후속 수정

사용자가 요구사항 단계에서 미래 탭을 눌러 가능 여부를 확인해야 하는 문제를 제기했습니다. 실제 progressStage로 메뉴와 초기 진입을 제한했습니다. 요구사항 단계에서는 초안과 요구사항 그룹만 보입니다. G1 통과 후 담당자가 단계를 이동하면 계획·설계가 열립니다. G2 검토는 계획·설계 안에서 진행하고, 이후 구현 준비가 열립니다.

오른쪽 검토 링크, 관리자 배정, 내 할 일의 계획 검토/배정도 같은 기준으로 제한했습니다. 요구사항 AI는 질문과 요구사항 문서만, 계획 AI는 진행 계획만 제공합니다. 비담당자에게 실행 선택기를 표시하지 않습니다. 배정되지 않은 사람에게 승인 입력 폼을 표시하지 않습니다.

검토 요청은 현재 자료의 대기 중·전원 승인·완료 상태를 문구로 구분합니다. 예전 자료나 다시 준비해야 하는 자료는 새 요청을 막지 않습니다. 다음 행동은 문서·현재 단계의 질문/결정·배정·reviewPreparations를 확인해 안내합니다. 후속 범위 질문과 결정으로 변환한 질문을 남은 질문으로 세지 않습니다.

후속 검증 결과입니다.

- npm run typecheck는 exit 0입니다. npm run build도 exit 0이며 215개 모듈을 빌드했습니다. 최종 JS는 index-myRHpGtY.js입니다.
- 별도 TestApp에서 제목과 초안 등록, 등록 화면만 표시, 요구사항 시작, 관리자 G1 배정, 검토자의 내 할 일 진입, 승인, 담당자의 계획 단계 전환을 실제 브라우저로 확인했습니다. 미래 단계 버튼은 요구사항 중 0개였고, 단계 이동 직후 계획·설계의 작업 탭이 열렸습니다.
- 요구사항의 AI 문서 종류 선택은 0개입니다. 계획에서는 진행 계획 생성만 보였습니다. 업무 확인자의 AI 실행 버튼은 0개입니다. 관리자 배정 화면에 G2 체크박스가 없었습니다.
- 검토 대기·전원 승인·완료에서 새 검토 요청 버튼이 사라졌습니다. 승인할 수 없는 사람의 체크박스와 의견 입력이 사라졌습니다.
- planning에서 G2 검토를 열어도 계획·설계 그룹을 유지합니다. ready 자료는 구현 준비로 열립니다. 이전 단계의 현재 단계 복귀도 확인했습니다.
- node /tmp/cg-srdetail-navigation-probe.cjs는 exit 0입니다. SSR로 초기 진입과 미래 단계 우회 제한 8개 경우를 확인했습니다. planning의 review 진입은 계획·설계 안의 계획 검토로 허용하는 것이 올바른 기대입니다. 첫 기대 해석 불일치는 이를 정정해 해결했습니다. ESM probe 준비 2회 실패 후 CJS로 실제 검증했습니다.
- 1280px·390px에서 문서 가로 넘침이 없었습니다. 최종 브라우저 console 메시지는 0개입니다. 현재 사용자 포트에서 미래 버튼 0개, 최신 빌드 파일 제공, readiness의 ready=true·generationReady=true를 확인했습니다.
- 단계 전환 뒤 화면 상단으로 이동하도록 보완했습니다. 이 마지막 표시 수정은 typecheck와 build로 검증했습니다.
- 도중 잘못 지정한 브라우저 카드 키·선택자는 timeout이나 다중 일치로 실패했습니다. 최신 화면과 DOM에서 선택자를 다시 읽어 확인했습니다. 제품 오류로 집계하지 않았습니다.

이번 후속 수정에서도 새 TDD와 이전 UI E2E 전면 개편은 생략했습니다. 사용자 DB에 테스트 항목을 추가하지 않았고 AI를 새로 호출하지 않았습니다.

## 남긴 범위

새 TDD, 이전 UI E2E 전면 정비, 전체 34개 스토리 수용성·성능 검증, Handoff와 외부 구현 이력의 전체 사용자 흐름은 후속 작업입니다. 결정권자의 새 결정 확정, G2 이후 전체 흐름, 실제 AI 생성의 브라우저 E2E를 이번에 새로 완료했다고 주장하지 않습니다. 일부 상세·고급 관리 영역의 용어 개선도 남습니다.

Vite의 향후 native config loader 호환 안내와 500kB 초과 chunk 경고가 남습니다. same-boot 식별 상실 복구는 기존 NQ21 미지원 상태입니다. no-fork 실행 관찰은 파일·네트워크·XPC·원격 실행 전체 격리 증명이 아닙니다.

Security, Resiliency, Property-Based Testing 확장은 기존 사용자 설정에 따라 비활성으로 N/A입니다.
