# PlanRepo 업무 규칙

버전은 0.1이며 **사용자 승인 완료**입니다. 승인 응답 “다음단계 진행”을 2026-09-08T14:53:15Z에 기록했습니다. UOW-01의 승인된 요구사항·스토리·논리 계약을 상세화한 설계안입니다. 앱 구현이나 실행 결과를 뜻하지 않습니다.

## 1. 기준과 적용

기준 문서는 `aidlc-docs/inception/requirements/requirements.md`, `aidlc-docs/inception/user-stories/stories.md`, `aidlc-docs/inception/application-design/component-methods.md`입니다. 데이터는 `aidlc-docs/construction/planrepo/functional-design/domain-entities.md`, 처리 순서·상태·시나리오는 `aidlc-docs/construction/planrepo/functional-design/business-logic-model.md`, 화면은 `aidlc-docs/construction/planrepo/functional-design/frontend-components.md`에서 연결합니다.

BR 식별자는 다음 Code Generation 테스트의 규칙 추적점입니다. 정량 제한·DB·HTTP endpoint·프로세스 제어 방식은 NFR·Infrastructure Design에 남깁니다. 아래 상세 선택은 새 제품 범위가 아니며 Functional Design 승인에서 확정합니다.

## 2. 규칙 목록

### BR-01 범위와 주체

모든 조회와 명령은 서버가 해석한 ProjectScope 또는 SrScope를 사용합니다. 다른 SR의 식별자·버전·문맥을 섞으면 거절합니다. 가상 사용자 선택은 고정 목록에서만 허용하며 클라이언트 역할·완료·승인 값은 권한 근거가 아닙니다. 내부 runtime 계약 여섯 개는 UI나 외부 업무 요청으로 호출하지 못합니다.

근거: FR-01, FR-16, NFR-04, NFR-08, AC-09.

### BR-02 SR 등록과 보존

SR에는 프로젝트·키·제목·목적·설명·담당자와 workflowVersion이 필요합니다. 프로젝트 안의 키는 중복되지 않습니다. 최초 설명은 보존하고 현재 설명을 새 버전으로 변경합니다. 중복 Mock 가져오기는 기존 SR을 안내하며 덮어쓰지 않습니다. Git 저장소 선택은 전제 조건이 아닙니다.

근거: FR-01, FR-02, FR-03, AC-01.

### BR-03 자료의 확인

자료 종류·출처·내용 또는 링크·버전과 확인 상태를 분리합니다. 확인은 사람이 읽은 정확한 버전과 확인자·시각·근거에 연결합니다. 링크를 등록하거나 AI가 읽었다고 말한 것만으로 확인하지 않습니다. 내용·대상·확인 결과가 달라지면 관련 검토 기준을 갱신합니다. 같은 대상·내용의 표시 이름만 바뀌면 승인 대상 변경으로 보지 않습니다.

근거: FR-02, FR-03, AC-01.

### BR-04 질문과 답변

질문에는 질문 내용·이유·답변 담당자·필요 게이트·현재 범위가 있습니다. 배정된 답변자가 답변과 근거를 저장해도 상태는 answered입니다. SR 담당자가 특정 답변·근거의 일관성과 문서 반영 또는 변경 불필요 이유를 확인해야 resolved입니다. 답변이나 해결 근거가 바뀌면 예전 해결 확인은 새 기준에 적용하지 않습니다.

근거: FR-04, FR-05, AC-02.

### BR-05 후속 질문과 결정 전환

후속 질문은 원 질문과 담당자·필수 시점을 보존합니다. 질문을 결정으로 전환하면 원 연결을 유지하고 새 결정은 미확정으로 만듭니다. converted_to_decision 질문의 차단 여부는 연결 결정에서 한 번만 계산합니다. 반복 전환으로 같은 문제의 결정을 중복 생성하지 않습니다. 전환 뒤 원 질문의 M-008 답변 변경·M-009 해결 확인은 거절합니다. 원본 조회·후속 질문은 허용하며 처리 책임은 연결 결정에 유지합니다.

근거: FR-04, FR-06, AC-02, AC-03.

### BR-06 결정 확정

지정된 현재 결정권자만 대안·선택·이유·근거를 확정하거나 재결정합니다. SR 담당자·관리자라는 역할만으로 확정할 수 없습니다. AI 추천과 제안 버전에는 확정 효력이 없습니다. 재결정은 이전 확정본을 보존하고 영향받는 문서·질문·검토를 갱신합니다.

근거: FR-06, FR-07, FR-10, AC-03.

### BR-07 범위 분류

SR 담당자가 current 항목의 requiredGate를 G1 또는 G2로 분류합니다. followup은 None과 이유·담당자·재검토 시점을 요구합니다. 현재 필수 항목을 후속 범위로 줄이려면 지정 결정권자의 범위 축소 결정과 개정 요구사항·완료 기준이 필요합니다. 새 묶음을 만든 후 재승인으로 새 범위를 채택합니다. 분류명만 바꾸거나 새 묶음 생성 전에 그 묶음 승인을 요구하지 않습니다.

근거: FR-05, FR-07, FR-16, AC-15.

### BR-08 불변 문서

문서 저장은 새 ArtifactVersion을 만듭니다. 문서·요구사항·섹션의 안정적인 식별자와 이전 버전·입력 버전·작성 주체를 유지합니다. 변경 요약과 원문 비교를 모두 제공합니다. 삭제한 섹션을 다른 내용에 재사용하지 않습니다. 과거 본문과 승인 상태를 덮어쓰지 않습니다.

근거: FR-08, FR-11, FR-15, NFR-02, AC-06.

### BR-09 계획 산출물

WorkflowPlan은 실행·생략 단계와 이유, 선택한 설계 문서, 요구사항과 검증 연결을 명시합니다. G2에는 진행 계획·선택한 필수 설계·구체적인 구현 계획이 필요합니다. 구현 계획에는 작업 순서·완료 기준·테스트 방법을 포함합니다. 별도 테스트 문서를 항상 요구하지 않지만 필수 기준을 생략하지 못합니다.

근거: FR-08, FR-16, AC-07, AC-11.

### BR-10 행동별 권한

SR 담당자는 문서·범위·검토 요청·전환·인계를 관리합니다. 배정 답변자는 답변, 지정 결정권자는 결정 확정, 현재 지정 검토자는 개별 승인을 담당합니다. 팀 관리자는 정책·검토자 배정을 관리합니다. 댓글·수정 요청은 팀 검토 참여자에게 허용합니다. 수정 반영은 요청 담당자 또는 SR 담당자가 하며 해결 확인은 원 요청자 또는 현재 지정 검토자가 합니다. 한 사람의 역할 겸임을 금지하지 않습니다.

근거: FR-05, FR-12, FR-14, FR-19, NFR-04, AC-05, AC-09.

### BR-11 동시성과 중복

명령에는 대상 자원의 기대 버전과 중복 방지 키가 있습니다. 같은 주체·행동·범위·키·내용은 같은 receipt를 반환하며 새 이력을 만들지 않습니다. 같은 범위·주체·키의 다른 명령 또는 내용은 충돌입니다. 개별 승인의 기준은 묶음·검토 epoch·현재 배정이며 다른 검토자의 표 하나가 같은 묶음을 오래되게 만들지 않습니다. 저장·확정 시점의 현재 권한과 대상 검사를 생략하지 않습니다.

근거: NFR-01, NFR-02, NFR-03, AC-09, AC-13.

### BR-12 원자적 업무 변경

문서·답변·결정 변경, ReviewImpact, 현재 참조·검토 요청 승계, 활동과 receipt는 같은 확정 경계에서 저장합니다. 하나라도 실패하면 부분 성공을 남기지 않습니다. 외부 Claude·Mock 조회를 저장 잠금 안에서 기다리지 않습니다. 거절과 저장 실패를 성공으로 표시하지 않습니다.

근거: FR-15, FR-16, FR-22, NFR-01, NFR-03, AC-13.

### BR-13 공식 묶음

ReviewBundle은 정확한 문서·결정·질문 결과·범위·출처·정책·검토자 버전과 reviewEpoch를 고정합니다. G2는 현재 유효한 상위 G1 묶음에 연결합니다. 필수 문서가 준비되어야 공식 묶음을 만들 수 있습니다. 미확정 결정은 그 시점의 불변 제안 스냅샷으로 고정합니다. 내용·정책·배정·epoch가 같은 검토 재요청은 현재 묶음과 요청을 재사용합니다. 미해결 질문이나 수정 요청은 그대로 보여주며 검토 요청·개별 승인을 일률적으로 금지하지 않습니다. 이 조건과 게이트 통과 조건은 다릅니다.

근거: FR-13, FR-14, AC-04, AC-09.

### BR-14 배정과 정책 적용

최초 검토자 배정은 문서·공식 묶음 없이 가능합니다. 정책 버전 생성은 기존 SR에 자동 소급하지 않습니다. SR에 명시 적용하거나 검토자를 변경하면 영향받는 검토 기준을 바꿉니다. 입력이 갖춰지면 새 고정 묶음을 만들고 아니면 NeedsInputs로 미준비 이유를 반환합니다. 가짜 문서·묶음·승인을 만들지 않습니다. 이전 현재 요청은 대체하고 필요한 새 요청만 표시합니다.

근거: FR-18, FR-19, AC-10.

### BR-15 개별 승인

현재 공식 묶음의 지정 검토자만 묶음 ID·버전·epoch와 필수 체크리스트를 확인해 승인합니다. 과거 묶음으로의 현재 승인은 거절합니다. 본인이 SR 담당자여도 지정 검토자라면 승인 기록은 가능합니다. 개별 승인은 단계 전환이나 게이트 통과가 아닙니다. 다른 검토자의 미승인·미해결 필수 질문만을 이유로 개별 승인을 거절하지 않습니다.

근거: FR-14, FR-16, AC-04, AC-09.

### BR-16 게이트 통과

지정 검토자가 한 명 이상이고 SR 담당자와 다른 사람이 한 명 이상 있어야 합니다. 지정 검토자 전원의 현재 묶음 승인, 필수 체크리스트·문서·질문 해결·결정 확정, 미해결 차단 수정 요청 부재를 모두 요구합니다. G2는 유효한 현재 G1과 정확한 연결도 요구합니다. 관리자·AI·클라이언트 완료 값으로 조건을 우회하지 않습니다.

근거: FR-13, FR-14, FR-16, AC-02, AC-04, AC-05, AC-09.

### BR-17 댓글과 수정 요청

일반 댓글은 문서 버전·섹션과 작성자에 연결합니다. 댓글만으로 내용이 바뀌지 않으면 승인을 유지합니다. 수정 요청에는 원 대상·현재 연결 대상·내용·담당자·원 요청자·차단 여부가 있습니다. 과거 문서 대상 요청도 허용하지만 현재 관련 범위의 새 차단 요청이면 현재 게이트에 영향을 줍니다.

근거: FR-12, FR-15, AC-05, AC-16.

### BR-18 반영 확인

반영 결과는 정확한 문서 버전·근거와 연결하며 awaiting_confirmation으로 둡니다. 원 요청자 또는 현재 지정 검토자가 현재 반영 기준을 확인해야 resolved입니다. 반영자도 이 자격을 겸하면 확인할 수 있습니다. 원 요청자는 검토자 배정에서 빠져도 요청자 자격을 유지합니다. 확인 전 대상이 다시 바뀌면 오래된 반영 확인을 거절합니다. 추가 수정 요구는 open으로 돌아갑니다.

근거: FR-12, FR-16, AC-05.

### BR-19 미해결 요청 승계

문서·묶음 교체와 섹션 삭제 때 open과 awaiting_confirmation 요청을 모두 승계합니다. 원 대상·이력과 차단 여부를 보존합니다. 대상 섹션이 없으면 별도 미해결 목록으로 이동합니다. 비차단 요청을 자동으로 차단으로 올리지 않으며 반영 확인 대기의 차단 요청을 해결된 것으로 간주하지 않습니다.

근거: FR-12, FR-15, AC-05, AC-16.

### BR-20 변경 영향

G1 기준 변경은 G1과 종속 G2를 무효화합니다. G2 전용 변경은 G1을 보존합니다. 승인 대상에 포함된 문서·답변 해결·결정·범위·출처, 새 필수 문제·차단 요청, 명시 정책 적용·검토자 변경에 적용합니다. 해당 reviewEpoch를 늘리고 needsNewBundle을 표시합니다. 기존 승인·묶음·인계는 삭제하지 않습니다. 단순 댓글·동일 대상 표시 이름·실패한 생성은 승인 기준을 바꾸지 않습니다.

근거: FR-15, FR-19, AC-06, AC-07, AC-10, AC-16.

### BR-21 재검토와 진행 단계

기준 변경으로 필요한 가장 앞선 검토 단계로만 복귀합니다. G1 재검토 중 G2 전용 변경이 생겨도 계획·설계로 전진하지 않습니다. 문제를 해결했다고 예전 묶음·G2 승인을 자동 복구하지 않습니다. 새 묶음 검토와 명시적 전환이 필요합니다. 외부 구현 사실은 별도 보존합니다.

근거: FR-15, FR-16, FR-21, AC-06, AC-07, AC-12.

### BR-22 단계 전환

접수·요구사항 구체화·계획·설계·구현 준비 완료·구현 중·완료를 명시적인 행동으로 전환합니다. 조회한 GateAssessment는 예약이나 허가증이 아닙니다. 확정 경계에서 현재 권한·묶음·기대 버전·필수 조건을 다시 평가합니다. 실패 시 차단 이유·담당자·대상과 최신 상태를 반환합니다.

근거: FR-16, FR-17, NFR-03, AC-09, AC-14.

### BR-23 AI 요청과 선택

생성 요청은 SR·작업 유형·현재 입력 버전·필요 로컬 규칙·대상 문서의 정확한 버전 또는 아직 없음 기준과 provider/model 선택을 고정해 pending 작업을 만듭니다. 첫 실제 provider는 시스템 Claude CLI입니다. 테스트용 연결도 같은 계약을 사용하지만 실제 호출로 표시하지 않습니다. 실제 모델 정보는 확인된 값만 기록합니다. 요청 후 전역 선택 변경이 기존 실행의 provider를 바꾸지 않습니다.

근거: FR-09, FR-23, AC-17, AC-18.

### BR-24 AI 실행 상태

GenerationRun 상태는 pending, running, succeeded, failed, cancelled입니다. 실행 인수는 하나의 ClaimRef에 귀속됩니다. 같은 소유권과 running 상태에서만 성공·실패를 확정합니다. 취소와 완료 중 먼저 확정한 terminal 상태를 보존합니다. 취소 확정·신호 전달·프로세스 종료 확인은 다른 사실입니다. 재시도는 현재 입력으로 새 실행을 만들고 이전 실행을 보존합니다.

근거: FR-09, FR-22, NFR-06, NFR-08, AC-19.

### BR-25 초안 검증과 오래됨

성공 결과도 형식·작업 유형·SR 참조 범위를 검사한 초안일 뿐입니다. 실행 완료와 적용 확정 시 입력 fingerprint·대상 버전을 각각 비교합니다. 오래된 결과는 보존하되 현재 본문을 덮어쓰지 못합니다. 사람이 현재 자료와 비교한 새 검토 초안은 원 실행을 지우지 않고 현재 입력에 연결합니다.

근거: FR-09, FR-10, NFR-02, AC-08, AC-19.

### BR-26 사람의 적용

SR 담당자의 명시적 선택으로 초안을 새 문서 버전 또는 미확정 질문·결정 제안으로 적용합니다. 질문 답변·결정 확정·승인·단계 전환은 별도 사람 행동입니다. 적용도 일반 문서 변경과 같은 권한·충돌·무효화·승계 검사를 거칩니다. 자동 저장·자동 승인·오래됨 표시 제거로 결과를 현재 기준처럼 만들지 않습니다.

근거: FR-09, FR-10, FR-15, AC-03, AC-08, AC-17.

### BR-27 AI 실행 경계

생성 provider는 질문·결정 제안·문서 초안만 반환하며 업무 저장소·승인·전환을 직접 호출하지 않습니다. 임의 도구 실행·파일 변경·다른 SR 문맥 혼합을 허용하지 않습니다. 실패·형식 오류·취소는 기존 업무 문서·승인을 보존합니다. 비밀 값과 원시 CLI 출력을 화면·이력·인계에 노출하지 않습니다. 실제 제한의 수단과 검증은 NFR 설계·구현에서 정합니다.

근거: FR-09, FR-10, FR-16, FR-23, NFR-07, NFR-08, AC-19.

### BR-28 인계 기준본

현재 유효한 G1·G2와 정확한 문서·질문·결정·승인·정책·검증 기준·후속 범위·workflowVersion으로 Handoff를 고정합니다. 미리보기는 과거 내용과 현재 유효성을 함께 표시합니다. 현재용 생성·내보내기는 확정 시 유효성을 재검사합니다. receipt 재조회로 무효한 현재용 다운로드를 허용하지 않습니다. 이미 외부로 받은 파일을 회수했다고 주장하지 않습니다.

근거: FR-20, NFR-03, AC-11, AC-13.

### BR-29 외부 구현 사실

외부 시작·완료·링크·근거는 Handoff별 ImplementationRecord에 수동 기록합니다. 시작 시 유효한 현재 인계를 선택합니다. 재검토 중 과거 인계 H1의 완료도 기록할 수 있지만 G1·G2를 복구하거나 새 인계 H2를 완료시키지 않습니다. 재승인 후 준비 완료까지 돌아오더라도 새 기준의 구현 시작은 명시적으로 기록합니다.

근거: FR-21, FR-22, AC-12.

### BR-30 조회와 검토함

보드·검토함·상세 요약은 같은 확정 revision에서 진행 단계·검토 상태·게이트 차단·외부 사실을 읽습니다. 조회는 검토 시작이나 승인 같은 숨은 쓰기를 하지 않습니다. 검토함은 기한 초과, 현재 단계 차단, 직접 요청, 최신순을 차례로 비교하고 동률은 안정적인 ID로 정렬합니다. 기한 없음은 기한 초과가 아닙니다. 과거 묶음의 요청을 현재 할 일로 중복 표시하지 않습니다.

근거: FR-17, FR-18, AC-10, AC-14.

### BR-31 UI와 오류

한국어 화면은 실제 버전·배정·연결 상태와 저장·생성 실패를 표시합니다. 입력 오류·권한 부족·오래된 버전·게이트 차단·실행 실패를 구분하고 입력을 보존합니다. Markdown 실행 HTML·스크립트를 실행하지 않고 키보드·텍스트로 상태와 주요 행동을 제공합니다. 터미널·드래그 단계 이동·근거 없는 전체 완료 퍼센트를 만들지 않습니다.

근거: FR-11, FR-16, FR-17, NFR-05, NFR-06, AC-09, AC-14.

### BR-32 활동과 데모 검증

주요 명령은 행위자·대상 버전·시각과 결과를 append 방식의 활동으로 남깁니다. 일반 UI에서 과거 이력을 수정·삭제하지 않습니다. 한 팀·프로젝트와 네 시드 SR의 가상 자료를 사용하고 Jira/GitHub는 Mock·외부 링크로 표시합니다. 실제 Claude의 질문·후속 문서·사람 적용·검토·인계 흐름을 실행해야 AC-17을 충족합니다.

근거: FR-01, FR-02, FR-21, FR-22, FR-23, NFR-07, AC-17.

## 3. 확장 규칙

Security Baseline·Resiliency Baseline·PBT는 비활성 상태입니다. 개별 규칙은 N/A이며 전체 규칙 로딩·적용을 생략합니다. 위 기본 권한·일관성·AI 경계와 구현 시 TDD는 유지합니다.
