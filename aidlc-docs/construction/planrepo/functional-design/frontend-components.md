# PlanRepo 프런트엔드 컴포넌트 설계

버전은 0.1이며 **사용자 승인 완료**입니다. 승인 응답 “다음단계 진행”을 2026-09-08T14:53:15Z에 기록했습니다. UOW-01의 승인된 범위에 따라 기술 중립적인 UI 구성·입력·상태·논리 API 연결을 정의합니다. 이 문서는 화면 구현이나 사용성 검증 결과가 아닙니다.

## 1. 기준과 책임

제품 기준은 `aidlc-docs/inception/requirements/requirements.md` 0.4와 `aidlc-docs/inception/user-stories/stories.md` 0.1입니다. 역할은 `aidlc-docs/inception/user-stories/personas.md`, 공개 계약은 `aidlc-docs/inception/application-design/component-methods.md`를 따릅니다. 개발 범위와 구현 순서는 `aidlc-docs/inception/application-design/unit-of-work.md` 및 `aidlc-docs/inception/application-design/unit-of-work-story-map.md`입니다. 작성 진행은 `aidlc-docs/construction/plans/planrepo-functional-design-plan.md`에서 관리합니다.

모든 문서 경로는 프로젝트 루트 기준입니다. UI는 C-01 WebUI에 속하며 C-02 ApplicationServices의 공개 계약만 호출합니다. 프레임워크·상태 관리 라이브러리·DB·HTTP 경로·응답시간 수치는 정하지 않습니다. 아래 props와 state는 논리적인 입력과 화면 내부 상태입니다.

서버는 현재 사용자·대상 소속·버전·검토 묶음·권한·게이트를 검사하고 업무 변경을 확정합니다. UI의 버튼 활성화·체크박스·화면 조회 결과는 이 검사를 대신하지 않습니다. UI는 C-03 정책, C-04 저장, C-05 실행기, C-06 provider, C-07 Mock 포트를 직접 호출하지 않습니다.

M-001의 WorkspaceView는 프로젝트·가상 사용자·연결 상태와 팀 설정에 필요한 현재/선택 가능 정책 버전·체크리스트를 제공합니다. UI-21은 이 조회 결과를 입력으로 받습니다. M-047의 SRDetailView는 SR 범위의 문서·근거·질문·결정·묶음·요청·정책·배정·생성·인계·인계별 외부 사실과 revision을 제공합니다. 세부 화면을 연다는 이유로 새로운 조회 메서드나 업무 변경을 만들지 않습니다. 데모 가져오기는 Jira 키를 M-004에 전달하며 외부 API나 C-07을 UI에서 직접 호출하지 않습니다.

공개 계약 연결 범위는 M-001부터 M-035까지와 M-040부터 M-048까지 총 44개입니다. M-036, M-037, M-038, M-039, M-049, M-050은 실행 소유권을 사용하는 내부 계약입니다. UI에서 호출하거나 RuntimeContext·ClaimRef·프로세스 핸들을 만들지 않습니다. 내부 취소 전달·종료 관찰은 공개 GenerationRunView에서 표시 가능한 결과로만 읽습니다.

## 3. props와 화면 내부 state

모든 데이터 컴포넌트는 확인된 조회 결과와 현재 대상 참조를 받습니다. 변경 폼에는 읽은 시점의 기준 버전과 허용 행동·사유가 전달됩니다. 허용 행동은 화면 안내용이며 서버의 현재 검사보다 우선하지 않습니다.

| 공통 입력 | 의미 |
|---|---|
| WorkspaceContext | 현재 프로젝트와 선택된 가상 사용자입니다. 역할·배정은 서버의 응답을 사용합니다. |
| ScopeRef | 프로젝트 수준은 ProjectScope, 기존 SR은 SrScope입니다. 대상 ID와 프로젝트 소속을 혼용하지 않습니다. |
| ViewBasis | 조회한 revision, 표시 중인 VersionRef·BundleRef와 필요한 입력 fingerprint입니다. 현재 조회 시각과 과거 처리 시각을 구분합니다. |
| ActionAvailability | 현재 응답에서 판단한 행동 가능 여부·권한/배정 사유·차단 대상입니다. 조회 성공 자체는 변경 권한이 아닙니다. |

## 4. 입력 보존·조회 갱신·동시 요청

서버 조회 데이터와 FormDraft를 분리합니다. 새 조회가 도착해도 dirty 입력을 덮어쓰지 않습니다. 동일 화면의 탭·패널 이동은 입력과 편집 기준을 유지합니다. SR·가상 사용자 전환 시 기존 대상의 입력을 다른 대상에 넘기거나 새 행위자로 자동 제출하지 않습니다. 미저장 입력이 있으면 보존하거나 명시적으로 폐기할 경로를 제공합니다. 재접속 후 보존하는 업무 상태는 서버에 확정된 저장본이며 미저장 브라우저 입력을 서버 저장 완료로 표시하지 않습니다.

조회 응답은 actor·프로젝트·SR·대상·조회 순번에 맞는 경우에만 화면에 적용합니다. 늦게 돌아온 다른 SR/사용자의 응답은 현재 화면에 합치지 않습니다. 변경 처리 결과가 이전 화면의 요청에 속하면 그 요청의 처리 사실만 보존하고 현재 편집의 저장 완료나 현재 묶음 승인으로 사용하지 않습니다.

하나의 제출에서 명령·입력·기준 버전·요청 식별자를 고정합니다. 처리 중 같은 제출 버튼의 반복 실행은 같은 요청으로 묶습니다. 응답을 잃어 결과가 불명확하면 실패나 성공을 단정하지 않고 결과 확인 필요를 표시합니다. 같은 명령·동일 입력의 재전송은 같은 idempotencyKey를 사용합니다. 다른 입력의 명시적 제출은 별도 요청이며 이전 key를 재활용하지 않습니다.

Committed는 서버가 확정한 버전과 결과로 표시합니다. Replayed는 이전에 처리된 요청임을 표시하며 현재 유효성과 최신 기준을 별도로 확인합니다. 과거 성공 receipt만으로 현재 게이트 통과·인계 내보내기를 성공 처리하지 않습니다. Rejected는 입력을 보존하고 DomainError의 현재 기준·사유·담당자·대상으로 복구를 안내합니다.

STALE_VERSION·STALE_BUNDLE·INPUT_CHANGED가 발생하면 사용자 입력·읽었던 기준과 최신 변경을 함께 보여줍니다. 강제 덮어쓰기나 묶음 참조의 자동 교체 후 승인 재전송을 제공하지 않습니다. 현재 자료와 비교해 다시 제출하거나 재생성·사람의 현재 초안 작성 경로를 사용합니다. 새 BundleRef로 바뀌면 이전 체크리스트 확인을 새 묶음의 확인으로 이월하지 않습니다.

성공한 업무 변경 뒤 관련 M-047·M-027·M-045·M-046·M-048 조회를 갱신합니다. 보드·검토함·상세가 서로 다른 기준을 섞어 표시하지 않도록 조회 기준을 함께 관리합니다. 갱신 실패 시 기존 표시가 최신이라는 주장을 멈추고 재조회 경로를 제공합니다. 일반 댓글의 revision 증가만으로 UI가 자체적으로 G1/G2를 무효화하지 않습니다.

입력 중인 내용과 저장된 문서가 다른 경우 생성·공식 검토·승인·인계가 참조하는 저장 버전을 명시합니다. 관련 내용을 포함하려면 사용자가 먼저 해당 저장을 확정합니다. 생성이나 승인 버튼이 다른 폼을 몰래 저장하거나 미저장 입력까지 승인했다고 표시하지 않습니다.

역할 겸임은 행동별로 판단합니다. SR 담당자가 지정 검토자이면 개별 승인할 수 있습니다. 반영자가 원 요청자 또는 현재 지정 검토자이면 그 자격으로 해결 확인할 수 있습니다. 팀 관리자에게 승인 우회나 강제 단계 전환 기능을 제공하지 않습니다. 공식 결정은 현재 지정 결정권자, 공식 승인은 현재 지정 검토자의 사람 행동입니다.

## 6. 주요 사용자 흐름

### 보드와 검토함에서 실제 대상으로 이동

UI-02는 SR 키·제목·담당자·진행 단계·검토 상태·차단 이유·다음 행동을 표시합니다. 최근 변경 시각·외부 작업은 보조 정보입니다. 필수 질문 수와 현재 승인 수처럼 의미가 분명한 수치를 사용하고 전체 진행 퍼센트나 드래그 앤 드롭 단계 전환은 제공하지 않습니다.

UI-03은 전체, 질문·결정, 문서 검토, 수정·확인 탭을 제공합니다. 행에는 SR·요청 내용·대상 버전/섹션·요청자·담당자·기한·차단 여부를 표시합니다. M-046이 제공하는 기한 초과, 현재 단계 차단, 직접 요청, 최신순의 우선순위를 유지합니다. 이전 묶음 요청을 현재 할 일로 중복 표시하지 않습니다.

카드나 행의 행동은 UI-06 안의 실제 질문·결정·문서·수정 요청으로 이동합니다. 검토함 요약에서 승인하지 않습니다. 빈 목록은 등록/데모 가져오기 또는 현재 배정 없음으로 설명하며 조회 실패와 구분합니다. 미배정 담당자·검토자·근거 부족은 실제 처리 대상과 다음 행동으로 연결합니다.

### 질문·결정과 문서 반영

UI-09는 이유·출처·관련 문서·답변 담당자·필요 시점과 후보 근거를 함께 보여줍니다. 사용자가 답변하면 답변됨으로 표시합니다. SR 담당자가 반영 문서나 변경 불필요 이유를 확인해야 해결됨이 됩니다. 모순·예외 누락은 후속 질문으로 연결하고 미해결 필수 항목을 남깁니다.

정책 선택 문제는 M-011로 미확정 결정에 연결합니다. 전환된 원 질문은 읽기와 후속 질문만 제공하고 답변 변경·해결 확인은 연결 결정의 처리로 안내합니다. UI-10의 지정 결정권자가 선택·이유·근거를 확정하며 원 질문과 이전 결정은 유지합니다. UI-11의 분류 변경만으로 공식 결정을 만들지 않습니다. G2에서 정할 필수 항목을 G1의 차단으로 합산하지 않습니다.

UI-12·UI-13은 요구사항·진행 계획·선택 설계·구현 계획을 구분합니다. 저장 후 UI-14에서 변경 요약과 두 버전의 원문을 확인합니다. 요약에는 바뀐 요구사항·결정·섹션이 연결되며 요약만으로 원문 비교를 대체하지 않습니다.

### 검토·수정 확인과 G1/G2 통과

UI-15에서 공식 묶음을 만든 뒤 UI-16에서 고정 자료와 체크리스트를 확인합니다. G1 체크리스트에는 문제·사용자, 포함/제외 범위, 업무 규칙·상태·경계, 검증 가능한 완료 기준, 예외·실패, 시스템·데이터·제약·영향, 확인/미확인 근거를 제공합니다. G2에서는 참조 G1·실행/생략 이유·요구사항/작업 연결·순서/영향·검증/회귀·적용/복구 조건을 확인합니다.

M-021의 성공은 본인의 개별 승인 기록입니다. UI-18은 지정 검토자 전원의 현재 묶음 승인, 담당자 외 동료 최소 한 명, 현재 단계의 필수 질문·결정·문서, 미해결 차단 수정 요청을 별도로 표시합니다. 검토자가 없으면 0/0 완료 대신 검토자 지정 필요를 보여줍니다. 필수 항목별 사유·담당자·대상 링크를 제공합니다.

수정은 UI-17에서 반영 제출과 해결 확인을 나눕니다. 확인 대기인 차단 요청은 계속 차단합니다. 한 요청의 해결 확인으로 다른 요청·부족한 승인까지 완료하지 않습니다. 비차단 요청은 업무 목록에 남더라도 단독으로 게이트를 차단하지 않습니다.

SR 접수에서 요구사항 구체화, G1을 통한 계획·설계, G2를 통한 구현 준비 완료는 UI-18의 명시적 M-028 요청으로 처리합니다. G1/G2의 조회는 M-027이며 전환 확정 시 서버가 다시 검사합니다. 구현 시작과 외부 완료는 UI-24의 M-043/M-044를 사용하고 일반 전환 버튼으로 인계·근거 조건을 우회하지 않습니다.

### 승인 후 변경과 재배정

변경 확정 결과에서 현재 단계·검토 상태·G1/G2 유효성을 함께 갱신합니다. G1 대상 변경은 종속 G2·새 인계에 영향을 주고 G2 전용 변경은 G1을 유지합니다. 새 차단 문제·필수 검토자 변경·정책 명시 적용은 필요한 새 묶음과 재승인을 안내합니다. 문제 해결이나 G1 재승인만으로 과거 G2를 되살리지 않습니다.

UI-17은 새 문서·묶음에 이어진 요청을 원 요청과 연결합니다. 삭제된 섹션의 미해결 요청은 별도 목록에서 현재 담당자·원 대상·차단 여부를 확인하고 계속 처리합니다. 이전 검토 요청·승인은 UI-25의 이력에 남습니다.

UI-21의 정책 저장과 UI-22의 기존 SR 정책 적용은 별도 명령입니다. 최초 배정 시 문서가 없으면 배정 결과와 검토 준비 부족을 표시합니다. 묶음이 만들어졌다고 추정하지 않습니다. 제외된 검토자의 오래된 승인 화면은 서버 거절을 표시하며 새 묶음 승인을 남기지 않습니다.

### 생성과 사람의 적용

UI-19는 저장된 입력의 버전·확인 상태·작업 종류를 표시하고 M-032를 요청합니다. M-033으로 작업 결과를 읽습니다. 긴 생성 중에도 UI-12·UI-16을 통한 기존 문서 열람·검토를 계속할 수 있습니다. 미승인 입력을 승인된 사실로 표시하거나 다른 SR의 자료·세션을 합치지 않습니다.

요청 provider/model과 확인 가능한 실제 model·CLI 버전을 구분합니다. 미확인 값은 미확인으로 표시하며 추정하지 않습니다. Claude·테스트 adapter·Mock 연결을 구분합니다. 형식 오류와 실행 실패에는 정제한 사용자용 원인과 재시도 경로만 제공하고 원시 CLI 출력·터미널·비밀 값을 고정 표시하지 않습니다.

M-034의 취소 확정과 실제 프로세스 종료 확인은 따로 표시합니다. 성공이 먼저 확정됐으면 이미 종료된 현재 상태를 표시하고 새로 취소됐다고 쓰지 않습니다. M-035는 실패/취소 기록과 연결된 새 실행이며 이전 시도를 덮어쓰지 않습니다. 성공 결과를 현재 입력으로 다시 생성할 때는 M-032의 새 요청을 사용합니다.

UI-20에서 현재 입력과 초안을 비교합니다. 오래된 결과는 즉시 적용할 수 없고 현재 입력으로 재생성하거나 M-019로 사람의 비교 반영을 남깁니다. M-018의 적용 직전 충돌은 입력을 보존하고 최신 자료를 안내합니다. 질문 제안의 후보 답변은 사람이 확인하며 결정 제안은 지정 결정권자가 확정하기 전까지 미확정입니다. 생성 성공·초안 적용·결정 확정·공식 승인을 각각 표시합니다.

### 인계와 인계별 외부 사실

UI-23은 Handoff ID·생성 시각·workflowVersion·고정 문서/결정/질문 처리/승인 버전·검증 기준·후속 범위를 보여줍니다. M-041의 미리보기와 M-042가 반환한 Markdown은 같은 고정 본문입니다. 새 현재용 내보내기는 서버가 성공으로 반환한 다운로드만 제공합니다. 무효한 게이트의 과거 미리보기를 현재용 내보내기 성공으로 바꾸지 않습니다.

과거 인계는 계속 조회할 수 있고 현재 새 인계 필요를 함께 표시합니다. UI-24에서 현재 유효한 인계를 선택해 외부 시작을 기록합니다. 완료는 실제로 기록할 인계와 그 외부 사실을 선택해 요약·근거를 보존합니다. H1의 외부 완료를 기록해도 최신 H2가 자동 완료되거나 H2의 게이트가 복구되지 않습니다.

재검토 중에도 과거 인계의 외부 완료 사실을 남길 수 있습니다. 서버가 반환한 현재 검토 단계·새 인계 필요를 유지합니다. 정상 흐름의 구현 완료는 유효한 현재 조건과 완료 근거에 대한 서버 결과로 표시합니다. PR 링크·검증 요약은 수동 외부 근거이며 PlanRepo가 코드·테스트·배포를 자동 검증했다고 표시하지 않습니다.

## 7. 오류 표현·한국어·키보드

| 오류·상황 | 화면의 복구 행동 |
|---|---|
| VALIDATION_ERROR | 오류 필드와 누락 이유를 표시하고 해당 입력으로 이동합니다. |
| FORBIDDEN·NOT_ASSIGNED | 현재 역할/배정 사유를 표시합니다. 입력을 자동 폐기하지 않고 가능한 조회·담당자 안내를 유지합니다. |
| STALE_VERSION·STALE_BUNDLE | 읽은 기준과 최신 변경을 보여주고 다시 확인하게 합니다. 이전 승인 체크를 현재 묶음에 재사용하지 않습니다. |
| INPUT_CHANGED | 생성 입력과 현재 입력 차이를 표시하고 재생성·사람의 현재 초안 작성 경로를 연결합니다. |
| GATE_BLOCKED | 각 차단 사유·담당자·실제 처리 대상으로 연결합니다. 전체 폼 오류 한 줄로 숨기지 않습니다. |
| IDEMPOTENCY_CONFLICT | 다른 입력에 같은 요청 식별자를 사용한 사실을 표시하고 현재 입력·이전 처리 사실을 구분합니다. |
| STORE_UNAVAILABLE | 입력과 마지막 저장본을 유지하고 실패·재시도 방법을 표시합니다. 저장됨 표시를 갱신하지 않습니다. |
| PROVIDER_UNAVAILABLE·INVALID_OUTPUT | 확인 가능한 실패·형식 오류와 재시도 경로를 표시합니다. 성공 초안이나 Mock 결과로 바꾸지 않습니다. |
| RUN_FINAL | 현재 종료 상태를 다시 표시합니다. 끝난 실행을 취소·성공·실패로 임의 변경하지 않습니다. |
| 조회 실패·결과 확인 필요 | 빈 목록·등록 성공·완료 실패로 단정하지 않고 마지막 확인 상태와 재조회/동일 요청 재확인을 구분합니다. |

기본 UI 문구는 한국어입니다. 버튼은 답변 저장, 해결 확인, 결정 확정, 개별 승인, 단계 전환, 초안 적용, 인계 생성, 현재 기준 Markdown 내보내기처럼 실제 행동을 구분합니다. 식별자·출처·버전은 원 값을 유지합니다. 상태에는 텍스트·아이콘·의미 있는 숫자를 함께 쓰고 색만으로 구분하지 않습니다.

메뉴·탭·접기·문서 비교·폼·체크리스트·주요 제출을 키보드로 탐색하고 실행할 수 있게 합니다. 입력에 명확한 이름을 연결하고 현재 초점이 보이게 합니다. 제출 오류는 오류 요약과 필드에 연결합니다. 처리 대상 이동 시 해당 제목/필드에 초점을 옮깁니다. 조회 갱신이나 생성 상태 변경만으로 작성 중 초점을 빼앗지 않습니다. 접힌 패널에서도 열기 동작과 현재 차단 요약에 접근할 수 있어야 합니다.

Markdown과 외부 자료의 실행 가능한 HTML·스크립트는 실행하지 않습니다. 원문 비교·출처·링크도 같은 표시 안전성 원칙을 사용합니다. 외부 링크는 근거를 여는 행동이고 확인 완료·상태 동기화가 아닙니다. 비밀 값·원시 프로세스 진단·전역 경로·실제 조직 자료를 화면에 노출하지 않습니다.

사용성의 10초 목표는 대표 사용자가 보드에서 차단된 SR의 **차단 이유와 담당자**를 찾는지 관찰하는 기준입니다. 다음 행동 찾기·원문/변경점/결정 이유/버전 확인 후 승인도 관찰하지만 여기에 별도의 10초 완료 조건을 추가하지 않습니다. 실제 관찰 전에는 목표를 달성했다고 표시하지 않습니다.
