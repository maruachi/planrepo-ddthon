# Inception Plan: [시연] 테이블오더 서비스 MVP

## 요구사항

> 이 문서의 답변·검토·승인은 Codex가 로컬 가상 역할로 진행한 시연 기록입니다. 실제 요청자의 제품 범위 확정이나 운영 승인을 뜻하지 않습니다. 원문 요구 외의 시연 가정과 제안은 구현 전에 요청자가 확인합니다.

이 문서는 [시연] 테이블오더 서비스 MVP의 Inception Plan 보완안입니다. 원문 요구사항의 필수 기능을 보존하고, 사람이 저장한 답변으로 확인된 사실과 AI가 보완한 시연 가정을 구분해 정리합니다. 실제 구현·배포·성능 측정은 수행하지 않았습니다.

**원문 요구와 시연 범위**
- 주문 성공 후 주문 번호를 표시하고 장바구니를 비운 뒤 5초 후 메뉴로 이동합니다.
- 결제·정산 연동은 추가하지 않으며, 주문 접수와 준비중·완료 상태 변경, 이용 완료, 과거 이력까지 필수 기능으로 유지합니다.
- 관리자 SSE와 2초 이내 표시 요구는 필수로 유지합니다.

**시연 가정(미확인, 구현 전 요청자 확인 필요)**
- 메뉴 관리 CRUD·가격 범위·필수 검증·이미지 URL·노출 순서 조정은 후속 요구로 보존하고, MVP 메뉴는 초기 등록 데이터로 제공합니다.
- 단일 매장 사례로 설명하되 매장 식별자를 모든 인증·주문·이력 조회 범위에 포함하고 다른 매장·테이블 데이터 접근은 차단합니다.
- 고객 주문 상태 실시간 갱신은 선택사항으로 두고 새로고침·재조회 시 반영합니다.
- 관리자·단말의 16시간 인증과 첫 주문부터 이용 완료까지의 식사 세션을 분리하며, 인증 만료가 식사 이력을 자동 종료하지 않습니다.

**고객용 필수 기능(원문 보존)**
- 초기 설정: 매장 식별자·테이블 번호·테이블 비밀번호 입력, 최종 로그인 정보 로컬 저장, 1회 로그인 성공 후 자동 로그인.
- 메뉴 조회: 메뉴명·가격·설명·이미지 표시, 카테고리 분류, 카드 레이아웃, 최소 44x44px 터치 버튼.
- 장바구니: 추가·삭제·수량 증감·비우기·합계 계산, 새로고침 시 보존, 확정 시에만 서버 전송.
- 주문 생성: 매장·테이블·세션 ID와 품목·수량·단가·총액 포함, 실패 시 에러 표시 및 장바구니 유지.
- 주문 내역: 현재 세션 주문만 시간순 표시, 대기중/준비중/완료 상태, 페이지네이션 또는 무한 스크롤.

**관리자용 필수 기능(원문 보존)**
- 매장 인증: JWT 16시간 세션, 새로고침 유지, 만료 시 자동 로그아웃, bcrypt 해싱, 로그인 시도 제한.
- 실시간 모니터링: 테이블 카드 총액·최신 n개 미리보기·상세 보기·테이블 필터·신규 강조, SSE 기반 2초 이내 표시 목표.
- 테이블 관리: 단말 16시간 인증과 식사 세션 구분, 주문 삭제(확인 팝업·즉시 반영·총액 재계산·피드백), 이용 완료(확인·이력 보존·목록과 금액 0·다음 세션), 과거 주문 역순·날짜 필터·닫기, OrderHistory·세션 ID·완료 시각 기록.

**후속 요구(미확인)**
- 메뉴 관리 CRUD, 가격 범위 검증, 필수 필드 검증, 이미지 URL 입력, 노출 순서 조정.

### 원문 세부 조건 확인

- 관리자 로그인은 매장 식별자, 사용자명, 비밀번호를 입력합니다. 테이블 초기 설정은 관리자 1회 설정으로 수행합니다.
- 메뉴가 기본 화면이며 카테고리 사이를 빠르게 이동합니다. 장바구니 총액은 수량 변경 즉시 갱신합니다.
- 주문 내역에는 주문 번호, 시각, 메뉴와 수량, 금액, 상태를 표시합니다. 현재 테이블의 현재 식사 세션만 조회하며 이용 완료 처리된 주문은 제외합니다.
- 관리자 주문 상세에는 테이블 번호, 주문 번호, 시각, 메뉴와 수량, 총액을 표시합니다. 카드를 누르면 전체 메뉴 목록을 확인합니다.
- 식사 세션은 첫 주문에 시작하고 이용 완료에 종료합니다. 다음 고객은 첫 주문 시 새로운 세션을 시작합니다. 과거 내역에는 주문 번호, 시각, 메뉴 목록, 총액, 이용 완료 시각을 표시합니다. 이용 완료의 성공·실패를 안내합니다.
- 초기 메뉴 관리의 후속 범위에서도 메뉴명, 가격, 설명, 카테고리, 이미지 URL과 조회·등록·수정·삭제·노출 순서 요구를 보존합니다.

## 사용자 시나리오

여섯 가지 상황을 정리합니다. 아래 화면 문구는 모두 제안이며 사람 확인이 필요합니다.

**상황 1. 고객 메뉴 탐색**: 고객이 태블릿의 기본 메뉴 화면에서 카테고리별로 메뉴를 탐색합니다.
- 화면 제안 — 제목 '메뉴', 본문 '카테고리별 메뉴를 골라 담아 주세요', 상태 '탐색 중', 버튼 '장바구니 보기'.

**상황 2. 주문 성공**: 고객이 장바구니에서 수량을 조절한 뒤 주문을 확정하면 주문 번호를 표시하고 장바구니를 비운 뒤 5초 후 메뉴로 이동합니다.
- 화면 제안 — 제목 '주문 완료', 본문 '주문 번호를 확인해 주세요. 5초 후 메뉴로 이동합니다', 상태 '접수됨', 버튼 '메뉴로 돌아가기'.

**상황 3. 주문 실패**: 주문 전송에 실패하면 에러 메시지를 표시하고 장바구니를 보존합니다.
- 화면 제안 — 제목 '주문 실패', 본문 '잠시 후 다시 시도해 주세요. 담은 메뉴는 그대로 있습니다', 상태 '실패', 버튼 '다시 시도'.

**상황 4. 관리자 접수와 상태 변경**: 관리자가 SSE로 신규 주문을 받아 대기중·준비중·완료로 상태를 변경합니다.
- 화면 제안 — 제목 '실시간 주문', 본문 '테이블별 신규 주문을 확인하고 상태를 변경해 주세요', 상태 '실시간', 버튼 '상태 변경'.

**상황 5. 이용 완료와 과거 이력**: 관리자가 이용 완료를 처리하면 세션 주문이 과거 이력으로 이동하고 목록과 금액이 0으로 리셋됩니다.
- 화면 제안 — 제목 '이용 완료', 본문 '이 테이블 이용을 완료하시겠습니까? 주문 내역은 과거 이력으로 이동합니다', 상태 '확인 필요', 버튼 '이용 완료'.

**상황 6. 다음 고객 새 세션**: 리셋이 끝나면 다음 고객이 이전 주문 내역 없이 새 세션으로 시작합니다.
- 화면 제안 — 제목 '새 세션', 본문 '이전 주문 내역 없이 새로 주문해 주세요', 상태 '대기', 버튼 '메뉴 보기'.

## 진행 계획

1. Inception 정리: 원문 요구사항과 사람 답변, 시연 가정을 확인 상태로 구분해 정리합니다.
2. 시나리오·화면 제안 확정: 여섯 상황과 화면 제안을 요청자와 확인합니다.
3. 작업 단위 계획: 아래 작업 단위별 수용 기준과 검증 방법을 확정합니다.
4. 구현 전 확인: 시연 가정(메뉴 CRUD 후속·단일 매장·고객 재조회·결제 제외)을 요청자가 확정합니다.

이 계획으로 달라지는 점은 원문에 흩어져 있던 필수 기능과 미확인 가정이 하나의 Inception Plan으로 정리되어 검토와 확정 대상이 명확해진다는 것입니다. 테스트는 아직 실행하지 않았고 성능 수치는 실측 결과가 아닌 목표값입니다.

## 주요 구조

근거가 있는 관계만 정리합니다. 확인되지 않은 관계는 만들지 않습니다.

- 고객 태블릿 → 서버: 확정 시에만 주문 데이터를 전송합니다.
- 주문 확정 → 주문 실패: 주문 전송 실패 시 에러를 표시하고 장바구니를 보존합니다.
- 서버 → 관리자 대시보드: SSE로 신규 주문을 2초 이내 표시하도록 전달합니다.
- 이용 완료 → 과거 이력: 세션 주문을 OrderHistory로 이동하고 목록과 금액을 0으로 리셋합니다.
- 이용 완료 → 다음 고객: 리셋 후 다음 고객이 새 세션으로 시작합니다.
- 매장 식별자 → 데이터 접근: 인증·주문·이력 조회 범위를 매장 단위로 제한합니다.

## 주요 결정

**원문 요구와 시연용 결정**
- 주문 성공 후 5초 자동 이동을 적용합니다.
- 결제·정산은 범위에서 제외합니다.
- 관리자 SSE와 2초 이내 표시를 필수로 유지합니다.

**제안·미확인 결정(구현 전 확인 필요)**
- 중복 클릭·재시도는 같은 주문 요청 ID로 중복 생성을 방지하도록 제안합니다.
- 실패 시 장바구니를 보존하고 가격·합계는 서버에서 재검증하도록 제안합니다.
- 이용 완료와 주문이 동시에 발생하면 종료된 세션의 주문을 거절하고 새 세션으로 재확인하도록 제안합니다.
- 메뉴 관리 CRUD는 후속 요구로 두고 MVP는 초기 등록 데이터로 제공합니다.
- 단일 매장 사례로 설명하되 멀티 매장 확장 범위는 요청자가 확인합니다.
- 기술 스택·부하 규모·단말 갱신 정책·SSE 측정 조건은 담당자와 구현 전 확인합니다.

## 작업 단위

각 작업 단위에 수용 기준과 검증 방법을 함께 적습니다. 테스트는 아직 실행하지 않았습니다.

1. 태블릿 초기 설정·자동 로그인
- 수용 기준: 매장 식별자·테이블 번호·테이블 비밀번호를 입력해 저장하면 이후 재실행 시 저장된 정보로 자동 로그인됩니다.
- 검증 방법: 설정 후 앱을 재실행해 자동 로그인 여부를 수동 확인합니다. (미실행)

2. 메뉴 조회 화면
- 수용 기준: 메뉴명·가격·설명·이미지가 카드로 표시되고 버튼이 최소 44x44px를 만족합니다.
- 검증 방법: 초기 등록 데이터로 화면을 열어 표시 항목과 버튼 크기를 점검합니다. (미실행)

3. 장바구니 관리
- 수용 기준: 추가·삭제·수량 증감·비우기·합계 계산이 동작하고 새로고침 후에도 항목이 유지됩니다.
- 검증 방법: 항목을 담고 새로고침해 보존 여부와 합계를 확인합니다. (미실행)

4. 주문 생성과 성공·실패 처리
- 수용 기준: 확정 시 매장·테이블·세션 ID와 품목·수량·단가·총액을 전송하고, 성공 시 주문 번호 표시 후 5초 뒤 메뉴로 이동하며, 실패 시 에러를 표시하고 장바구니를 보존합니다.
- 검증 방법: 정상·실패 응답을 각각 재현해 화면 전환과 장바구니 상태를 확인합니다. (미실행)

5. 주문 내역 조회
- 수용 기준: 현재 세션 주문만 시간순으로 표시되고 대기중/준비중/완료 상태와 페이지네이션이 동작합니다.
- 검증 방법: 세션별 주문을 만들어 필터링과 정렬을 확인합니다. (미실행)

6. 관리자 인증
- 수용 기준: JWT 16시간 세션이 유지되고 새로고침 시에도 로그인 상태가 유지되며 만료 시 자동 로그아웃됩니다. 비밀번호는 bcrypt로 저장하고 로그인 시도를 제한합니다.
- 검증 방법: 세션 만료·새로고침·연속 로그인 실패 시나리오를 수동 확인합니다. (미실행)

7. 실시간 주문 모니터링
- 수용 기준: 테이블 카드에 총액·최신 n개 미리보기·상세 보기·필터·신규 강조가 표시되고 SSE로 신규 주문이 2초 이내 표시되는 것을 목표로 합니다.
- 검증 방법: 신규 주문을 발생시켜 표시 지연과 강조를 관찰합니다. 측정 조건은 미확인입니다. (미실행)

8. 테이블 관리
- 수용 기준: 주문 삭제는 확인 팝업·즉시 반영·총액 재계산·피드백을 제공하고, 이용 완료는 확인 후 세션 주문을 이력으로 보존하며 목록과 금액을 0으로 리셋해 다음 세션을 시작합니다. 과거 주문은 역순·날짜 필터·닫기를 제공하고 OrderHistory에 세션 ID와 완료 시각을 기록합니다.
- 검증 방법: 삭제·이용 완료·과거 조회 흐름을 순서대로 재현해 데이터 이동과 리셋을 확인합니다. (미실행)
