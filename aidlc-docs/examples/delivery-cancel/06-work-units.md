# 06. 작업 단위

> 이 파일은 하나의 `plan.md`에 있는 **작업 단위** 문단을 예시로 나눠 놓은 자료입니다. 실제 개발 작업이 배정되거나 완료됐다는 뜻이 아닙니다.

## 누가 무엇을 확인하나요?

기획 담당자와 개발 담당자는 고객에게 약속한 동작이 빠짐없이 작업으로 나뉘었는지 확인합니다. 검토자는 각 작업이 어느 요구사항과 예외를 다루는지 읽습니다.

- **사람이 판단합니다:** 작업의 범위, 순서, 담당, 완료 판단 기준을 실제 개발 전에 정합니다.
- **AI가 정리할 수 있습니다:** 문서의 화면, 서버 처리, 저장, 외부 서비스 내용을 후보 작업으로 묶습니다. 세부 코드와 배포 방법을 임의로 확정하지 않습니다.
- **용어 설명:** **작업 단위**는 한 목적과 결과를 중심으로 나눈 개발 준비 항목입니다. **구현 준비**는 코드를 만들기 전에 필요한 설계와 검증 기준을 구체화하는 과정입니다.

## Plan에서 나눈 내용

- 작업 단위 1: 주문 상세·취소 확인·취소 결과/환불 상태 화면 구성(고객 화면).
- 작업 단위 2: 주문 취소 API의 취소 확정 직전 배송 상태 재확인과 먼저 확정된 주문 상태를 유지하는 처리.
- 작업 단위 3: 주문 상태 저장소의 취소 완료/배송 시작 단일 확정과 반복 요청을 한 번만 처리하는 기능.
- 작업 단위 4: 환불 서비스 연동과 환불 접수·확인 중·완료 상태 표시 및 39,000원 예시 금액 표기.
- 작업 단위 5: 환불 응답 지연 시 '환불 상태 확인 중' 안내와 30분 기준 담당자 알림.

각 작업은 고객에게 약속한 동작을 기준으로 나눴습니다. 세부 코드·저장 기술·배포 작업은 다음 개발 과정에서 정합니다.
