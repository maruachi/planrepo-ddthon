# 03. 진행 계획

> 이 파일은 하나의 `plan.md`에 있는 **진행 계획** 문단을 예시로 나눠 놓은 자료입니다. 실제 개발 착수나 실제 직원 승인이 끝났다는 기록이 아닙니다.

## 누가 무엇을 확인하나요?

작성자는 초안이 어떻게 문서가 되고 수정되는지 확인합니다. 검토자는 현재 문서 버전을 읽고, 반드시 바꿔야 할 내용이 있으면 문단에 의견을 남긴 뒤 반영 여부를 확인합니다.

- **사람이 판단합니다:** 어떤 의견이 반드시 반영돼야 하는지, 현재 문서에 동의할 수 있는지 정합니다.
- **AI가 정리할 수 있습니다:** 요약, 빠진 질문, 문장 수정, 화면 예시를 선택적으로 제안합니다. AI 질문에 모두 답하는 일은 승인 조건이 아닙니다.
- **용어 설명:** **문서 버전**은 수정할 때마다 남는 문서의 한 시점입니다. **승인**은 검토자가 현재 버전의 내용에 동의한다는 뜻이며 실제 개발·배포 완료를 뜻하지 않습니다.

## Plan에서 나눈 내용

이 예시는 새 기능의 개발 전에 팀이 같은 문서를 읽고 동의하는 과정까지 진행합니다.

1. **초안을 올립니다.** 기획 담당자가 가지고 있던 설명을 그대로 올립니다. 올린 문서가 바로 Plan이 됩니다.
2. **필요한 부분만 다듬습니다.** 기획 담당자는 문서를 직접 수정할 수 있습니다. AI에게 요약, 빠진 질문, 문장 수정이나 화면 예시를 요청하는 것은 선택입니다.
3. **중요한 선택을 확인합니다.** 이 예시에서는 취소와 배송 시작이 겹칠 때 먼저 확정된 주문 상태를 유지하기로 정했습니다.
4. **동료 검토자 한 명에게 검토받는 것을 목표로 합니다.** 검토자는 고객에게 보여줄 내용과 예외 처리가 문서에 맞는지 읽고, 바꿔야 할 문단에 의견을 남깁니다.
5. **수정한 문서를 다시 확인합니다.** 작성자는 의견을 반영합니다. 시스템은 새 버전과 변경 내용을 연결합니다.
6. **문서를 승인합니다.** 검토자가 현재 문서를 승인하고 담당자가 승인 범위를 확정합니다. 이 승인은 문서의 내용에 대한 합의입니다.

AI 질문에 전부 답하거나 별도의 근거 기록을 작성하는 일은 승인 조건이 아닙니다. 사람이 리뷰에서 요청한 필수 수정은 해결 여부를 확인합니다.

이번에 확정하지 않는 일은 실제 개발 착수, 배포 일정, 실제 결제나 환불 실행입니다. 이 문서는 그 단계에서 활용할 계획입니다.
