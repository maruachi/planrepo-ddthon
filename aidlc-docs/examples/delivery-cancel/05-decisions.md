# 05. 주요 결정

> 이 파일은 하나의 `plan.md`에 있는 **주요 결정** 문단을 예시로 나눠 놓은 자료입니다. 실제 주문·환불 정책의 확정이 아닙니다.

## 누가 무엇을 확인하나요?

SR 담당자는 여러 선택지 중 어떤 원칙을 따를지 확인합니다. 검토자는 그 결정이 요구사항과 시나리오에 일관되게 반영됐는지 확인합니다.

- **사람이 판단합니다:** 배송과 취소 중 무엇을 우선할지, 반복 요청과 환불 지연을 어떤 정책으로 다룰지 정합니다.
- **AI가 정리할 수 있습니다:** 사람의 답변과 초안에서 결정 문장을 찾아 한곳에 모읍니다. AI 추천만으로 정책이 확정되지는 않습니다.
- **용어 설명:** **결정**은 여러 가능한 처리 방식 중 팀이 따르기로 한 원칙입니다. **정책**은 비슷한 상황에서도 일관되게 적용할 업무 기준입니다.

## Plan에서 나눈 내용

**결정: 먼저 확정된 주문 상태를 유지합니다.** SR 담당자가 답한 내용에 따라, 취소 확정 직전 배송 상태를 재확인해 배송 시작이 확인되면 배송을 우선합니다. 주문은 유지하고 취소·환불은 실행하지 않으며 반품 안내로 전환합니다. 배송 전 상태에서 취소 확정이 먼저 완료되면 취소 완료 상태를 유지하고 배송 시작 처리는 거절합니다. 두 상태 변경은 같은 주문에 대해 한 번만 확정되도록 합니다. 이는 예시 체험용 결정이며 실제 서비스 정책의 확정이 아닙니다.

**결정: 버튼을 여러 번 눌러도 한 번만 처리합니다.** 취소 요청 버튼을 반복해서 눌러도 주문 취소와 환불 요청은 한 번만 처리합니다.

**결정(확인됨): 환불 상태 구분과 지연 처리.** 환불 접수, 환불 상태 확인 중, 환불 완료를 구분해 보여 주고, 응답 지연 시 30분 기준으로 담당자에게 알립니다.

개발 전에 더 구체화할 내용: 반품 안내로 연결할 실제 주소, 운영 담당자에게 알리는 채널, 주문 상태를 한 번만 확정하는 저장 방식은 구현 준비에서 정합니다. 이번 문서 승인으로 이 세부 사항까지 정했다고 보지 않습니다.
