# 07. 문서 검토 결과

> 이 기록은 PlanRepo 로컬 시연에서 Codex가 작성자와 검토자 역할을 바꾸어 가며 만든 예시 기록입니다. 실제 직원이 검토했거나 실제 주문·환불을 처리했다는 뜻이 아닙니다.

## 누가 무엇을 했나요?

- **SR 담당자 역할**은 초안을 Plan 문서로 다듬고, 취소와 배송 시작이 겹치는 상황에 대한 질문에 답했습니다. 동료의 수정 요청을 문서 v3에 반영하고 반영 내용을 보고했습니다.
- **동료 검토자 역할**은 문서 v2의 `주요 결정` 문단을 읽고 일반 댓글 한 건과 필수 수정 요청 한 건을 남겼습니다. 수정된 v3을 다시 읽고 반영을 확인한 뒤 요청을 해결 처리했습니다.
- **시스템**은 댓글, 수정 요청, 문서 버전, 반영 보고, 해결 확인을 서로 연결했습니다.

## 일반 댓글

검토자는 고객이 **주문 취소**와 **실제 환불 완료**를 다른 상태로 이해할 수 있다고 보았습니다. 그래서 환불 접수 상태와 실제 돈이 돌아온 상태를 문서와 화면에서 나눠 보여 주면 좋겠다는 의견을 남겼습니다. 이 댓글은 참고 의견이며 승인을 차단하지 않았습니다.

## 필수 수정 요청

검토자는 `배송 우선`이라는 표현이 취소가 먼저 끝난 뒤에도 배송을 계속한다는 뜻으로 읽힐 수 있다고 지적했습니다. 다음 내용을 바꾸기 전에는 승인할 수 없는 수정으로 요청했습니다.

- 우선순위를 `먼저 확정된 주문 상태를 유지합니다`로 명확히 표현합니다.
- 주문 취소 완료와 환불 접수를 구분합니다.
- 배송 시작, 일부 취소, 환불 지연 때 고객에게 보여 줄 안내를 적습니다.

## 고객 관점에서 바뀐 점

| 수정 전에 모호했던 표현 | 문서 v3에서 확인한 표현 |
|---|---|
| 배송을 우선한다는 표현만으로는 취소가 먼저 확정된 경우가 불분명했습니다. | 취소와 배송 중 **먼저 확정된 주문 상태를 유지**합니다. |
| 주문이 취소되면 환불도 이미 끝난 것처럼 읽힐 수 있었습니다. | `주문 취소 완료`, `환불 접수`, `환불 확인 중`, `환불 완료`를 나눠 보여 줍니다. |
| 예외 상황에서 고객이 볼 안내가 부족했습니다. | 배송 시작 시 반품 안내, 일부 취소 시 고객센터 안내, 환불 지연 시 확인 중 안내를 구분합니다. |

## 반영 보고와 해결 확인

SR 담당자 역할은 문서 v3에 위 표현과 네 가지 상황의 고객 안내 문구를 추가했다고 보고했습니다. 동료 검토자 역할은 현재 v3 본문을 다시 읽고 다음 내용을 확인했습니다.

- 취소와 배송 중 먼저 확정된 상태를 유지합니다.
- 주문 취소·환불 접수·환불 완료를 구분합니다.
- 취소 성공, 배송 시작, 일부 취소, 환불 지연의 고객 안내를 확인했습니다.

이로써 필수 수정 요청은 `해결`로 남았습니다. 수정 요청을 숨기거나 AI가 자동으로 해결한 것이 아니라, 사람 역할이 수정과 확인을 각각 수행했습니다.

상세 저장 기록은 `aidlc-docs/examples/delivery-cancel/evidence/app-record.json`에 있습니다.
