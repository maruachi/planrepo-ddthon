# 추가 원문·재개 검증

독립 검토에서 사용자 답변이 선택지에 의존하는 경우 질문 맥락이 사라질 수 있다는 잠재적 공백을 제기했습니다. 이 우려는 기존 다섯 사례에서 관찰된 실패가 아니므로 스킬을 먼저 수정하지 않았습니다.

## 선택지 맥락 검증

별도 새 에이전트가 같은 스킬을 읽고 회의실 대행 정책의 A·B·C 선택 대화에 답했습니다. 사용자는 “B로 할게”라고 답하고 v1을 확인한 뒤 짧은 인계를 요청했습니다.

실제 결과는 `aidlc-docs/skill-development/intent-discovery/tests/followup/source-context.json`에 있습니다. S2로 원래 질문과 세 선택지를 보존하고, S3에 짧은 사용자 답변을 보존했습니다. S4에는 확인 대상 v1 설명을, S5에는 현재 확인 발언을 남겼습니다. 선택한 정책은 지정 대체 담당자의 해당 회의실 승인으로 유지했습니다. B를 선택한 별도의 동기는 미확인으로 남겼습니다.

관찰 결과는 PASS입니다. 질문 맥락 손실을 재현하지 못했으므로 추가 금지 문구나 재승인 절차를 넣지 않았습니다.

## 파일만 사용한 새 세션 재개

인계 문서를 `aidlc-docs/skill-development/intent-discovery/tests/followup/checkpoint.md`에 추출했습니다. 새 에이전트에는 스킬과 이 문서만 제공했습니다. 이전 대화·fixture·다른 결과는 제공하지 않았습니다.

“지난번 회의실 승인 결정을 이어서 구체화하자”라는 입력에 답했습니다. 실제 결과는 `aidlc-docs/skill-development/intent-discovery/tests/followup/checkpoint-resume.json`에 있습니다. 확인된 v1을 유지하고 대체 담당자를 지정하거나 바꿀 권한의 주체만 질문했습니다. 이미 선택한 부재 정책을 다시 묻지 않았습니다.

관찰 결과는 PASS입니다. 파일을 통한 문맥 복원과 미결정 재개를 확인했습니다. 모든 가능한 선택지 답변이나 장기 대화에서의 보존을 증명하지는 않습니다.

## 데이터 처리

일부 결과 JSON은 문서 개행을 이중 이스케이프로 저장했습니다. 원문 결과 JSON은 변경하지 않았습니다. checkpoint를 만들 때 본문 전체에 실제 개행이 없고 이스케이프 개행이 있을 때만 표시용 개행으로 변환했습니다. 문서의 문구·출처·결정 내용은 변경하지 않았습니다.
