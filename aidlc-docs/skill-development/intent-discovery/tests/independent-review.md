# 의도 탐색 스킬 독립 검토

제공된 다섯 green 응답에서 중요한 동작 실패는 발견하지 않았습니다. 사용자 답변이 앞선 AI 질문에 의존할 때 질문 원문을 보존하는 규칙에는 잠재적 공백이 있습니다. 이 공백은 아래 재현 대화로 추가 검증해야 하며, 관찰된 실패로 계산하지 않습니다.

## 검토 범위와 완료 기록

- [x] `aidlc-docs/skill-development/intent-discovery/skill/SKILL.md` 전체를 읽었습니다.
- [x] `aidlc-docs/skill-development/intent-discovery/skill/agents/openai.yaml`을 읽었습니다.
- [x] `aidlc-docs/skill-development/intent-discovery/tests/fixtures/S1.json`부터 `aidlc-docs/skill-development/intent-discovery/tests/fixtures/S5.json`까지 읽었습니다.
- [x] `aidlc-docs/skill-development/intent-discovery/tests/green/S1.json`부터 `aidlc-docs/skill-development/intent-discovery/tests/green/S5.json`까지 대조했습니다.
- [x] JSON 10개를 파싱하고 fixture의 사용자 발화 11개가 green 문서에 원문 그대로 포함됐는지 확인했습니다. 모두 포함됐습니다.

baseline-review와 다른 검토자의 판단은 읽지 않았습니다. 스킬과 제품 파일을 수정하지 않았습니다. 새 인터뷰, 제품 테스트, 웹 조회는 실행하지 않았습니다. 검토 중 발견한 잠재적 공백을 주 담당자에게 전달했으며, 주 담당자는 별도 재현을 준비하겠다고 알렸습니다. 그 재현 결과는 이 검토에 포함하지 않았습니다.

## 관찰된 결과

| 사례 | 관찰한 동작 | 판단 |
|---|---|---|
| S1 | 우선 해결할 불편과 기대 변화에 관한 연결된 질문을 하고 실제 답변을 기다립니다. 예시를 매장의 사실로 확정하지 않습니다. | 첫 질문의 적응성과 설문 강제 방지를 확인했습니다. |
| S2 | v1의 확인을 재사용하고 후속 기술 검토 때문에 인터뷰를 다시 열지 않습니다. 의도서 확인과 AI-DLC 단계 승인을 구분합니다. | 정상 인계 경계를 확인했습니다. |
| S3 | 질문 중단과 즉시 인계 요청을 함께 반영해 `provisional_handoff`로 정리합니다. 부재 대행·조회 정책을 미결정으로 남기고 기술 제안 위임을 정책 결정으로 확대하지 않습니다. | 중단 지시와 위임 범위가 유지됩니다. |

모든 green 응답은 장면 예시를 실행한 테스트로 주장하지 않습니다. MRBS와 테이블오더를 구현 대상으로 전환하는 동작도 없습니다. `openai.yaml`의 호출 설명은 인터뷰 목적과 일치합니다. 암시적 호출을 허용하지만 스킬 본문에는 승인된 구현이나 단순 수정에 인터뷰를 끼워 넣지 않는 범위 제한이 있습니다.

## 추가 검증이 필요한 원문 추적 공백

잠재적 중요도는 P2입니다. 근거는 `aidlc-docs/skill-development/intent-discovery/skill/SKILL.md:48`과 `aidlc-docs/skill-development/intent-discovery/skill/SKILL.md:52`입니다.

현재 규칙은 사용자 원 요청과 답변의 원문 보존을 의무화합니다. 확인 근거에는 버전·범위·발언을 남깁니다. 그러나 짧은 답변의 의미를 결정하는 AI 질문·선택지·제안 원문은 보존 대상으로 명시하지 않습니다. 의도 항목의 설명이 올바르면 당장의 의미는 유지됩니다. 다만 수신자가 그 설명과 사용자 답변의 대응을 원문으로 검증하려면 질문 문맥도 필요합니다.

제공된 green 응답은 확인 대상이 된 AI 설명을 A1 등의 출처로 보존합니다. 따라서 현재 결과에 원문 손실이 나타났다고 판단하지 않습니다. 다섯 fixture에는 선택지 문자나 지시어만으로 답한 사용자 발화가 없어 이 조건을 검증하지 못했습니다.

### 재현용 대화

다음은 추가 검증을 위한 구성 사례이며 실행한 결과가 아닙니다.

1. 사용자: “담당자가 없는 날의 예약 승인 방법을 정하고 싶습니다.”
2. AI: “A는 담당자가 돌아올 때까지 대기하는 방식입니다. B는 미리 지정한 대행자가 승인하는 방식입니다. 어느 쪽이 맞습니까?”
3. 사용자: “B로 하겠습니다. 여기까지 저장하고 다음에 이어갑시다.”
4. 새 세션에는 저장된 의도서만 전달합니다.

규칙을 사용자 원문만의 보존으로 해석하면 U2에는 “B로 하겠습니다”가 남고, 의도 항목에는 AI가 풀어 쓴 “지정 대행자가 승인합니다”만 남을 수 있습니다. 이 경우 재개 담당자는 B의 원래 문구와 범위를 독립적으로 복원할 수 없습니다. 의도 항목에 잘못된 해석이 들어갔는지도 원문으로 대조할 수 없습니다. 반대로 질문과 선택지를 출처로 보존하거나 접근 가능한 원문을 연결하면 이 위험은 발생하지 않습니다.

### 필요한 최소 보완

추가 재현에서 공백이 확인되면 원문·출처 항목에 다음 조건 한 문장만 추가하는 방안을 권고합니다.

> 사용자 답변이 선택지 번호·지시어·짧은 동의에 의존하면, 그 의미를 결정하는 AI 질문·선택지·제안 원문도 출처 ID로 보존하거나 수신자가 읽을 수 있는 원문에 연결합니다.

이 보완은 새로운 질문이나 재승인을 요구하지 않습니다. 기존 답변의 해석 근거만 보존합니다.

## 검증 범위의 한계

이번 검토는 저장된 단일 응답 결과를 읽고 대조한 검토입니다. S1 뒤에서 새 사용자 답변을 받아 후속 질문을 선택하는 반복 인터뷰 전체를 실행하지 않았습니다. 저장된 파일만으로 다른 세션에서 재개하는 동작도 실행하지 않았습니다. 판단 자체의 명시적 위임, 부분 확인, 답변 보정이 누적되는 긴 인터뷰의 동작은 현재 다섯 사례만으로 확인할 수 없습니다.

JSON 파싱과 원문 포함 여부 확인은 스킬 동작의 추가 실행이 아닙니다. 이 검토만으로 모든 변형 대화나 실제 설치 환경에서의 호출 순서까지 검증됐다고 주장하지 않습니다.
