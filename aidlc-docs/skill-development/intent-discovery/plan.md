# intent-discovery 스킬 작성·검증 계획

스킬 작성·검증·설치를 마쳤습니다. 사용자의 “오키 그럼 이를 따로 한번 만들어보자”를 앞선 스킬 설계의 구현 승인으로 적용합니다. PlanRepo 제품 구현과 분리한 스킬 산출물입니다.

## 범위와 배치

원본 스킬은 `aidlc-docs/skill-development/intent-discovery/skill/`에 둡니다. 검증 후 Codex 개인 스킬 폴더의 `intent-discovery/`에 복사합니다. 프로젝트의 기존 요구사항·AI-DLC 원본·단계·제품 코드와 시작 규칙은 변경하지 않습니다. 명시 호출과 제한된 의도 탐색 상황에서 사용할 수 있게 합니다.

원 요청·사람의 답변·해석의 지위를 기록하고 실제 응답을 기다리며 반복 질문합니다. 사용자 중단·위임·미결정 인계와 AI-DLC 승인 분리, 이후 Inception 재진입을 지원합니다. MRBS·테이블오더는 절차 검증 사례입니다.

## 실행 체크리스트

- [x] P1. 앞선 합의·Superpowers writing-skills·TDD·검증 지침·skill-creator 형식을 확인했습니다.
- [x] P2. 다섯 대화 시나리오와 동일 조건 비교 기준을 정의했습니다.
- [x] P3. 스킬 없는 다섯 독립 응답을 실행하고 원문과 실패 근거를 보존합니다.
- [x] P4. 실제 실패에 맞춰 최소 스킬·의도서 계약·AI-DLC 인계 안내를 작성합니다.
- [x] P5. 동일 시나리오를 새 독립 에이전트 다섯 개로 실행하고 의미 기준으로 비교했습니다. 적용군 5/5가 통과했습니다.
- [x] P6. 다섯 적용 사례에서 새 결함은 없었습니다. 독립 검토의 선택지 맥락 우려도 추가 실행에서 재현되지 않아 스킬을 더 변경하지 않았습니다.
- [x] P7. 5턴 모의 인터뷰의 탐색·보류·재개·확인·인계를 실행했습니다. 파일만 읽은 새 세션 재개와 독립 최종 검토도 확인했습니다.
- [x] P8. 본문·YAML·참조를 검증하고 개인 스킬로 설치했습니다. 공식 validator와 설치본 diff가 exit 0입니다.
- [x] P9. 사용법과 검증 명령·결과·한계를 기록했습니다. 최종 응답으로 설치와 호출 방법을 안내합니다.

## 행동 검증 기준

평가는 질문 개수나 특정 문구 일치보다 실제 행동을 봅니다. S1은 근거 없는 정책 확정 없이 목적을 탐색하고 사용자 응답을 기다려야 합니다. S2는 확인된 v1을 다시 묻지 않고 원문·합의·미결정·단계 승인 구분을 인계해야 합니다. S3는 명시적 중단을 존중하고 대행·조회 미결정을 확정으로 바꾸지 않아야 합니다. S4는 모순을 드러내고 변경된 내용에 과거 확인을 재사용하지 않아야 합니다. S5는 기존 목적·범위를 유지하고 새 설계의 이탈만 재검토해야 합니다.

원문과 결과는 `aidlc-docs/skill-development/intent-discovery/tests/`에 보존합니다. 스킬 없는 대조군과 스킬 적용군은 각각 다섯 개의 독립 실행입니다. 같은 모델의 사례 기반 관찰이며 확률적 품질이나 완벽한 의도 포착을 증명하지 않습니다. 테스트 에이전트가 스스로 사용자 답변을 만들어 다음 턴으로 넘어가지 못하게 합니다.

## 개발 규칙 적용

기존 워크플로우의 앞단 도구를 따로 만드는 승인된 요청입니다. PlanRepo Code Generation의 진행 상태는 유지합니다. 이미 표시한 Welcome과 이미 결정한 비활성 확장을 다시 묻지 않습니다. 사용자 원문·진행·검증은 `aidlc-docs/audit.md`에 append합니다. 외부 게시·push·PR은 이 요청에 포함하지 않습니다.
