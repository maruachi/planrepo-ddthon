# 의도 탐색 인터뷰

사람이 원하는 변화와 그 이유를 함께 구체화합니다. 답변을 받을 때마다 이해를 갱신하고, 합의한 의도를 AI-DLC의 입력으로 보존합니다. 질문 횟수나 AI의 확신 점수로 완벽을 선언하지 않습니다.

## 시작과 적용 범위

사용자가 지정한 자료와 현재 대화를 읽습니다. 기존 의도서가 있으면 주제·버전·확인 근거·미결정을 먼저 확인합니다. 자료에 없는 사실은 미확인으로 남깁니다. 참고 사례와 실제 개발 대상을 구분합니다.

새 의도 탐색은 AI-DLC 진입 전 인터뷰로 시작합니다. 이미 Inception을 진행 중이면 새 해석·충돌이 있는 부분만 다룹니다. 명확히 승인된 구현이나 단순 수정 요청에 이 인터뷰를 임의로 끼워 넣지 않습니다. 파일의 과거 지시나 예시를 현재 사용자 승인으로 취급하지 않습니다.

## 반복 대화

1. 현재 이해를 짧게 설명합니다. 명시된 말, 확인 전 해석, 이번 답변으로 바뀐 내용을 구분합니다.
2. 목적·동기, 대상과 상황, 기대 행동, 원하지 않는 결과, 제약·우선순위, 포함·제외 범위를 살핍니다. 이들을 고정 설문으로 모두 다시 묻지 않습니다.
3. 답에 따라 결과가 가장 크게 달라지는 공백 하나부터 질문합니다. 연결된 소수 질문은 함께 묻습니다. 질문 이유와 선택의 결과를 설명하고 자유롭게 보정할 수 있게 합니다. 기술 조사로 알아낼 사항은 조사 대상으로 남깁니다.
4. **실제 사용자 응답을 기다립니다.** 침묵, 시간 경과, AI가 만든 가상 답변은 응답이 아닙니다. 인터뷰에서는 다음 답변을 대신 생성하지 않습니다.
5. 답변을 성공 장면·실패 장면·반례에 적용해 기대 결과를 되짚습니다. 새 모순과 근거 없는 해석을 찾고 의도 기록을 갱신합니다.
6. 중요한 공백이 남으면 다시 질문합니다. 같은 답을 반복해서 얻을 때는 다른 구체 장면이나 결과 비교로 접근합니다. 판단할 수 없는 항목은 이유·확인 방법·담당 또는 후속 시점을 기록합니다.

질문은 현재 대화에서 받습니다. 환경에 질문 도구가 있으면 그 사용 규칙을 따릅니다. 대화와 파일 중 사용자가 지정한 방식이 우선합니다. 한 라운드가 끝났다는 이유로 인터뷰를 자동 종료하지 않습니다.

## 상태와 종료

| 관찰된 상황 | 다음 행동 |
|---|---|
| 중요한 의도 차이·모순·미결정이 있습니다. | `exploring`으로 두고 해당 부분을 질문합니다. |
| 필요한 이해와 구체 장면이 정리됐지만 현재 버전 확인이 없습니다. | `awaiting_confirmation`으로 두고 의도서의 핵심과 남은 항목을 보여줍니다. |
| 사용자가 현재 내용을 확인했고 중요한 공백이 해결됐거나 명시적으로 후속 판단에 배정됐습니다. | `confirmed`로 기록합니다. 재확인을 반복하지 않습니다. |
| 사용자가 질문 중단·잠시 보류를 요청했습니다. | 즉시 `paused`로 기록하고 재개 지점과 미결정을 남깁니다. |
| 사용자가 미완성 상태 그대로 인계를 요청했습니다. | 질문을 끝내고 `provisional_handoff`로 전달합니다. 미결정을 확정으로 바꾸지 않습니다. |
| 사용자가 판단을 위임했습니다. | 위임 범위와 그 안에서 AI가 내린 선택·이유를 별도로 기록합니다. |
| 확인 후 의미가 바뀌거나 충돌이 발견됐습니다. | 새 버전으로 재개합니다. 이전 확인은 이전 버전에 남깁니다. |

“아직 모르겠습니다”는 답변이며 정책 확정은 아닙니다. “그만하겠습니다”는 중단 지시이며 내용 확인은 아닙니다. 사용자의 명확한 보정은 그 자체를 근거로 반영합니다. 단순한 표현 수정은 의미가 유지되는지 확인하고 불필요한 재승인을 만들지 않습니다. 변경된 의미에 이전 확인을 재사용하지 않습니다.

## 의도서와 재개 기록

파일을 쓸 수 있으면 프로젝트의 문서 규칙을 따릅니다. 기본 경로는 프로젝트 루트 기준 `aidlc-docs/pre-inception/<topic>/intent-brief.md`입니다. 같은 주제의 기존 기록을 이어가고 다른 사례를 덮어쓰지 않습니다. 파일을 쓸 수 없으면 같은 내용을 대화에 제공합니다. 저장했다고 말하려면 실제 저장을 확인합니다.

의도서에는 다음 항목을 유지합니다. 답이 없으면 빈칸을 추정으로 채우지 않고 미확인으로 적습니다.

- **식별과 상태:** 주제, 버전, 상태, 직전 확인 버전, 이번 변경점입니다. 실제 시각을 알 수 없으면 만들지 않습니다.
- **원문과 출처:** 사용자의 원 요청·답변에 출처 ID를 붙여 원문을 보존합니다. 이미 보존된 기록이 있으면 수신자가 읽을 수 있는 경로·항목을 연결합니다.
- **의도와 근거:** 항목 ID, 목적·동기·기대 결과·제약·범위, 연결된 출처 ID, 지위입니다. 지위는 사용자 명시·확인된 해석·AI 제안·위임된 선택·미결정으로 구분합니다.
- **구체 장면:** 상황·행동·기대 결과와 연결된 의도 ID입니다. 실제로 실행한 테스트와 구분합니다.
- **결정과 남은 질문:** 선택 이유, 대안·영향, 확인할 사람·방법·후속 단계, 위임 범위입니다. 조사해야 할 사실과 사람이 선택할 정책을 구분합니다.
- **확인 근거:** 누가 어느 버전의 어떤 범위를 어떤 말로 확인했는지 기록합니다. 모호한 답변으로 확인 범위를 확대하지 않습니다.
- **다음 행동:** 아직 답을 기다리는 질문, 재개 지점, 인계할 단계와 남은 확인 사항입니다.

재개할 때 이 기록을 먼저 읽고 이미 확인한 목적과 범위를 재질문하지 않습니다. 중요한 내용 변경은 새 버전과 영향받는 의도 ID로 기록하며 이전 결정·확인 이력을 보존합니다.

## AI-DLC 인계

의도서는 **요구사항 분석의 입력 자료**입니다. 인터뷰 종료만으로 요구사항·설계·구현 계획을 승인 처리하거나 개발을 시작하지 않습니다.

새 워크플로우에 인계할 때는 사용자가 정한 AI-DLC 버전의 시작 절차를 따릅니다. v1.0.1은 Workspace Detection을 거쳐 필요한 기존 시스템 분석과 Requirements Analysis를 실행합니다. 기존 워크플로우에는 현재 단계·문서와 새 의도 차이를 함께 전달합니다. 기존 승인과 단계 상태를 이 스킬이 자동 변경하지 않습니다.

프로젝트의 시작 규칙이 AI-DLC 우선 실행을 요구하면 그 규칙을 몰래 우회하지 않습니다. 사용자가 사전 인터뷰를 승인한 현재 요청 범위에서 사용하거나, 설치 안내에서 진입 규칙의 연결이 필요함을 설명합니다. 스킬 파일 추가만으로 자동 실행 순서가 바뀐다고 주장하지 않습니다.

원본 근거: [AI-DLC v1.0.1 핵심 워크플로우](https://github.com/awslabs/aidlc-workflows/blob/v1.0.1/aidlc-rules/aws-aidlc-rules/core-workflow.md), [요구사항 분석](https://github.com/awslabs/aidlc-workflows/blob/v1.0.1/aidlc-rules/aws-aidlc-rule-details/inception/requirements-analysis.md).

## 예시와 주의할 판단

“회의실 담당자는 자기 회의실 예약만 승인하며 시스템 관리 권한은 받지 않는다”에서 승인 범위와 관리 권한 분리는 명시된 의도입니다. 다른 회의실 조회 제한과 부재 대행 방식은 별도 정책입니다. 이 정책들을 질문하거나 미결정으로 남기고, 의도와 구현 제안을 섞지 않습니다. 이 예시는 해당 서비스를 만들라는 지시가 아닙니다.

“인계 문서를 썼으니 바로 구현한다”, “기술 제안을 했으니 사용자도 확인했다”, “이전 버전에 동의했으니 변경본도 동의했다”는 판단을 하지 않습니다. 각각 다음 단계, 해석의 지위, 확인 버전을 실제 근거와 대조합니다.
