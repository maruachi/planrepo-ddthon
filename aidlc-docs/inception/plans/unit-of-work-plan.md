## 작업 단위와 완료 범위

세 단위는 하나의 로컬 앱을 순서대로 완성하는 개발 작업 묶음이다. 승인 실행 계획의 세 단위와 Code Generation의 Greenfield multi-unit monolith 구성 패턴을 따른다. 단위별 배포·서버·DB를 만들지 않는다.

| 단위·문서 디렉터리명 | 주 책임과 컴포넌트 | 해당 단위 완료 시 확인할 범위 |
|---|---|---|
| U1 sr-document-foundation | C03 생성/보드/상세, C04 전체 문서 계약, C09 저장 기반, C10 직접 입력; C01/C02 앱 기반·문서 UI/전송 | SR 생성·재열람, 문서 편집·이력·비교·복원, 참조와 사건 저장. 후속 계획/리뷰 데이터용 확장 계약 |
| U2 aidlc-planning | C05·C07·C08·C11, 계획 UI/전송, 실행/질문/응답/결정 저장 확장 | 실제 CLI 생성·실패·질문 결과, SR 문맥과 사건, 단계·회차·자체 승인, 코드 구현 직전 종료와 구현 대기 전환 |
| U3 review-implementation | C06, C01 역할/리뷰/수동 완료 UI, 해당 C02 명령, C03.markImplemented, 리뷰 저장 확장 | 버전 고정 비차단 리뷰, 새 버전과 대상 구분, 수동 완료, 전체 사용자 흐름 통합 검증 |

U1 → U2 → U3 순서로 각 단위의 Functional Design → NFR Requirements → NFR Design → Code Generation(계획·생성)을 마친다. Infrastructure Design은 기존 승인대로 생략한다. 전체 단위 완료 뒤 Build and Test를 수행한다. 해당 단계의 승인 절차는 유지한다.

## 스토리 배정안

주 담당은 수용 기준을 추적하고 최종 통합 확인을 책임지는 단위이다. 다른 단위에서 먼저 구현되는 기능이나 이후 생기는 데이터 생산 경로를 협력 범위로 명시한다. 선행 단위에서 준비 데이터로 확인한 것을 전체 스토리 완료로 기록하지 않는다.

| 스토리 | 주 담당 | 협력 및 완료 경계 |
|---|---|---|
| US-01 SR 직접 생성 | U1 | C10 외부 입력 경계 포함. Git/Jira 없이 저장·필수값·첨부 확인 |
| US-02 칸반 단계·회차 | U2 | U1 고정 6열·카드/상세, U2 단계·회차, U3 리뷰 별도 표시·최종 완료 위치. 전체 기준은 U3 후 확인 |
| US-03 실제 AI 생성 | U2 | U1 prepareGenerated/commit 재사용. 실제 생성·저장·UI 열람으로 완료 |
| US-04 생성 실패 | U2 | 실행·결과·저장 실패가 성공으로 공개되지 않는지 확인 |
| US-05 질문·결정 | U2 | U1 사건/버전 기반 사용. U3 리뷰와 자체 승인의 구분 통합 확인 |
| US-06 문서 재열람 | U1 | U2 실제 생성 문서, U3 리뷰 역할에서도 기존 열람 경로 재사용·확인 |
| US-07 문서 편집 | U1 | U2 실행 중 편집/늦은 결과 통합 시 기존 버전 보존 확인 |
| US-08 문서·결정 이력 | U1 | U1 조회/보존, U2 AI·질문·결정 사건 생산, U3 리뷰 사건 생산. 전체 사건 범위는 U3 후 확인 |
| US-09 버전 비교 | U1 | U3 리뷰 역할에서 재사용. 비교가 저장 데이터를 바꾸지 않음 |
| US-10 과거 내용 복원 | U1 | 과거 원본과 복원 전 최신을 보존하고 새 버전·사건 생성 |
| US-11 비차단 리뷰 요청 | U3 | U1 VersionRef, U2 자체 진행 정책과 실제 후속 진행으로 검증 |
| US-12 대상 버전 검토 | U3 | U1 정확한 버전 열람/이력 재사용, 역할 전환·이후 버전 구분 |
| US-13 구현 대기 | U2 | C05.completePlanning/C11과 UI를 U2에서 구현. U3에서 수동 완료까지 연결 검증 |
| US-14 수동 구현 완료 | U3 | U1 C03에 markImplemented 추가, U2 구현 대기 상태만 수동 완료 처리 |

실행 계획의 잠정 US-11–US-14 묶음 중 US-13의 주 구현을 U2에 배정한다. 승인 Application Design의 C05.completePlanning 소유권에 따른 구체화이며 U3는 구현 대기부터 수동 완료까지 통합 확인을 맡는다. 제품 기능이나 순서는 바꾸지 않는다.

FR-01/05/06/09의 저장·문서 기반은 U1, FR-02/03/04 및 FR-08의 계획 종료는 U2, FR-07과 FR-08의 수동 완료는 U3에 연결한다. FR-02의 리뷰 표시와 FR-06의 사건 생산은 위 협력 범위로 추적한다. NFR-01–NFR-06은 모든 단위의 공통 제약이며 단위별 해당 검증에 연결한다.

## 공유 계약과 통합 책임

| 계약·영역 | 기반 담당 | 후속 단위의 책임과 제한 |
|---|---|---|
| C01/C02 앱 조립·전송 | U1 | U2 계획 화면/명령, U3 리뷰/역할/완료 화면/명령을 같은 앱에 추가. 신규 단위마다 별도 서버 생성 금지 |
| VersionRef·HistoryEvent·ActorContext | U1 | U2 실행/질문/결정, U3 리뷰/완료 사건 추가. 소속 검증과 본문 없는 사건 보존을 공통 적용 |
| C09 read/commit | U1 | U2/U3가 자기 도메인의 조회·변경 타입과 저장 스키마를 확장하며 기존 저장 계약 유지. U1 코드가 U2/U3 서비스를 호출하지 않음 |
| C04.prepareGenerated | U1 | U2가 호출해 얻은 DocumentChanges를 Run/질문/진행 결과와 함께 한 commit에 반영. 별도 선행 문서 저장 금지 |
| WorkflowState | U1 초기 SR 목록 상태·보관, U2 진행 의미 | U2가 단계/회차/승인/구현 대기 판단. U3는 C03.markImplemented로 수동 최종 전환만 추가. 이중 상태 원본 금지 |
| 리뷰 문맥 | U2의 C07 읽기 계약 | U3가 Review 저장/조회 형식을 연결. U2에서는 리뷰 없음으로 실행 가능. C07에서 C06으로 역호출하는 의존성 추가 금지 |
| 뒤늦은 생성 결과와 편집 | U1 버전·최신 포인터 기본 규칙 | U2가 실행 입력 버전과 결과 도착 시 처리를 구체화·검증. 이전 문서를 덮어쓰지 않으며 변경 시 공통 계약 문서 갱신 |
| 스택·저장·실행 설정 | U1 NFR Requirements/Design | U2는 CLI의 실행/입력/출력/중단과 상태 처리 추가, U3는 리뷰·역할·키보드 사용성 적용. 기존 선택 재사용 |

U1에서 미래 도메인의 모든 상세 필드를 추측해 구현하지 않는다. 현재 설계의 공통 식별자·VersionRef·변경/사건 저장 의미를 먼저 정의하고, U2/U3가 필요한 구체 타입을 추가한다. 후속 확장 시 기존 SR·문서·사건 보존을 검증한다.

## 의존성 계획

행은 의존하는 단위, 열은 선행 기반 단위이다. X는 개발/통합 선행 조건이며 독립 네트워크 서비스 호출을 뜻하지 않는다.

| 단위 | U1 | U2 | U3 |
|---|---|---|---|
| U1 | - | - | - |
| U2 | X | - | - |
| U3 | X | X | - |

U2는 U1의 SR·문서·버전·사건·저장 계약을 사용한다. U3는 U1의 버전/저장과 U2의 계획 진행·구현 대기 상태를 사용한다. C06 리뷰 서비스 자체는 C05를 호출하지 않고, 통합 UI가 진행과 리뷰를 각각 호출한다. U3에서 추가하는 C03 메서드 역시 U2 서비스 호출을 요구하지 않는다. U2의 리뷰 문맥 읽기는 공통 저장 계약이므로 U3 코드 선행 의존성이 아니다.

## Greenfield 코드 구성 제안

아래는 논리 배치 계획이다. 아직 앱 디렉터리나 코드를 만들지 않는다. 프레임워크의 라우트·엔트리 파일 규칙은 U1 기술 선택 후 이 책임 구조에 맞춘다.

| 경로 | 배치 책임 |
|---|---|
| src/sr-document-foundation/ | SR·문서·버전·이력·저장·입력 경계 및 관련 화면/전송 모듈 |
| src/aidlc-planning/ | 계획 서비스·정책·문맥·CLI 어댑터 및 계획 화면/전송 모듈 |
| src/review-implementation/ | 리뷰 기능·역할 화면·수동 완료 사용자 흐름. C03.markImplemented는 C03의 기존 위치에 추가 |
| src/shared/ | 공통 식별/결과/참조 계약만 배치. 계획/리뷰 서비스를 공통 모듈로 옮겨 역의존을 만들지 않음 |
| src/app/ | 단일 앱 조립·서버/브라우저 진입과 라우트 연결. 프레임워크에 따라 위치 조정 가능 |
| tests/sr-document-foundation/, tests/aidlc-planning/, tests/review-implementation/ | 해당 단위에서 필요한 의미 있는 검증 |
| tests/integration/ | 단위 연결 검증이 자동화될 경우의 위치. 전체 E2E 자동화는 필수 아님 |
| config/ | 필요 시 로컬 실행 설정. 데이터 위치·CLI 설정의 실제 값은 NFR에서 결정 |
| aidlc-docs/construction/{unit-name}/ | 해당 단위 설계와 코드 요약 문서만 저장 |

하나의 프로젝트 빌드/실행 설정을 공유한다. 실제 저장 데이터 위치는 U1 NFR에서 결정한다. 원문 requirements/와 기존 사용자 파일은 보존한다.

## 단위 인계와 검증 계획

1. U1: SR 저장·재열람, 선택 버전 열람·편집·비교·복원, 본문 변화 없는 사건, 버전 소속·이력 보존을 확인한다. 계획 문서는 검증용 준비 데이터로 기능 확인 가능하며 실제 AI 생성 증거는 U2에서 얻는다.
2. U2: 실제 Claude Code CLI로 문서를 생성·저장·UI 열람하고 실패 표시를 확인한다. 질문만 있는 정상 결과, 자체 승인/수정 요청, 회차·단계·구현 대기, 실행 결과와 문서 변경의 일관된 저장을 검증한다. 정확한 CLI 옵션·인증 유효성은 아직 확인하지 않았다.
3. U3: 리뷰 요청 중 후속 계획 진행, 원래 버전 검토와 최신 버전 구분, 역할 전환, 수동 완료, 모든 사건과 카드 표시를 연결한다.
4. Build and Test: 승인된 핵심 통합 흐름 1개, 실제 CLI 실패 경로, 저장 재열람과 주요 키보드 조작을 확인한다. 단계 규칙의 필수 지침 문서를 작성하며 비적용 성능/PBT 항목은 N/A로 남긴다.

이 목록은 후속 검증 계획이며 현재 테스트 통과 기록이 아니다. 하루 목표와 기존 승인 범위를 유지한다. CLI 실행 불가나 저장/참조 문제가 발견되면 사실을 기록하고 해결하며 모의 성공으로 대체하지 않는다.
