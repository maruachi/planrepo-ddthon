# Plan 중심 제품 의도 재정렬

버전은 0.4입니다. 상태는 confirmed입니다. 사용자가 최신 응답에서 플랫폼 범위를 AI-DLC Inception까지로 명시했습니다. 이 과정의 문서 전체를 Plan으로 부릅니다. 확인 근거는 S3이며, 구체적인 저장·화면 선택은 아래 구현 계획의 AI 판단으로 구분합니다. 이전 0.1의 개발 실행 포함 해석은 S3으로 정정합니다.

## 최신 문서 중심 결정

현재 프로토타입은 초안 원문에서 시작합니다. 사용자는 **문서**, **요약·시각화**, **공유·리뷰** 세 탭에서 하나의 현재 Plan 버전을 읽고 검토합니다. 문서가 비어 있지 않고 사람이 남긴 차단 수정 요청이 해결됐으며 지정 검토자가 현재 버전을 승인하면 공식 문서 검토를 완료할 수 있습니다.

요구사항, 사용자 시나리오, 진행 계획, 주요 구조, 주요 결정, 작업 단위는 완전한 예시의 여섯 문단입니다. 여섯 문서를 따로 작성하거나 모든 문단을 채우는 일은 검토 조건이 아닙니다. `aidlc-docs/examples/delivery-cancel/README.md`에서 예시 원문, 문단별 안내, 문서 v3에 대한 로컬 검토·승인 시연 결과를 읽을 수 있습니다. 이 결과는 하나의 사용자가 가상 역할을 바꾸어 가며 진행했으며 실제 직원 검토가 아닙니다.

AI 질문에 모두 답하거나, 근거를 별도 입력으로 옮기거나, 답변이 문서에 반영됐다는 확인을 따로 남기는 일은 필수가 아닙니다. AI 질문과 근거는 문서 검토를 돕는 참고 추천입니다. 사람은 의도와 중요한 결정을 확인하고, 내용 변경을 채택할지 선택하며, 현재 문서를 최종 승인합니다. 시스템은 구조와 관련 내용을 연결하고, 참고 추천을 표시하며, 문서 버전과 검토 이력을 관리합니다.

질문 답변 후보를 선택하거나 자유롭게 답하는 행동, AI 보완안을 채택하는 행동은 작성과 리뷰 맥락 안에 둑니다. AI 정리와 시각화는 결재 전 문서 검토의 선택 보조 기능입니다. AI 대화와 그래프 생성을 정규 통과 단계로 강제하지 않습니다.

결재 완료본은 읽기 전용으로 유지하고 승인 이력을 보존합니다. 화면 전용 그림을 꾸미기 위해 승인 뒤 문서를 바꾸는 흐름을 정규 단계로 두지 않습니다. 새 요구 변경이 생기면 사용자가 명시적으로 개정안 준비를 시작합니다. 문서 내용을 저장하거나 AI 제안·질문을 반영해 현재 검토 기준이 바뀌면 영향받는 범위를 재검토합니다. 기존 결재본을 열람하거나 AI 개정안을 생성만 한 경우에는 승인 상태를 변경하지 않습니다. 이 화면 흐름을 구현하고 격리 앱에서 작성·검토·결재와 승인본 열람을 검증했습니다. 초안 Grill-me 필수화는 후속 논의이며 현재 AI 질문은 선택 기능입니다.

## 원문과 근거

S1은 aidlc-docs/audit.md의 “Plan 중심 제품 의도 재정렬”에 보존한 사용자 전체 원문입니다. 사용자는 정확한 Plan 구성, Plan Review, Unified UI를 설명했습니다. 문서 단위 검토와 Inception까지 사람·AI의 이해를 맞추는 과정을 핵심으로 명시했습니다.

S3은 같은 감사 기록의 “Inception 범위 확정”에 보존한 최신 사용자 원문입니다. SR별 Inception 문서 작성, 주요 구조·결정의 요약/시각화, 공유·결재가 플랫폼 범위입니다.

S2는 같은 감사 기록의 “프로토타입 시연 범위 질문”입니다. 답변은 현재 대화에서 받습니다. 기존 프로토타입·시간 우선·새 TDD 후속 지시는 유지합니다.

## 현재 구현과의 차이

확인한 기능과 아직 없는 경험을 구분합니다.

- GenerationAssistant는 질문 제안 또는 문서 초안을 요청합니다. 특정 답변을 AI가 어떻게 해석했는지 되짚고 사람이 교정하는 대화 흐름은 없습니다. src/web/components/GenerationAssistant.tsx와 src/contracts/views.ts의 GenerationInput을 확인했습니다.
- 질문 선택, 답변, 해결 확인, 후속 질문 작성, 문서 반영이 서로 다른 폼과 탭에 있습니다. src/web/components/QuestionPanel.tsx, DraftReview.tsx, SRDetail.tsx를 확인했습니다.
- 댓글·수정 요청의 조회와 저장 서비스는 있습니다. 현재 문서 검토 화면에는 문단에서 댓글·수정 요청·해결을 이어가는 UI가 없습니다. src/web/components/ReviewSummary.tsx, BundleReviewForm.tsx와 src/application의 변경 요청 서비스를 확인했습니다.
- SR별 검토자 배정 M-030과 UI 모두 관리자만 허용합니다. src/application/review-policy-service.ts와 src/web/components/SRReviewAssignment.tsx를 확인했습니다.
- 기존 요구사항의 DEC-01은 한 프로젝트 데모이며 FR-21은 외부 구현 수동 기록입니다. I5·I6의 최종 제품 방향과 이번 시연 범위를 구분해야 합니다. 현재 AI 생성 연결만으로 실제 개발까지 연결됐다고 표시하지 않습니다.

질문·답변 이력, 문서 버전, 고정 AI 입력, 사람의 초안 적용, 검토 승인과 변경 이력은 재사용합니다. 프로토타입 P1~P8의 완료는 당시 범위와 검증 근거이며 새 의도의 충족 판정이 아닙니다.

## 추천하는 사용 흐름

1. 사용자가 하고 싶은 일이나 기존 초안을 원문 그대로 올립니다. 같은 화면에서 함께 검토할 사람을 고릅니다.
2. **문서** 탭에서 원문을 읽고 직접 수정합니다. 필요하면 같은 작성·리뷰 맥락에서 AI 질문의 답변 후보를 선택하거나 자유 답을 적고, AI 보완안을 채택할지 정합니다. AI 질문에 모두 답해야 다음으로 갈 수 있는 것은 아닙니다.
3. **요약·시각화** 탭에서 현재 문서의 요지, 주요 구조, 상황별 흐름을 원문과 함께 확인합니다. 시스템은 근거가 있는 내용을 연결하고 미확인 AI 추천을 구분합니다.
4. **공유·리뷰** 탭에서 작성자와 동료가 같은 현재 문서 버전을 검토합니다. 검토자가 남긴 차단 수정 요청은 해결 여부를 확인하고, 현재 버전에 동의하면 승인합니다.
5. 승인은 정확한 문서 버전에 연결합니다. 승인된 버전은 읽기 전용으로 유지하고 원래 승인 이력을 보존합니다. 실제 개발 실행은 S3에 따라 플랫폼 범위에서 제외합니다.
6. 새 요구 변경이 생기면 명시적으로 개정안 준비를 시작합니다. 문서 내용을 저장하거나 AI 제안·질문을 반영해 검토 기준이 바뀌면 영향받는 범위를 재검토합니다. 열람과 생성만으로는 승인을 바꾸지 않습니다.

“접수”, “요구사항 정리”, “계획·설계”는 내부 진행 정보로 남길 수 있습니다. 첫 화면은 현재 요청된 행동을 설명합니다. 예를 들어 “답변을 기다리고 있습니다”, “검토 의견을 확인해 주세요”, “동료가 검토 중입니다”를 보여 줍니다. AI-DLC 단계와 생성 문서 전체는 필요할 때 펼쳐 봅니다.

Inception 종료의 근거는 목적·범위·주요 동작·예외·완료 조건·미결정을 사람이 읽고 확인한 기록입니다. AI의 자신감 점수나 질문 개수만으로 이해가 일치했다고 판정하지 않습니다. 실제로 일치하는지는 문서와 구체적인 성공·실패 사례로 검토합니다.

## 검토자 선택의 경계

I7에 따라 Plan을 올리는 사람의 검토자 지정 경로가 필요합니다. 팀 공통 검토 정책의 편집 권한까지 넓히는 요구는 아닙니다.

현재 최초 등록자는 originalDescription.authorId로 조회되고 담당자는 sr.ownerId입니다. 두 사람이 항상 같지는 않습니다. 단순히 관리자 조건을 owner 조건으로 바꾸고 등록자 요구까지 해결했다고 판정하지 않습니다.

간단한 시작 흐름에서는 등록자를 Plan 작성자·담당자로 기본 설정하는 안을 제안합니다. 다른 사람에게 담당을 넘긴 뒤 최초 등록자의 권한을 유지할지는 별도 정책 판단으로 남깁니다. 현재 멤버십, 동료 검토, 검토자 변경 시 재검토 규칙은 유지합니다.

## 구체 장면

다음은 설계를 설명하는 예시이며 실행한 테스트나 새 개발 대상이 아닙니다.

사용자가 “결제 취소를 지원하고 싶습니다”라고 설명합니다. AI는 취소 가능한 시점이 업무 흐름과 예외 처리를 바꾼다고 설명하고 시점을 묻습니다. 사용자의 답을 받은 뒤 “제가 이해한 취소 범위와 실패 시 동작은 다음과 같습니다”라고 다시 제시합니다. 사용자는 잘못 이해한 부분을 고칩니다. 문서에 반영할 변경을 확인한 뒤 동료가 그 문단의 예외 처리를 검토합니다. 수정 후 현재 버전을 승인합니다. 이 장면이 I2·I3·I4의 시연 기준입니다.

## 대안과 판단

| 접근 | 판단 |
|---|---|
| 기존 단계와 폼을 조금씩 손봅니다. | 수정은 작지만 질문·문서·검토 사이의 분절이 남습니다. |
| 채팅 화면만 제공합니다. | 시작은 쉽지만 합의한 문서 버전과 동료 검토가 묻힙니다. |
| Plan 문서와 대화를 한 작업 공간에서 연결합니다. | I2·I3·I4를 함께 보여 줄 수 있어 추천합니다. |

## 남은 확인과 다음 행동
