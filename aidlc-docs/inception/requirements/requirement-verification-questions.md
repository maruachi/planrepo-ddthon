# PlanRepo 요구사항 확인 질문

상태는 답변 수집·검증 완료입니다. 이 파일은 질문과 답변 원문을 보존하는 기록입니다. 현재 결정과 제품 조건은 `aidlc-docs/inception/requirements/requirements.md` 버전 0.4에 통합했습니다. 후속 질문과 승인 응답은 대화에서 받습니다.

## 기록을 읽는 방법

각 질문의 `[Answer]:`에는 사용자가 작성한 답변을 그대로 보존했습니다. 질문 선택지는 답변을 수집한 시점의 내용입니다. 현재 판단에는 요구사항 0.4의 DEC-01부터 DEC-11을 적용합니다. 이미 받은 답변을 다시 요구하지 않습니다.

제품명은 최신 요청에 따라 PlanRepo로 사용합니다. 원본의 Workbench와 같은 제품입니다. G1·G2, 단일 구현 단위, 전원 승인, 담당자 외 동료 최소 한 명, 강제 이동 제외는 원본 기본안으로 유지하고 요구사항 초안에서 함께 검토합니다. 변경을 원하면 마지막의 범위 변경 메모에 적을 수 있습니다.

내부 검토 사례인 MRBS·테이블오더는 요구사항과 plan의 발전·검토 흐름을 확인하는 참고 사례로 반영합니다. 사례 속 상세 기능이나 미결정 정책을 이번 제품의 확정 요구사항으로 가져오지 않습니다.

## Question 1 — Q-01: 이번 결과물의 수준

확인 항목 Q-01·Q-04·Q-05, NFR-04·07과 연결합니다.

A) 기능 데모로 만듭니다. 가상 사용자 전환, 한 팀·프로젝트, 원본의 가상 SR 4개를 사용합니다. G1·G2, 저장, 권한 검사, 내보내기는 실제로 동작해야 합니다. 제품의 권장 기본안입니다.

B) 실제 팀이 사용하는 시범 서비스로 만듭니다. 다음 확인에서 초기 사용자·검토 역할, 첫 적용 SR, 조직 인증과 운영 조건을 구체화합니다.

X) 기타입니다. 원하는 결과물 수준을 적어 주십시오.

**참고**: A를 선택하면 Q-04의 실제 인명과 Q-05의 실제 업무 SR은 이번 단계에서 묻지 않습니다. 가상 역할은 G1·G2의 전원 승인과 담당자 외 동료 최소 한 명이라는 기본안을 따릅니다. B를 선택하면 원본 Q-04·Q-05를 답변 검증 전에 추가 확인합니다.

## Question 6 — Q-08: 자료 처리와 규모 제약

확인 항목 Q-08, NFR-01·06·07, AC-13과 사용성 목표과 연결합니다.

이번 결과물에 적용해야 할 데이터 처리·보관·성능 제약이 있습니까?

A) 가상 데이터만 사용합니다. 별도 조직 제약이나 운영 수치 목표는 없습니다. 설계 단계에서 검증용 사용자·SR·문서 규모와 저장·복구 확인 조건을 제안받겠습니다.

B) 정해진 제약이 있습니다. 예상 사용자 수, 최대 문서 크기, 보관 기간, 응답시간 목표와 자료·모델 호출·저장 위치 제약 중 정해진 내용을 적어 주십시오.

X) 기타입니다. 아직 결정하지 못한 항목이나 확인 담당자를 적어 주십시오.

[Answer]:A

**참고**: A는 보존·충돌 방지·권한 검사를 생략한다는 뜻이 아닙니다. 원본의 보드 차단 사유·담당자를 10초 안에 찾는 사용성 목표도 유지합니다. 실제 사내 자료 사용이 필요하면 허용된 경로를 별도로 확정합니다.

## Question 7 — Q-09: 필수 게이트와 후속 범위 분류의 권한

B) 팀 관리자가 분류와 변경안을 작성합니다. 결정 확정은 지정 결정권자가 맡습니다. 검토 묶음에 분류·이유를 포함하고 필요한 재승인을 받습니다.

X) 기타입니다. 지정·제안·확정 역할을 적어 주십시오.

[Answer]:A

**참고**: 어느 안에서도 현재 구현에 필요한 항목을 이유 없이 후속 범위로 돌려 게이트를 통과할 수 없습니다. 범위를 줄이면 요구사항·완료 기준 변경과 재승인이 필요합니다. AI는 분류를 제안할 수 있지만 사람의 확정이나 승인을 대신하지 않습니다.
