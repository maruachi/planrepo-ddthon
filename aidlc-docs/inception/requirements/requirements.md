## 3. 기능 요구사항 (Functional Requirements)

### 3.1 단계·상태 모델 (§4)
- **FR-STG-1**: 칸반 4단계 — `SR 접수 → Inception → Construction 설계 → 구현 대기`.
- **FR-STG-2**: 각 카드는 세 facet을 분리 표시.
  - 진행 위치: 예) `Inception / 요구사항 분석`, `Construction / U2 Functional Design`.
  - 검토 상태: `답변 필요` · `결정 확정 대기` · `계획 승인 대기` · `수정 중` · `수정 확인 대기` · `산출물 승인 대기` · `승인 완료`.
  - AI 실행 상태: `실행 전` · `실행 중` · `추가 답변 대기` · `초안 준비` · `실패` · `취소` · `중단·재개 가능`.
- **FR-STG-3**: 리뷰 요청으로 별도 Review 단계 이동 없음. 필수 리뷰는 단계별 필수 승인 조건으로 관리. 수시 의견 요청 허용.
- **FR-STG-4**: 문서 탐색 클릭 ≠ 실제 단계 전환. 전환 버튼은 결과 설명 라벨(`Construction 설계 시작`, `설계 승인 완료`). 드래그 제공 시에도 동일 전환 조건 검사.
- **FR-STG-5**: 진행률 분모 = 해당 SR의 실행 대상 작업·필수 산출물. 생략(`해당 없음`) 단계는 미완료로 세지 않음.
- **FR-STG-6**: 여러 유닛 병렬 진행 시 각 유닛의 진행 위치 + 미해결 의존성 표시.
- **FR-STG-7** *(Q9=A)*: 검토 상태·AI 실행 상태 facet을 **유닛별**로 모델링. SR 카드는 대표/집계값 + 유닛별 상세 펼침.

### 3.2 질문·결정 (§2, §6)
- **FR-QN-1**: 질문 제목 형식 지원 — `## Question 1`, `### Q1.`, `### Clarification Question 1` 등 원본 유지.
- **FR-QN-2**: 선택지 수·문자(A/B/…/X)를 원본 그대로. 고정 오지선다 아님.
- **FR-QN-3**: 단일 선택 / 문서 명시 복수 선택 / Other + 자유 설명 지원.
- **FR-QN-4**: `[Answer]` 형식(`[Answer]:A`, `[Answer]: A`, `- [Answer]: A`, 답변이 선택지보다 앞) 보존. **지정 Answer만** 변경(§12.1).
- **FR-QN-5**: Other가 어떤 문자인지 원본에서 읽어 사용(X·마지막 문자 추측 금지).
- **FR-QN-6**: `(3)`/`(2)` 등을 고정 단계 수로 해석 금지. UI는 숫자의 대상 명시(`미확정 질문 3개`, `설계 승인 2/4`).
- **FR-QN-7**: 답변 연결은 문서·질문 식별자 + 내용/선택지 변경 여부로 확인(질문 번호만 사용 금지).
- **FR-QN-8**: 답변 상태 머신 — `미답변 → 편집 중/미저장 → 답변 제안(저장됨) → 확정`.
- **FR-QN-9**: 확정 답변 수정 시 새 제안으로 회귀 + 재확정 필요. 이전 확정 기록 보존.
- **FR-QN-10**: 질문 카드 필수 정보(§6): 질문·원문 위치·포함 문서 버전 / 선택지·자유 설명·현재 [Answer] / 결정 이유·관련 링크 / 선택 영향·근거 / 담당 결정권자·필수 여부·해결 단계 / 제안·확정 상태·확정자·시각·근거 / 후속 질문의 부모 실행 링크. **AI 권고는 사람 확정과 구분**, 출처 없으면 확정처럼 표기 금지.
- **FR-QN-11**: 현재 단계 필수 질문만 단계 진행 차단. 일반 의견·선택 질문·후속 단계 결정 사항은 차단 여부 별도 표시.
- **FR-QN-12**: 일괄 답변 반영 전 대상 문서·질문 목록 미리보기. 저장 실패를 성공처럼 표시 금지.
- **FR-QN-13** *(Q2=C)*: 질문 형식 오류·중복 번호·Answer 누락은 **위치 안내**로 표시하고 "미답변 0건"으로 숨기지 않음(§12.12). 구조화 시드 + 소수 원본 Markdown 예시로 시연.
- **FR-QN-14**: 네 행동을 분리 — **답변 저장 · 결정 확정 · 생성 계획 승인 · 설계 산출물 승인**(§12.2). 각 행동은 서로 다른 버튼/행위자.

### 3.3 답변 저장 모델 (§10 ⨯ §6, Q6=B)
- **FR-SV-1**: 편집 중 초안 자동 저장 — `저장 중` / `저장됨` / `저장 실패` / `미저장` 표시.
- **FR-SV-2**: 명시적 **'답변 저장'** 행동으로 초안 → `답변 제안(저장됨)` 승격.
- **FR-SV-3**: 저장 실패를 명확히 표시(성공 위장 금지, §6).

### 3.4 문서 버전·리뷰·수정 요청 (§7)
- **FR-VER-1**: 승인 요청은 `문서 ID + 문서 버전`에 고정.
- **FR-VER-2**: 본문 또는 Answer 변경은 새 버전을 만든다. 기존 승인본·승인자·시각 보존.
- **FR-VER-3**: 새 버전은 재승인 필요. 이전 승인 승계 없음. v2 확인 후 v3 생성 시 v2 화면의 승인으로 v3 승인 불가(§12.4, §12.5).
- **FR-VER-4**: 댓글은 원래 버전 + 인용 문구·위치 저장. 새 버전에서 위치 미검출 시 `이전 버전의 댓글`로 표시.
- **FR-VER-5**: 원본 계획 변경 시 그 계획을 입력으로 쓴 산출물 + 후속 산출물(같은 단계 포함)에 `재검토 필요` 표시(§12.8). 자동 삭제·전체 되돌림 없음.
- **FR-REV-1**: 리뷰 화면 순서 — (1) 이번 리뷰의 판단·변경 요약 (2) 이전 승인본/선택 과거 버전과 변경 비교 (3) 관련 질문·확정 답변·열린 수정 요청 (4) 전체 원문·버전 이력 (5) 체크리스트·필수 리뷰어 상태·현재 버전 승인.
- **FR-REV-2**: 제목만 보고 즉시 승인하는 버튼 없음. 승인 패널에서 해당 버전 변경 확인 후 승인.
- **FR-RR-1**: 수정 요청 상태 — `열림 → 수정 완료·확인 대기 → 리뷰어 확인 완료`. 작성자는 수정한 새 버전을 지정해 제출.
- **FR-RR-2**: 수정 완료 제출만으로 차단 미해제(§12.6). 리뷰어가 지정 수정 버전 확인 후 해결/재오픈. 확인 대기 중 재변경 시 최신 수정 버전 재확인.
- **FR-RR-3**: AI 수정 초안은 별도 문서 생성만으로 원본 수정 요청을 해결하지 않음 — 원본의 새 버전으로 반영하는 명시적 행동 필요.

### 3.5 역할·승인 정책 (§5, Q7=B, Q8=B)
- **FR-ROLE-1**: 5역할 — 요청자·기획자 / 개발자·문서 작성자 / 결정권자 / 리뷰어 / 리더. 각 역할의 §5 행동 정의.
- **FR-ROLE-2** *(Q7=B)*: **'역할로 보기' 전환기**로 현재 역할에 따라 가능한 행동을 바꿈. 비활성 버튼은 사유 표시(§10). 제출자 ≠ 최종 확인자, 결정권자 ≠ 리뷰어 구분 유지.
- **FR-POL-1**: 기본 정책 = SR별 지정 필수 리뷰어 **전원 승인**.
- **FR-POL-2** *(Q8=B)*: 대안 정책(과반수·리더 승인)을 대화형 선택. 요청에 적용된 정책 + 리뷰어 집합 기록.
- **FR-POL-3**: 정책 변경이 과거 승인을 자동으로 최신 정책의 승인으로 전환하지 않음.
- **FR-POL-4**: 수정 요청 최종 확인은 요청 리뷰어. 리뷰어 변경·위임 시 변경자·이유 기록.

### 3.6 AI 실행·재개 상태 (§8) — 표시만, 실제 실행 없음
- **FR-AI-1**: 실행별 기록 — SR, 실행 ID, 부모 실행 ID, 작업 종류, 입력 문서 버전, 확정 답변, 수정 요청, 시작·완료 시각, 체크포인트.
- **FR-AI-2**: 미저장 답변으로 실행 불가. 필수 답변 확정 필요.
- **FR-AI-3**: 질문 분석 / 생성 계획 승인 / 산출물 생성 구분. 계획 승인 필요 작업은 승인 후 생성.
- **FR-AI-4**: 수정 요청 반영 실행은 열린 수정 요청이 있어도 시작 가능(교착 방지, §12.7).
- **FR-AI-5**: 결과는 새 초안 — 생성 성공이 승인·다음 단계 이동을 뜻하지 않음.
- **FR-AI-6**: 후속 질문 시 최초 계획·기존 답변·실행 ID 보존 + 새 답변 추가로 이어서 실행(§12.3).
- **FR-AI-7**: 실패·취소·중단 시 문서·확정 답변 보존. 부분 결과는 승인 가능한 최종 산출물 아님.
- **FR-AI-8**: 동일 실행 중복 시작 방지. 재시도 대상·입력 버전 표시.
- **FR-AI-9**: 실행 중 입력 변경 시 이전 입력 결과가 최신 문서를 덮어쓰지 않음 — 이전 입력 기준 초안 표시 + 재검토/재실행 안내(§12.10).
- **FR-AI-10**: 재시작 후 마지막 체크포인트·다음 행동 복귀(§12.9, 실제 제품 한정 — 목업은 시드 상태로 표현).

### 3.7 세 가지 게이트 (§9)
- **FR-GATE-1 (AI 실행)**: 입력 저장 완료 + 필수 답변 확정 + 필요한 생성 계획 승인 + 중복 실행 없음.
- **FR-GATE-2 (문서 승인)**: 확인한 버전 일치 + 해당 버전 필수 답변 확정 + 차단 수정 요청 해결 + 검토 체크리스트 확인.
- **FR-GATE-3 (다음 단계·구현 인계)**: 단계 필수 산출물의 유효 최신 승인 + 필수 결정 완료 + 차단 요청 없음 + 입력 변경 영향 해소 + 진행 중/미해결 실행 없음.
- **FR-GATE-4 (예외 진행)**: 리더 예외 진행 시 미충족 조건·사유·실행자 기록 + `예외 진행` 표시. 미결정·미승인을 완료로 바꾸지 않음.

### 3.8 UI 표면 (§10)
- **FR-UI-INBOX** *(내 검토함, Q11=C)*: 개인 기본 화면(팀 보드는 별도). **단일 우선순위 목록**(기한 초과 → 차단 → 직접 요청·멘션 → 생성 시각) + **행동 유형 필터 탭**(기본 '전체'). 5개 행동(답변 작성·결정 확정·계획 승인·산출물 승인·수정 결과 확인) 구별. 각 행: SR·요청 종류·대상 문서·버전·요청자·기한·다음 행동. 빈 상태 vs 필터 결과 없음 구별.
- **FR-UI-BOARD** *(팀 보드)*: 카드에 대표 차단 원인·해결 담당자·대기 기간 우선. 경고 배지 동등 나열 금지(추가는 상세로). 차단 원인 클릭 → 해당 질문·문서·수정 요청 이동, 이동 전 통과 조건 + 즉시 해결 행동 제시. Git/PR은 선택 참고, 핵심 진행과 분리.
- **FR-UI-DETAIL** *(SR 상세, Q1=A · Q5=A)*: 상단 고정(SR·현재 작업·지금 필요한 행동·담당자·차단 이유). 중앙은 질문·변경 검토 집중(4종 변형 대상). 문서 트리·팀·AI 실행 정보는 접이식 보조 영역. 문서 집중 보기 + 패널 폭 조절, 좁은 화면은 서랍/순차. 주요 버튼은 결과 설명(`답변 저장`·`결정 확정`·`생성 계획 승인`·`설계 초안 검토`·`설계 승인 완료`). **AI 실행 상태는 본문에 표시**(터미널 강제 금지) — 인라인 배지/로그 + 읽기전용 구현 인계 컨텍스트. **CLI 터미널·Git diff/PR 제거.**
- **FR-UI-STATE**: 상태를 색만으로 전달 금지 — 텍스트+아이콘+숫자. 자동 저장/저장 중/실패/미저장, 불러오기/빈 상태/연결 오류 정의.

### 3.9 핵심 데이터 연결 (§11) — 시드 스키마
7개 엔티티를 필수 링크와 함께 시드 데이터로 모델링:
- **SR**: 담당자, 업무 단계, 작업 범위, 적용 워크플로우 버전, 관련 Jira/저장소.
- **설계 작업/유닛**: 적용 여부·사유(`해당 없음`), 필수 산출물, 선행 작업, 검토 시점.
- **문서 버전**: 원문, 종류, 문서 ID, 버전, 생성 근거, 입력 문서 버전, 이전 버전.
- **결정**: 원본 질문/선택지, 답변, 필수 여부, 결정권자, 확정 버전·시각·근거.
- **승인 요청/기록**: 문서 버전, 리뷰어, 정책, 결과, 시각.
- **수정 요청/댓글**: 요청 당시 버전·영역, 작성자, 수정 버전, 수정자, 확인자, 상태.
- **AI 실행**: 최초/부모 실행, 입력 묶음, 출력 버전, 실행 상태, 체크포인트, 오류.

### 3.10 구현 인계 컨텍스트

## 8. 미해결 사항의 기본 가정 (승인 시 확정, 이후 단계에서 재확인)
분석에서 식별된 세부 모호성은 아래 기본값으로 진행한다. 이견이 있으면 승인 시 지적해 주세요.
- **버전 번호 체계**: 정수 `v1 → v2 → v3`(시안의 `v1.2` 대신).
- **버전 생성 트리거**: 답변 **확정**이 문서 Answer를 갱신하며 새 버전을 만든다. 미확정 답변 제안(저장)은 초안이며 버전을 만들지 않는다.
- **필수 리뷰어 지정 단위**: SR 범위 내에서 **단계/산출물별**로 지정(§4·§5·§11 종합).
- **리더 예외 진행 적용 범위**: 문서 승인 게이트 + 다음 단계·구현 인계 게이트(AI 실행 게이트는 기술 전제이므로 제외).
- **완료 후 재차단 SR 위치**: `구현 대기` 칼럼에 유지하되 `재검토 필요` 배지·차단 표시(이전 단계 자동 복귀 없음).
- **완료 전환**: 자동 전환 아님 — §9 조건 검사 후 명시적 `설계 승인 완료`/구현 인계 버튼(§4·§9 우선, §2 9단계 서술 대비).

## 9. 핵심 요구사항 요약
PlanRepo MVP 목업은 **4단계 설계 전용** AI-DLC 워크벤치로서, ① 네 행동(답변 저장·결정 확정·생성 계획 승인·설계 산출물 승인)과 세 게이트(AI 실행·문서 승인·다음 단계/구현 인계)를 시각적으로 분리하고, ② 문서 ID+버전 고정 승인과 수정 요청 라이프사이클을 정확히 표현하며, ③ **가을톤 비주얼을 고정한 채 SR 상세 중앙 검토 영역만 4가지로 변형**하여 어떤 정보 배치가 질문 응답·변경 검토를 가장 빠르게 만드는지 비교하는 **단일 자기완결 HTML**로 제공한다. 완료 상태는 Git/PR 없이 도달하는 `구현 대기`다.
