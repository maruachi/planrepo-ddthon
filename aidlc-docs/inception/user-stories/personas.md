# PlanRepo 페르소나 (Personas)

§5의 5개 역할 + 목업 평가자 = 6개 페르소나. 각 페르소나는 서로 다른 **행동/게이트/권한**을 유발하며(§5·§9), 목업의 '역할로 보기' 전환기(FR-ROLE-2)로 시연된다. 모든 상호작용은 데모(실제 인증 없음, §3).

---

## P1. 요청자·기획자 — "정하은" (Product Planner)
- **목표**: SR의 요구사항·범위·수용 기준이 설계에 정확히 반영되는지 확인한다.
- **책임(§5)**: 요구사항 보완, 범위·수용 기준 검토.
- **주요 과업**: SR 배경 열람, 요구사항 관련 질문에 의견 제시(비차단), 수용 기준 대비 산출물 확인.
- **성공 지표**: 재작업 없이 범위 오해가 조기에 드러남.
- **좌절 요인**: 결정 근거가 흩어져 있어 "왜 이렇게 정해졌는지" 추적이 어려움.
- **기술 숙련도**: 중 — 문서·칸반에 익숙, 코드는 다루지 않음.
- **주 화면**: 팀 보드, SR 상세(질문·결정 근거 열람).

## P2. 개발자·문서 작성자 — "김도현" (Developer / Author)
- **목표**: AI 실행으로 초안을 만들고, 질문에 답을 제안하고, 수정 요청을 반영해 승인까지 끌고 간다.
- **책임(§5)**: 답변 제안, 문서 수정, 수정 완료 제출, AI 실행.
- **주요 과업**: 생성 계획의 질문에 `[Answer]` 제안·저장(FR-QN-4, FR-SV), AI 실행 트리거·상태 확인(FR-AI), 새 버전 작성, 수정 완료 제출(FR-RR-1).
- **성공 지표**: "지금 답할 질문"과 "이전 검토 이후 바뀐 것"을 빠르게 찾아 왕복을 줄임(§13).
- **좌절 요인**: 실행 상태를 보려 터미널을 열어야 하거나(§10 금지), 저장 실패가 성공처럼 보이는 것.
- **기술 숙련도**: 상 — CLI/Git에 익숙하나 목업에서는 본문 인라인 상태로 작업.
- **주 화면**: SR 상세(중앙 질문·검토 영역 — 4종 변형의 핵심 사용자), 내 검토함.

## P3. 결정권자 — "이서준" (Decision Owner)
- **목표**: 담당 질문의 답변을 확정하고 근거를 남긴다. 답변 저장과 '확정'을 혼동하지 않는다.
- **책임(§5)**: 담당 질문 답변 확정·변경 결정과 근거 기록.
- **주요 과업**: 제안된 답변 검토→확정(FR-QN-8), 확정 답변 수정 시 재확정 인지(FR-QN-9), 필수 질문이 단계를 차단함을 확인(FR-QN-11).
- **성공 지표**: 확정과 승인이 분리되어 오확정이 없음(AC-2).
- **좌절 요인**: 답변 저장이 자동으로 확정·승인처럼 처리되는 UI.
- **기술 숙련도**: 중.
- **주 화면**: 내 검토함(결정 확정 필터), SR 상세(질문 카드).

## P4. 리뷰어 — "박민지" (Reviewer)
- **목표**: 특정 문서 버전의 변경을 확인하고 승인하거나 수정 요청하고, 수정 결과를 확인한다.
- **책임(§5)**: 특정 버전 검토·승인, 수정 요청, 수정 결과 확인.
- **주요 과업**: 리뷰 5단계 순서로 검토(FR-REV-1), 제목만 보고 승인 금지(FR-REV-2), 버전 고정 승인(FR-VER-1·3), 수정 요청 열기/확인(FR-RR-1·2), 과거 버전 화면에서 최신 승인 불가 인지(AC-5).
- **성공 지표**: "이전 검토 이후 바뀐 것"을 즉시 보고 정확한 버전을 승인.
- **좌절 요인**: 어떤 버전을 승인하는지 모호, 수정 완료 제출만으로 차단이 풀린 것처럼 보임(AC-6).
- **기술 숙련도**: 중~상.
- **주 화면**: 내 검토함(산출물 승인·수정 확인 필터), SR 상세(변경 비교·승인 패널).

## P5. 리더 — "최유진" (Lead)
- **목표**: SR의 필수 리뷰어·범위·승인 정책을 설정하고, 필요 시 예외 진행을 판단한다.
- **책임(§5)**: 필수 리뷰어·작업 범위 설정, 예외 진행 판단.
- **주요 과업**: 승인 정책 선택(전원/과반수/리더, FR-POL-2), 필수 리뷰어 지정, 게이트 미충족 시 `예외 진행` + 사유 기록(FR-GATE-4).
- **성공 지표**: 정책·예외가 감사 가능하게 기록되고 미승인을 완료로 바꾸지 않음.
- **좌절 요인**: 정책 변경이 과거 승인을 조용히 뒤바꿈(FR-POL-3 위반 상황).
- **기술 숙련도**: 중.
- **주 화면**: 팀 보드(차단 개요), SR 상세(정책·게이트 패널).

## P6. 목업 평가자 — "한지우" (Mockup Evaluator)  *[비교 주체 · §13]*
- **목표**: 4종 화면 변형을 전환해 보며 어떤 정보 배치가 "지금 답할 질문 찾기"와 "이전 검토 이후 변경 확인"을 가장 빠르게 만드는지 판단한다.
- **책임**: 목업 비교·의사결정(제품 역할 아님, 목업 전용).
- **주요 과업**: 인앱 전환기로 4종 토글(MK-2), 동일 과업을 각 변형에서 수행하며 속도·명료성 비교, 새로고침 시 초기화 인지(MK-6).
- **성공 지표**: 4종 중 가장 빠른 정보 배치를 근거 있게 선택.
- **좌절 요인**: 변형 간 비주얼이 달라 비교 변수가 흐려짐(→ NFR-VIS-1으로 비주얼 고정).
- **기술 숙련도**: 상 — UX/제품 의사결정자.
- **주 화면**: 전역 셸(전환기) + SR 상세 4종.
