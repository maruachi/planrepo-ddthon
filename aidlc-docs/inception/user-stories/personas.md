## 공통 사용 맥락

첫 버전은 로그인 없는 로컬 macOS 단일 사용자 웹 앱이다. 아래 페르소나는 한 사용자가 전환하여 시연하는 업무 역할이다. 별도 계정·권한 등급, 연령·직급·회사 규모는 가정하지 않는다. CLI와 Jira는 연동 대상이며 페르소나가 아니다.

## P-01. 계획 작성자

- 목표: SR의 구현 전 계획을 하나의 UI에서 구체화하고 문서와 결정을 추적하며 외부 구현에 넘길 준비를 한다.
- 사용 맥락: 초기 요구와 선택적 마크다운을 입력하고 로컬 Claude Code CLI로 계획을 생성한다. Inception과 Construction에서 검토·수정·반복 진행한다.
- 주요 활동: SR 생성, 칸반 조회, 실제 문서 생성과 실패 확인, 질문 응답·결정, 편집·이력·비교·복원, 리뷰 요청, 구현 상태 수동 관리.
- 어려움: 업무 도구 사이를 오가는 부담, 계획의 변경 이유와 과거 내용을 함께 확인하는 어려움, 리뷰와 계획 진행 상태의 혼동. 원문과 승인 요구사항에서 도출한 역할 관점의 설명이다.
- 제약: 문서는 PlanRepo가 자체 관리한다. 코드 구현·커밋·PR은 외부 작업이고 실제 Jira 연동이나 다중 사용자 협업은 MVP에 없다.
- 성공 기준: 실제 생성·저장된 문서와 결정 이력을 확인하고, 리뷰 중에도 계획 작업을 계속하며 구현 대기로 정리할 수 있다.
- 관련 스토리: US-01–US-11, US-13, US-14. US-12 검토 결과를 후속 결정에 활용한다.

## P-02. 피어 리뷰어

- 목표: 구현 전에 특정 계획 문서 버전을 검토하고 작성자의 의사결정을 돕는다.
- 사용 맥락: 같은 로컬 앱에서 리뷰어 역할로 전환해 요청된 버전을 읽고 필요하면 이력·차이를 확인한다.
- 주요 활동: 대상 버전 열람, 이력·비교, 검토 결과 또는 수정 요청 기록.
- 어려움: 검토 대상 버전의 불명확함, 문서 변경 후 과거 검토의 적용 대상을 혼동하는 문제. FR-06·FR-07에서 도출했다.
- 제약: 별도 로그인·리뷰어 계정·외부 알림을 요구하지 않는다. 리뷰는 작성자의 진행을 막지 않으며 AI-DLC 자체 승인을 대신하지 않는다.
- 성공 기준: 대상 버전을 구분하여 결과를 기록하고 이후 문서가 변경되어도 원래 검토 대상을 확인할 수 있다.
- 관련 스토리: US-06, US-08, US-09, US-12. US-11의 요청을 검토한다.
