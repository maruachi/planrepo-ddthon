# PlanRepo 사용자 스토리

버전은 0.1이며 **사용자 승인 완료**입니다. 요구사항 0.4와 작성 계획 0.1을 승인받아 작성했습니다. 아래 수용 기준은 구현 후 검증할 명세이며 테스트 통과 결과가 아닙니다.

기준은 `aidlc-docs/inception/requirements/requirements.md`, 작성 계획은 `aidlc-docs/inception/plans/story-generation-plan.md`, 역할 정의는 `aidlc-docs/inception/user-stories/personas.md`입니다. 모든 파일 경로는 프로젝트 루트 기준입니다.

## 읽는 방법과 공통 수용 기준

각 스토리는 한 역할의 목적을 다룹니다. 의존 스토리는 업무상 필요한 상태를 설명하며 개발 순서나 sprint 계획이 아닙니다. 승인된 상태·권한·문서 버전을 가진 가상 데이터를 준비하면 각 스토리를 따로 검증할 수 있습니다. C1·C2는 스토리 내부 수용 기준이며 제품 AC 식별자와 다릅니다. 공통 기준 SC는 이를 지정한 스토리의 수용 기준에도 적용됩니다.

### SC-01 저장·복구와 입력 보존

**조건**: 저장할 입력과 기존 저장본이 있습니다. **행동**: 저장·새로고침·재접속과 저장 실패를 각각 검증합니다. **결과**: 성공한 상태와 버전·승인·인계는 유지됩니다. 실패하면 입력과 기존 저장본을 보존하고 실패·재시도 방법을 표시합니다. 저장 중·성공·실패를 구분합니다. (NFR-01, NFR-06, AC-13)

### SC-02 오래된 요청과 동시 저장

**조건**: 두 화면이 같은 대상을 읽은 뒤 한쪽이 변경했습니다. **행동**: 다른 화면에서 이전 버전으로 저장·검토·승인을 요청합니다. **결과**: 버전 충돌과 최신 변경을 표시하고 최신 상태를 덮어쓰지 않습니다. (NFR-02, AC-09, AC-13)

### SC-03 전환의 현재 조건과 중복 방지

**조건**: 반복 요청 또는 요청 처리 중 조건 변경이 발생합니다. **행동**: 질문 전환·승인·단계 전환·인계를 재요청합니다. **결과**: 한 행동의 중복 대상·이력이 생기지 않습니다. 단계 전환과 인계 직전에 현재 권한·버전·게이트를 다시 검사해 무효한 성공을 남기지 않습니다. (NFR-03, AC-13)

### SC-04 동일한 권한 검사

**조건**: 행동 권한이 없거나 현재 배정이 바뀐 가상 사용자가 있습니다. **행동**: 화면과 직접 요청으로 상태를 변경합니다. **결과**: 같은 역할·배정 검사를 적용하고 거부 이유를 표시합니다. 데모 사용자 전환과 현재 사용자를 표시하며 실제 조직 인증이라고 표현하지 않습니다. (NFR-04, AC-09)

### SC-05 안전한 표시와 키보드 사용

**조건**: Markdown에 실행 가능한 HTML·스크립트가 있고 사용자가 키보드만 사용합니다. **행동**: 문서를 열고 주요 행동을 실행합니다. **결과**: 스크립트는 실행되지 않으며 출처를 표시합니다. 주요 행동에 키보드로 접근·실행할 수 있습니다. 상태를 색만으로 구분하지 않고 텍스트·아이콘·숫자로 표시합니다. (NFR-05)

### SC-06 생성 중 이용과 가상 자료

**조건**: 가상 SR과 가상 사용자로 긴 생성 작업을 실행합니다. **행동**: 기존 문서를 열고 검토합니다. **결과**: 열람·검토가 가능하고 생성 상태를 표시합니다. 실제 사내 자료나 비밀 값을 데모 입력으로 사용하지 않습니다. 성능 규모·응답시간 목표는 NFR 설계에서 정하며 여기서 임의 확정하지 않습니다. (NFR-06, NFR-07)

### SC-07 주요 행동의 추적 기록

**조건**: 문서 생성·적용·답변·결정·검토·승인·정책·전환·인계 중 관련 행동을 처리합니다. **행동**: 결과와 활동 이력을 확인합니다. **결과**: 행위자·대상 버전·시각을 연결해 남기고 일반 UI에서 이력을 수정·삭제하지 않습니다. 실패를 성공 기록으로 남기거나 과거 기록을 덮어쓰지 않습니다. (FR-22)

## J-01 SR 접수와 근거 확인

### US-001 SR 직접 등록

**주 페르소나**: P-01입니다. **참여 페르소나**: 없음입니다.

**사용자 목적**: SR 담당자는 검토를 시작하기 위해 Git 연결 없이 SR을 등록할 수 있어야 합니다.

**시작 조건·의존 관계**: 새 프로젝트 또는 기존 SR 목록에서 시작합니다. 선행 스토리는 없습니다.

**요구사항 연결**: FR-01, FR-03, AC-01, FR-16. **공통 수용 기준**: SC-01, SC-04, SC-05, SC-07.

- **C1**: **조건**: 한 팀·프로젝트의 가상 사용자를 선택했습니다. **행동**: SR 키·제목·목적·설명·담당자·프로젝트를 입력하고 등록합니다. **결과**: SR 접수 상태와 현재 사용자를 표시하고 원 설명을 보존합니다. workflowVersion은 v1.0.1이며 구현 단위는 하나입니다. (FR-01, FR-03, AC-01)
- **C2**: **조건**: Git·Jira 연결이나 기존 시스템 근거가 없습니다. **행동**: 필수 정보로 등록합니다. **결과**: Git 선택을 요구하지 않으며 Jira 키·URL·참고 자료·기존 시스템 여부는 선택 입력으로 처리합니다. (FR-01, AC-01)
- **C3**: **조건**: 필수 정보가 빠져 있습니다. **행동**: 등록하거나 다음 단계로 이동합니다. **결과**: 누락 항목을 표시하고 잘못된 등록·전환을 완료로 표시하지 않습니다. (FR-01, FR-16)

### US-002 가상 Jira 가져오기와 원 설명 확인

**주 페르소나**: P-01입니다. **참여 페르소나**: 없음입니다.

**사용자 목적**: SR 담당자는 외부 요청의 출발 내용을 잃지 않도록 Mock Jira의 SR을 가져오고 최초 설명을 확인할 수 있어야 합니다.

**시작 조건·의존 관계**: 가상 Jira 목록 또는 이미 가져온 SR이 있습니다. US-001의 등록 상태를 준비할 수 있습니다.

**요구사항 연결**: FR-01, FR-03. **공통 수용 기준**: SC-01, SC-03, SC-04, SC-05, SC-07.

- **C1**: **조건**: 처음 보는 Jira 키가 있습니다. **행동**: 데모 가져오기를 실행합니다. **결과**: Jira 키·URL·원 설명을 연결하고 Mock임을 표시합니다. Jira 상태와 PlanRepo 단계는 별도로 표시합니다. (FR-01, FR-03)
- **C2**: **조건**: 같은 Jira 키의 SR이 이미 있습니다. **행동**: 다시 가져옵니다. **결과**: 중복을 알리고 기존 SR의 설명·합의·승인을 덮어쓰지 않습니다. (FR-03)
- **C3**: **조건**: 가져온 이후 설명을 수정했습니다. **행동**: 출발 설명과 현재 내용을 비교합니다. **결과**: 최초 설명을 계속 확인할 수 있습니다. 바뀐 외부 설명을 기존 합의에 자동 적용하지 않습니다. (FR-03)

### US-003 근거 연결과 확인 상태 관리

**주 페르소나**: P-01입니다. **참여 페르소나**: 없음입니다.

**사용자 목적**: SR 담당자는 검토의 근거를 설명하기 위해 자료와 확인되지 않은 내용을 구분할 수 있어야 합니다.

**시작 조건·의존 관계**: SR이 등록되어 있습니다. US-001 또는 US-002와 연결합니다.

**요구사항 연결**: FR-02, AC-01, NFR-08. **공통 수용 기준**: SC-01, SC-04, SC-05, SC-07.

- **C1**: **조건**: 텍스트·Markdown·링크 자료가 있습니다. **행동**: SR에 연결하고 검토합니다. **결과**: 출처·대상 버전과 확인 여부를 구분하고 확인자·시각을 남깁니다. (FR-02)
- **C2**: **조건**: 자료를 읽지 못했거나 기존 시스템 근거가 부족합니다. **행동**: 확인 상태를 조회합니다. **결과**: 확인된 사실로 표시하지 않습니다. 미확인 자료와 필요한 확인 항목을 남기고 다음 행동에서 찾을 수 있습니다. (FR-02, AC-01)
- **C3**: **조건**: 서로 다른 SR의 참고 자료가 있습니다. **행동**: 현재 SR의 근거를 엽니다. **결과**: 그 SR에 연결된 자료만 근거로 다루며 다른 사례의 결정·승인을 상속하지 않습니다. (FR-02, NFR-08)
## J-02 질문 해결과 공식 결정

### US-004 배정된 질문에 답변

**주 페르소나**: P-02입니다. **참여 페르소나**: P-01입니다.

**사용자 목적**: 업무 확인자는 질문의 이유를 이해하고 업무 규칙과 예외를 전달하기 위해 답변할 수 있어야 합니다.

**시작 조건·의존 관계**: 등록된 질문과 답변 담당자가 있습니다. 질문은 US-009의 생성 초안에서 사람의 확인을 거쳐 준비할 수 있습니다.

**요구사항 연결**: FR-04, AC-02, FR-05, FR-16. **공통 수용 기준**: SC-01, SC-04, SC-05, SC-07.

- **C1**: **조건**: AI가 질문과 답변 후보를 제안했습니다. **행동**: 질문을 엽니다. **결과**: 이유·출처·관련 문서·답변 담당자·필요 시점을 표시하며 근거 있는 후보도 사람의 확인 대상으로 둡니다. (FR-04, AC-02)
- **C2**: **조건**: 배정된 질문에 선택지가 있습니다. **행동**: 선택하거나 직접 작성하고 근거와 함께 제출합니다. **결과**: 선택형·자유 입력을 모두 지원하고 답변됨 상태로 저장합니다. 해결됨으로 자동 전환하지 않습니다. (FR-05, AC-02)
- **C3**: **조건**: 필수 질문에 답변만 남겼습니다. **행동**: 관련 게이트의 통과 조건을 확인합니다. **결과**: 담당자의 해결 확인 전까지 미해결로 남고 필요한 게이트를 차단합니다. (FR-05, FR-16, AC-02)

### US-005 답변 해결 확인과 후속 질문

**주 페르소나**: P-01입니다. **참여 페르소나**: P-02입니다.

**사용자 목적**: SR 담당자는 요구사항의 누락을 줄이기 위해 답변을 검토하고 해결하거나 후속 질문을 남길 수 있어야 합니다.

**시작 조건·의존 관계**: US-004의 답변됨 질문이 있습니다. 문서 적용은 US-011·US-012로 준비합니다.

**요구사항 연결**: FR-05, AC-02, FR-04, FR-16. **공통 수용 기준**: SC-01, SC-04, SC-05, SC-07.

- **C1**: **조건**: 답변에 근거가 있고 현재 문서와 일관됩니다. **행동**: 반영된 문서 또는 변경 불필요 이유를 확인해 해결합니다. **결과**: 확인 근거와 연결을 남기고 질문을 해결됨으로 표시합니다. (FR-05, AC-02)
- **C2**: **조건**: 답변에서 예외·실패 정책이 빠져 있거나 서로 모순됩니다. **행동**: 담당자가 후속 질문을 등록합니다. **결과**: 원 질문과 검토 맥락을 유지하고 새로운 질문의 담당자·필요 시점을 표시합니다. 미해결 필수 항목은 계속 차단합니다. (FR-04, FR-05, AC-02)
- **C3**: **조건**: AI가 해결됐다고 판단했으나 사람이 확인하지 않았습니다. **행동**: 질문 상태와 게이트를 확인합니다. **결과**: AI 판단만으로 질문을 닫거나 차단을 해제하지 않습니다. (FR-05, FR-16, AC-02)

### US-006 질문을 공식 결정으로 전환

**주 페르소나**: P-01입니다. **참여 페르소나**: P-04입니다.

**사용자 목적**: SR 담당자는 선택과 합의가 필요한 문제를 분리하기 위해 질문을 결정 항목에 연결할 수 있어야 합니다.

**시작 조건·의존 관계**: 선택이 필요한 질문이 있습니다. US-004·US-005와 연결합니다.

**요구사항 연결**: FR-06, FR-07, AC-03, NFR-03. **공통 수용 기준**: SC-01, SC-03, SC-04, SC-05, SC-07.

- **C1**: **조건**: 정책 선택이 필요한 질문이 있습니다. **행동**: 결정으로 전환하고 대안·영향과 결정권자를 지정합니다. **결과**: 원 질문·답변과 새 결정의 연결을 보존하고 결정은 미확정으로 둡니다. (FR-06, FR-07, AC-03)
- **C2**: **조건**: 같은 질문의 전환을 반복하거나 동시에 요청합니다. **행동**: 전환 결과와 차단 수를 확인합니다. **결과**: 결정이 중복 생성되지 않고 같은 문제를 질문과 결정에서 중복 집계하지 않습니다. 미확정 결정의 차단은 유지합니다. (FR-06, AC-03, NFR-03)

### US-007 근거 있는 결정 확정과 재결정

**주 페르소나**: P-04입니다. **참여 페르소나**: P-01입니다.

**사용자 목적**: 결정권자는 합의한 선택을 구분하기 위해 배정된 결정의 선택과 이유를 확정할 수 있어야 합니다.

**시작 조건·의존 관계**: US-006의 미확정 결정 또는 이미 확정한 결정 버전이 있습니다.

**요구사항 연결**: FR-07, AC-03, FR-15, AC-06, AC-07. **공통 수용 기준**: SC-01, SC-02, SC-04, SC-05, SC-07.

- **C1**: **조건**: 자신의 결정으로 배정되어 있고 질문·대안·영향을 검토했습니다. **행동**: 선택·이유·근거를 기록해 확정합니다. **결과**: 결과·시각·결정권자와 버전을 보존합니다. (FR-07, AC-03)
- **C2**: **조건**: AI 추천이나 미배정 사용자의 선택만 있습니다. **행동**: 확정을 요청합니다. **결과**: 공식 결정으로 처리하지 않고 지정 결정권자의 확정을 요구합니다. (FR-07, AC-03)
