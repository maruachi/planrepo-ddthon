# PlanRepo 사용자 스토리

상태: 생성·검증 완료. user-stories-approval-questions.md의 Q1 A로 산출물 승인 확인 (2026-09-08T13:57:25Z).

근거: [요구사항 명세](../requirements/requirements.md), [승인된 생성 계획](../plans/story-generation-plan.md), [페르소나](personas.md).

사용자 여정을 따라 14개 스토리를 묶었다. 수용 기준은 구현 후 확인할 명세이며 현재 테스트 결과가 아니다. 관련 스토리는 사용자 흐름의 연관·선후 관계이며 개발 일정이나 구현 순서가 아니다.

## 계획 시작

### US-01. SR 직접 생성

계획 작성자로서 제목·요구 설명과 선택적 마크다운으로 SR을 만들고 싶다. 계획 작업의 출발점을 한곳에 보관하기 위해서다.

- 페르소나: P-01
- 요구사항: FR-01, FR-05, FR-09; NFR-02, NFR-03, NFR-04, NFR-06
- 관련 스토리: US-02, US-03

수용 기준:

1. 주어진 상황: Git·Jira가 연결되지 않은 로컬 앱. 수행 행동: 제목·요구 설명을 입력하고 생성. 관찰 결과: SR이 자체 저장소에 저장되고 SR 목록에 카드로 표시된다.
2. 주어진 상황: 제목 또는 요구 설명이 비어 있음. 수행 행동: SR 생성 시도. 관찰 결과: SR을 생성하지 않고 빠진 필수 입력의 이유를 표시한다.
3. 주어진 상황: 유효한 필수 입력. 수행 행동: 마크다운을 첨부하거나 첨부 없이 각각 생성. 관찰 결과: 두 경우 모두 생성할 수 있고 첨부 내용은 해당 SR 상세에서 확인할 수 있다.

### US-02. 칸반 단계와 회차 확인

계획 작성자로서 SR의 단계와 반복 회차를 확인하고 싶다. 현재 계획의 위치와 반복 진행을 파악하기 위해서다.

- 페르소나: P-01
- 요구사항: FR-01, FR-02; NFR-03
- 관련 스토리: US-01, US-03, US-05, US-11, US-13, US-14

수용 기준:

1. 주어진 상황: 저장된 SR이 있는 보드. 수행 행동: 칸반 조회. 관찰 결과: SR 목록·요구사항 분석·Inception·Construction·구현 대기·구현 완료의 고정 열과 SR의 위치를 확인한다.
2. 주어진 상황: Inception 또는 Construction에 있는 SR. 수행 행동: 같은 단계 반복 진행 후 카드 조회. 관찰 결과: 해당 단계의 회차 변화를 확인하며 반복마다 열이 추가되지 않는다. 숫자는 하위 stage 완료 개수와 구분된다.
3. 주어진 상황: SR 카드. 수행 행동: 카드 선택. 관찰 결과: 상세에서 초기 입력과 연결 문서를 열 수 있고 리뷰 상태는 계획 단계와 별도로 확인한다.

## AI와 계획 진행

### US-03. 실제 AI로 계획 문서 생성

계획 작성자로서 현재 SR 문맥으로 AI-DLC 문서를 생성하고 싶다. 도구를 오가지 않고 구현 전 계획을 구체화하기 위해서다.

- 페르소나: P-01
- 요구사항: FR-03, FR-04, FR-05, FR-06; NFR-02, NFR-03, NFR-04, NFR-06
- 관련 스토리: US-01, US-04, US-05, US-08

수용 기준:

1. 주어진 상황: SR 입력·첨부·기존 문서·관련 결정과 실행 준비된 CLI. 수행 행동: 다음 단계 진행 요청. 관찰 결과: 서버가 macOS의 실제 Claude Code CLI를 기존 인증으로 실행하며 AI-DLC 규칙과 해당 SR 문맥을 전달한다. 실행 전과 생성 중 상태가 구분된다.
2. 주어진 상황: 문서 생성 성공. 수행 행동: 결과 열람. 관찰 결과: SR에 연결된 계획 문서와 성공 상태를 UI에서 확인하고 AI 생성 이력을 보관한다.
3. 주어진 상황: 문서 생성 요청. 수행 행동: 실행 범위와 결과 확인. 관찰 결과: 모의 데이터만으로 성공을 대체하지 않는다. 생성은 코드 구현 직전 계획을 대상으로 하며 코드 구현을 자동 실행하지 않는다.

### US-04. 문서 생성 실패 인지

계획 작성자로서 생성 실패를 분명히 알고 싶다. 미완성 문서를 완료된 계획으로 오인하지 않기 위해서다.

- 페르소나: P-01
- 요구사항: FR-03; NFR-03
- 관련 스토리: US-03

수용 기준:

1. 주어진 상황: 생성 중인 SR에서 CLI 실행 실패. 수행 행동: 진행 상태 조회. 관찰 결과: 생성 중과 구분되는 실패 상태를 표시한다.
2. 주어진 상황: CLI 실행 실패 후. 수행 행동: 문서와 완료 상태 확인. 관찰 결과: 실패한 실행을 성공한 문서 생성이나 단계 완료로 표시하지 않는다.

### US-05. 질문 응답과 계획 결정 기록

계획 작성자로서 AI 질문에 답하고 문서의 승인·수정 요청을 남기고 싶다. 의도를 다음 계획에 반영하고 결정 근거를 보존하기 위해서다.

- 페르소나: P-01
- 요구사항: FR-04, FR-06; NFR-03, NFR-04
- 관련 스토리: US-03, US-08, US-11, US-12

수용 기준:

1. 주어진 상황: 질문이 필요한 AI-DLC 단계. 수행 행동: UI에서 질문을 확인하고 응답. 관찰 결과: 응답을 해당 SR의 진행 문맥과 이력에 보관하고 후속 진행에서 참조한다.
2. 주어진 상황: 생성 문서가 있음. 수행 행동: 승인 또는 수정 요청 기록. 관찰 결과: 결정 종류·내용과 대상 문서 버전을 이력에서 식별한다.
3. 주어진 상황: 문서 본문을 변경하지 않음. 수행 행동: 결정만 기록. 관찰 결과: 본문 변경이 없어도 결정 사건을 누락하지 않는다.
4. 주어진 상황: AI-DLC 자체 승인이 필요한 단계와 별도 리뷰. 수행 행동: 피어 리뷰 결과 조회. 관찰 결과: 리뷰 결과와 단계 승인을 구분하며 피어 리뷰 완료만으로 AI-DLC 승인을 대신했다고 표시하지 않는다.

## 문서 관리

### US-06. 저장 문서 다시 열기

계획 작성자 또는 리뷰어로서 저장한 SR과 문서를 다시 열고 싶다. Git 연결 없이 이전 작업을 이어서 확인하기 위해서다.

- 페르소나: P-01, P-02
- 요구사항: FR-01, FR-05, FR-06; NFR-02, NFR-03, NFR-04
- 관련 스토리: US-01, US-03, US-07, US-12

수용 기준:

1. 주어진 상황: SR과 문서를 저장한 로컬 앱. 수행 행동: 다른 화면을 거쳐 해당 SR 다시 열기. 관찰 결과: 저장된 입력과 계획 문서를 다시 읽을 수 있다.
2. 주어진 상황: Git을 연결하지 않음. 수행 행동: 저장 문서와 이력 조회. 관찰 결과: Git 연결이나 커밋 요구 없이 조회할 수 있다.

### US-07. 계획 문서 편집

계획 작성자로서 생성 문서를 수정하고 싶다. 실제 요구와 내 판단을 문서에 반영하기 위해서다.

- 페르소나: P-01
- 요구사항: FR-05, FR-06; NFR-03, NFR-04
- 관련 스토리: US-03, US-06, US-08

수용 기준:

1. 주어진 상황: 저장된 문서. 수행 행동: UI에서 내용을 수정하고 저장. 관찰 결과: 수정된 내용을 열람하고 사람의 수정 이력과 새 버전을 식별한다.
2. 주어진 상황: 수정 전후 내용이 다른 문서. 수행 행동: 이전 버전 조회. 관찰 결과: 수정 전 내용도 유지되어 열람할 수 있다.

### US-08. 문서와 결정의 이력 조회

계획 작성자 또는 리뷰어로서 문서 변화와 결정 이력을 함께 보고 싶다. AI와 사람이 무엇을 바꾸고 결정했는지 이해하기 위해서다.

- 페르소나: P-01, P-02
- 요구사항: FR-04, FR-05, FR-06; NFR-03, NFR-04
- 관련 스토리: US-03, US-05, US-07, US-10, US-12

수용 기준:

1. 주어진 상황: AI 생성·진행, 사람 편집, 결정·수정 요청이 있는 SR. 수행 행동: 이력 조회. 관찰 결과: 모든 해당 사건이 남고 사건 종류와 관련 문서 버전을 구분한다.
2. 주어진 상황: 여러 버전이 있는 문서. 수행 행동: 과거 버전 선택. 관찰 결과: 선택한 버전 내용을 볼 수 있다.
3. 주어진 상황: 본문 변화 없는 결정 또는 수정 요청. 수행 행동: 해당 사건 열람. 관찰 결과: 결정·요청 내용과 대상 문서 버전을 확인한다.

### US-09. 두 문서 버전 비교

계획 작성자 또는 리뷰어로서 두 버전의 차이를 보고 싶다. 변경 내용을 확인하고 수정이나 검토를 판단하기 위해서다.

- 페르소나: P-01, P-02
- 요구사항: FR-06; NFR-03, NFR-04
- 관련 스토리: US-08, US-10, US-12

수용 기준:

1. 주어진 상황: 내용이 다른 두 버전. 수행 행동: 비교할 두 버전 선택. 관찰 결과: 선택한 버전의 식별 정보와 변경 내용을 확인할 수 있다.
2. 주어진 상황: 문서 버전 이력이 있음. 수행 행동: 비교 후 원본과 이력 조회. 관찰 결과: 비교 동작이 원본 내용이나 저장된 이력을 바꾸지 않는다.

### US-10. 과거 문서 내용 복원

계획 작성자로서 과거 버전의 내용을 복원하고 싶다. 이전 결정을 다시 채택하면서 변화 기록을 보존하기 위해서다.

- 페르소나: P-01
- 요구사항: FR-05, FR-06; NFR-03, NFR-04
- 관련 스토리: US-08, US-09

수용 기준:

1. 주어진 상황: 현재와 내용이 다른 과거 버전. 수행 행동: 과거 버전 복원. 관찰 결과: 복원된 내용이 최신 문서에서 보인다.
2. 주어진 상황: 복원을 수행한 문서. 수행 행동: 이력과 이전 버전 열람. 관찰 결과: 복원을 새 버전으로 기록하고 복원 전 최신 버전과 선택한 과거 버전도 유지한다.

## 계획 검토

### US-11. 진행을 유지하며 리뷰 요청

계획 작성자로서 원하는 시점에 리뷰를 요청하고 싶다. 피드백을 기다리는 동안 계획 작업을 이어가기 위해서다.

- 페르소나: P-01
- 요구사항: FR-02, FR-06, FR-07; NFR-02, NFR-03, NFR-04
- 관련 스토리: US-02, US-03, US-05, US-12

수용 기준:

1. 주어진 상황: Inception 또는 Construction의 SR과 문서 버전. 수행 행동: 리뷰 요청. 관찰 결과: 카드는 기존 열에 남고 리뷰 상태 및 대상 버전을 별도로 확인한다.
2. 주어진 상황: 리뷰가 미완료이고 AI-DLC 자체 진행 조건은 충족한 SR. 수행 행동: 다음 단계 진행. 관찰 결과: 리뷰 미완료만을 이유로 진행을 막지 않으며 리뷰 대상은 원래 버전으로 유지한다.

### US-12. 대상 버전 검토 결과 기록

피어 리뷰어로서 요청된 버전의 검토 결과나 수정 요청을 남기고 싶다. 작성자가 피드백의 적용 대상을 이해하도록 하기 위해서다.

- 페르소나: P-02
- 요구사항: FR-06, FR-07; NFR-02, NFR-03, NFR-04
- 관련 스토리: US-05, US-06, US-08, US-09, US-11

수용 기준:

1. 주어진 상황: 리뷰 요청이 있는 로컬 앱. 수행 행동: 리뷰어 역할로 전환해 대상 열람. 관찰 결과: 별도 로그인 없이 요청된 문서 버전을 읽고 검토할 수 있다.
2. 주어진 상황: 대상 버전을 검토함. 수행 행동: 검토 결과 또는 수정 요청 기록. 관찰 결과: 내용과 대상 버전이 이력에 남고 작성자 역할에서 확인할 수 있다.
3. 주어진 상황: 검토 대상 이후 새 문서 버전이 생성됨. 수행 행동: 기존 검토 결과 조회. 관찰 결과: 결과는 원래 버전에 연결되고 새 버전까지 검토·승인한 것으로 표시되지 않는다.

## 외부 구현으로 전달

### US-13. 계획을 구현 대기로 정리

계획 작성자로서 준비한 SR을 구현 대기로 표시하고 싶다. 외부 개발 작업에 넘길 준비 상태를 구분하기 위해서다.

- 페르소나: P-01
- 요구사항: FR-04, FR-08; NFR-03
- 관련 스토리: US-02, US-03, US-05, US-14

수용 기준:

1. 주어진 상황: 코드 구현 직전 계획을 마친 SR. 수행 행동: 계획 종료 후 구현 대기로 이동. 관찰 결과: 구현 대기 열에 표시되고 준비한 계획 문서를 계속 열람할 수 있다.
2. 주어진 상황: 구현 대기 전환 요청. 수행 행동: 전환 결과 확인. 관찰 결과: PlanRepo가 코드 구현·빌드·커밋·PR 생성을 자동 시작하지 않는다.

### US-14. 외부 구현 완료를 수동 표시

계획 작성자로서 외부에서 구현을 마친 SR을 완료 처리하고 싶다. 계획 관리 화면에서도 구현 현황을 정리하기 위해서다.

- 페르소나: P-01
- 요구사항: FR-08; NFR-03
- 관련 스토리: US-13

수용 기준:

1. 주어진 상황: 구현 대기 상태의 SR. 수행 행동: 사용자가 구현 완료 처리. 관찰 결과: 카드가 구현 완료 열에 표시된다.
2. 주어진 상황: Git·Jira·빌드 결과를 연결하지 않음. 수행 행동: 구현 완료 처리 결과 확인. 관찰 결과: 수동 전환이 가능하며 사용자의 선언으로 구분하고 자동 검증된 빌드 성공을 뜻하지 않는다.

## 공통 수용 기준과 제약

1. 모든 주요 UI 입력·진행·열람·편집·비교·복원·검토 조작을 키보드로 수행할 수 있어야 한다. 실제 조작법은 설계 후 검증한다.
2. 로컬 단일 사용자와 기존 Claude Code 인증을 사용한다. 실제 설치·인증·실행 성공은 구현 시 확인한다. Git이나 Jira 연결은 문서 저장의 선행 조건이 아니다.
3. US-01의 향후 Jira 연결 경계는 후속 설계·코드 검토에서 확인한다. 현재 Jira 호출·인증·동기화는 제공하지 않으며 UI에 사용할 수 있는 연동처럼 표시하지 않는다.
4. US-03의 CLI 실행 경계와 SR·문서 관리의 구분은 후속 설계·코드 검토 대상이다. 이러한 기술 제약을 가상의 사용자 페르소나나 사용 가능한 Jira 기능 스토리로 만들지 않는다.
5. 실제 CLI, 비교·복원, AI와 사람의 결정 이력을 승인 없이 모의 기능이나 후속 범위로 바꾸지 않는다.
6. 회차 시작값·증가 시점, 하위 stage 매핑, 리뷰 상태명, 저장 기술, CLI 명령 및 단계 전환 조건의 상세는 후속 설계에서 정한다. 미확정 수치를 발명하지 않는다.
7. 자동 재시도·중복 진행 방지·전체 흐름 자동 테스트·운영 성능 수치·다중 사용자 협업을 신규 필수 요구로 추가하지 않는다. 필수 저장과 실제 연동의 성공·실패 검증은 유지한다.

## 통합 시나리오 연결

1. US-01·US-02로 SR을 생성하고 칸반·상세를 확인한다.
2. US-03·US-05로 실제 계획 생성·질문 응답·결정을 수행하고 US-02에서 반복 회차를 확인한다.
3. US-06–US-10으로 문서를 재열람·편집하고 AI·사람 이력 및 본문 변화 없는 결정을 조회한 뒤 비교·복원한다.
4. US-11로 리뷰를 요청한 상태에서 계획을 진행한다. US-12로 역할을 전환해 원래 버전의 결과를 남기고 이후 버전에 잘못 적용되지 않는지 확인한다.
5. US-13·US-14로 구현 대기·수동 완료를 표시한다. 저장 문서·이력을 다시 열고 주요 조작을 키보드로 수행한다.

별도 실패 경로는 US-04로 확인한다. 이는 NFR-05의 흐름 시연을 스토리에 연결한 것이며 실행 완료 기록이 아니다.

## INVEST 검토

| 기준 | 검토 결과 | 근거와 후속 사항 |
|---|---|---|
| Independent | 사용자 목적별 분리 | 편집·이력·비교·복원, 리뷰 요청·결과를 나눴다. 저장 SR·문서 등 선행 상태와 연관 스토리는 명시했다. 준비된 상태로 각 결과를 검증할 수 있다. |

| Testable | 스토리별 수용 기준 | 상황·행동·결과로 성공·실패·복원·본문 불변 결정·비차단 리뷰를 표현했다. 유보한 세부는 구현 검증 전에 구체화한다. |

문서 수준의 INVEST 검토이며 구현 완료·공수 확정·테스트 통과를 뜻하지 않는다.
