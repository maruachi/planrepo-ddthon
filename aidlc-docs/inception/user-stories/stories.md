# PlanRepo 사용자 스토리 (User Stories)

- **분해 방식(Q-S1=E)**: 에픽(기능 영역) + 스토리(페르소나·여정 관점).
- **형식**: "As a [페르소나], I want …, so that …" + Given/When/Then 수용 기준(Q-S4=A).
- **범위 태그(Q-S5=B)**: `[목업]` = 이번 HTML 목업에서 시연 · `[참고]` = 제품 비전 전용(범위 밖, 맥락용).
- **추적성(Q-S7=A)**: 각 스토리에 관련 요구사항(FR/NFR/MK) + 인수 시나리오(AC) 표기.
- **INVEST**: 각 스토리는 독립·협상 가능·가치·추정 가능·작음·테스트 가능하도록 작성.

## EPIC-A. 진행 파악 (팀 보드 · 내 검토함)

### US-A1 [목업] 내 다음 행동 찾기
**As a** 리뷰어(P4), **I want** 내 검토함에서 지금 내가 할 행동을 우선순위 순으로 보고 싶다, **so that** 문서 전체를 다시 읽지 않고 바로 처리할 수 있다.
- **관련**: FR-UI-INBOX, FR-QN-14 / **AC**: (설계 속도 목적 §13)
- **AC**
  - Given 내 검토함에 여러 요청이 있을 때, When 화면을 열면, Then 기한 초과 → 차단 → 직접 요청·멘션 → 생성 시각 순으로 단일 목록이 정렬된다.
  - Given 각 행에서, Then SR·요청 종류·대상 문서·버전·요청자·기한·다음 행동이 보인다.
  - Given 5개 행동(답변 작성·결정 확정·계획 승인·산출물 승인·수정 결과 확인)이 섞여 있을 때, Then 행별 라벨+아이콘으로 구별되고, 필터 탭(기본 '전체')으로 좁힐 수 있다.
  - Given 항목이 없을 때, Then '항목 없음'과 '필터 결과 없음'을 구별해 표시한다.

### US-A2 [목업] 차단 원인에서 해결 지점으로 이동
**As a** 리더(P5), **I want** 팀 보드 카드에서 대표 차단 원인과 담당자를 보고 클릭으로 해결 지점으로 이동하고 싶다, **so that** 무엇이 막혔는지 빠르게 파악하고 해소한다.
- **관련**: FR-UI-BOARD, FR-STG-2 / **AC**: (§13)
- **AC**
  - Given 카드에 여러 경고가 있을 때, When 카드를 보면, Then 대표 차단 원인·해결 담당자·대기 기간이 우선 표시되고 나머지 배지는 상세로 접힌다.
  - Given 차단 원인을 클릭하면, Then 해당 질문·문서·수정 요청으로 이동하기 전에 통과 조건과 즉시 해결 행동을 먼저 보여준다.
  - Given Git/PR 정보가 있어도, Then 카드의 핵심 진행 상태와 섞이지 않고 선택적 참고로만 표시된다.

### US-A3 [목업] 유닛별 진행·의존성 파악
**As a** 개발자(P2), **I want** Construction에서 병렬 유닛 각각의 진행 위치와 미해결 의존성을 보고 싶다, **so that** 어느 유닛부터 손대야 할지 안다.
- **관련**: FR-STG-6, FR-STG-7 / **AC**: —
- **AC**
  - Given 여러 유닛이 병렬 진행 중일 때, Then 각 유닛의 진행 위치와 미해결 의존성이 표시된다.
  - Given SR 카드를 볼 때, Then 검토 상태·AI 실행 상태는 대표/집계값으로 보이고 펼치면 유닛별 상세가 나온다.
  - Given 생략된(`해당 없음`) 설계 작업이 있을 때, Then 진행률 분모에서 제외된다.

## EPIC-B. 질문 응답과 결정

### US-B1 [목업] 원문 보존 답변 저장
**As a** 개발자(P2), **I want** 원문 선택지 형식을 유지한 채 지정한 `[Answer]`만 저장하고 싶다, **so that** 문서 형식을 깨지 않고 답을 남긴다.
- **관련**: FR-QN-1~5, FR-SV-1·2 / **AC**: AC-1
- **AC**
  - Given `## Question`/`### Q1.` 등 원본 제목과 A/B/…/X 선택지·줄바꿈이 있는 문서에서, When '답변 저장'을 하면, Then 지정한 `[Answer]:`만 바뀌고 선택지 문자·줄바꿈은 그대로 유지된다.
  - Given Other 문자가 X가 아닌 문서에서, Then 원본에서 읽은 Other 문자를 사용한다(추측 금지).
  - Given 편집 중일 때, Then 초안이 자동 저장되고 저장 중/저장됨/저장 실패/미저장이 표시된다.

### US-B2 [목업] 답변 저장 ≠ 확정 ≠ 승인
**As a** 결정권자(P3), **I want** 답변 저장이 결정 확정이나 문서 승인을 자동으로 완료하지 않게 하고 싶다, **so that** 각 행동이 명확히 분리된다.
- **관련**: FR-QN-8·14, FR-SV / **AC**: AC-2
- **AC**
  - Given 답변이 저장되어 '답변 제안'이 됐을 때, Then 결정 확정·문서 승인은 여전히 미완료로 남는다.
  - Given 담당 결정권자가 '결정 확정'을 하면, Then 그 질문만 확정 상태가 되고 확정자·시각·근거가 기록된다.
  - Given 확정된 답변을 수정하면, Then 새 제안으로 돌아가 재확정이 필요하고 이전 확정 기록은 보존된다.

### US-B3 [목업] 후속 질문을 같은 실행 맥락에서 이어가기
**As a** 개발자(P2), **I want** 후속 질문에 답한 뒤 기존 계획과 이전 답변을 유지한 채 실행을 이어가고 싶다, **so that** 맥락을 잃지 않는다.
- **관련**: FR-QN-10(부모 실행 링크), FR-AI-6 / **AC**: AC-3
- **AC**
  - Given 초기 계획에서 파생된 후속 질문에 답할 때, Then 최초 계획·기존 답변·실행 ID가 보존되고 새 답변이 추가된다.
  - Given 후속 질문 카드에서, Then 최초 질문/부모 실행으로 돌아가는 링크가 보인다.

### US-B4 [목업] 필수 질문만 차단
**As a** 개발자(P2), **I want** 현재 단계 필수 질문만 진행을 차단하고 의견·후속 단계 질문은 구분해 보고 싶다, **so that** 불필요하게 막히지 않는다.
- **관련**: FR-QN-11 / **AC**: —
- **AC**
  - Given 필수 질문이 미확정일 때, Then 단계 진행이 차단되고 그 사유가 표시된다.
  - Given 일반 의견·선택 질문·후속 단계 결정 사항일 때, Then 차단하지 않으며 '차단 아님'으로 별도 표시된다.

### US-B5 [목업] 파서 오류와 미답변 구별
**As a** 개발자(P2), **I want** 질문 형식 오류·중복 번호·Answer 누락이 위치와 함께 표시되게 하고 싶다, **so that** 오류가 '미답변 0건'으로 숨겨지지 않는다.
- **관련**: FR-QN-12·13 / **AC**: AC-12
- **AC**
  - Given 형식 오류가 있는 원본 Markdown 예시에서, When 파싱하면, Then 오류 위치가 안내되고 미답변 0건으로 숨기지 않는다.
  - Given 오류를 수정하면, Then 해당 차단이 해제된다.
  - Given 일괄 답변 반영 전, Then 대상 문서·질문 목록을 미리 보여주고 저장 실패를 성공처럼 표시하지 않는다.

## EPIC-C. 생성 계획과 AI 실행 상태  *(표시만, 실제 실행 없음)*

### US-C1 [목업] 계획 승인 후 산출물 생성
**As a** 개발자(P2), **I want** 질문 분석 → 생성 계획 승인 → 산출물 생성이 구분되게 하고 싶다, **so that** 승인 없이 산출물이 만들어지지 않는다.
- **관련**: FR-AI-3·5, FR-QN-14 / **AC**: —
- **AC**
  - Given 계획 승인이 필요한 작업에서, Then 계획 승인 후에만 산출물 생성이 시작된다.
  - Given 산출물 생성이 성공해도, Then 그것이 곧 승인·다음 단계 이동을 뜻하지 않고 결과는 '새 초안'으로 표시된다.

### US-C2 [목업] AI 실행 상태를 본문에서 확인
**As a** 개발자(P2), **I want** 실행 중/추가 답변 대기/실패/취소/중단·재개 상태를 본문 인라인으로 보고 싶다, **so that** 터미널을 열지 않아도 된다.
- **관련**: FR-AI-1·7·10, FR-UI-DETAIL, NFR-A11Y-1 / **AC**: (AC-9 표시)
- **AC**
  - Given 실행 상태가 있을 때, Then 본문에 텍스트+아이콘으로 표시되고 색만으로 전달하지 않는다.
  - Given 실패·취소·중단 상태의 실행에서, Then 문서와 확정 답변이 보존되고 부분 결과는 '승인 가능 최종본'으로 표시되지 않는다.
  - Given 미저장 답변이 있을 때, Then 실행 시작이 비활성화되고 사유가 표시된다(FR-AI-2).

### US-C3 [목업] 중복 실행·입력 변경 안전장치
**As a** 개발자(P2), **I want** 중복 실행이 막히고 실행 중 입력이 바뀌면 기존 문서가 덮어써지지 않게 하고 싶다, **so that** 결과가 유실·오염되지 않는다.
- **관련**: FR-AI-8·9 / **AC**: AC-10
- **AC**
  - Given 동일 실행을 중복 시작하려 하면, Then 차단되고 재시도 대상·입력 버전이 표시된다.
  - Given 실행 중 입력이 바뀌면, Then 이전 입력 기준 초안으로 표시되고 재검토/재실행이 안내된다.

### US-C4 [참고] 재시작 후 체크포인트 복구
**As a** 개발자(P2), **I want** 브라우저/CLI 재시작 후 마지막 체크포인트로 복귀하고 싶다, **so that** 실행을 이어간다.
- **관련**: FR-AI-10 / **AC**: AC-9 *(§12.9 '실제 제품' 한정 — 목업은 시드 상태로만 표현)*
- **AC**
  - Given 새로고침 이후, Then 목업은 데모 초기화를 표시하고(MK-6), 복구는 시드 상태 화면으로 설명한다.

## EPIC-D. 문서 버전·변경 검토·승인

### US-D1 [목업] 버전 고정 승인
**As a** 리뷰어(P4), **I want** 승인이 문서 ID + 버전에 고정되고 새 버전은 재승인이 필요하게 하고 싶다, **so that** 과거 승인이 조용히 승계되지 않는다.
- **관련**: FR-VER-1·2·3 / **AC**: AC-4
- **AC**
  - Given v2가 승인된 뒤 v3가 생성되면, Then v2 이력·승인자·시각은 보존되고 v3에는 재승인이 필요하다.
  - Given 본문 또는 Answer가 바뀌면, Then 새 버전이 생성된다.

### US-D2 [목업] 과거 버전에서 최신 승인 불가
**As a** 리뷰어(P4), **I want** 과거 버전 화면에서 최신 버전을 승인할 수 없게 하고 싶다, **so that** 검토하지 않은 변경을 승인하지 않는다.
- **관련**: FR-VER-3, FR-REV-2 / **AC**: AC-5
- **AC**
  - Given v2 화면을 보고 있고 v3가 이미 존재할 때, When 승인하려 하면, Then v3 승인은 차단되고 최신 버전 검토로 유도된다.
  - Given 어떤 버전이든, Then 제목만 보고 즉시 승인하는 버튼은 없고 승인 패널에서 변경 확인 후 승인한다.

### US-D3 [목업] 리뷰 5단계 순서로 변경 검토
**As a** 리뷰어(P4), **I want** 리뷰 화면이 판단 요약 → 변경 비교 → 관련 질문·답변·수정 요청 → 원문·이력 → 체크리스트·승인 순서로 제시되게 하고 싶다, **so that** "바뀐 것"을 빠르게 검토한다.
- **관련**: FR-REV-1, NFR-A11Y / **AC**: (§13)
- **AC**
  - Given 리뷰를 시작하면, Then 다섯 영역이 정해진 순서로 제공된다.
  - Given 댓글이 이전 버전 위치에 달렸고 새 버전에서 위치를 못 찾을 때, Then '이전 버전의 댓글'로 표시된다(FR-VER-4).

### US-D4 [목업] 입력 변경 시 재검토 전파
**As a** 리뷰어(P4), **I want** 원본 계획이 바뀌면 그 계획을 입력으로 쓴 산출물과 후속 산출물에 '재검토 필요'가 표시되게 하고 싶다, **so that** 낡은 승인이 유지되지 않는다.
- **관련**: FR-VER-5 / **AC**: AC-8
- **AC**
  - Given 원본 계획이 변경되면, Then 같은 단계·다음 단계의 관련 산출물에 '재검토 필요'가 표시된다.
  - Given 입력이 바뀌어도, Then 기존 산출물이 자동 삭제되거나 전체가 이전 단계로 되돌려지지 않는다.

## EPIC-E. 수정 요청 라이프사이클

### US-E1 [목업] 수정 요청 상태 흐름
**As a** 리뷰어(P4), **I want** 수정 요청이 열림 → 수정 완료·확인 대기 → 리뷰어 확인 완료로 흐르게 하고 싶다, **so that** 제출만으로 차단이 풀리지 않는다.
- **관련**: FR-RR-1·2, FR-POL-4 / **AC**: AC-6
- **AC**
  - Given 작성자가 수정한 새 버전을 지정해 '수정 완료'를 제출하면, Then 상태는 '확인 대기'가 되고 차단은 유지된다.
  - Given 요청 리뷰어가 지정 수정 버전을 확인하면, Then 해결(또는 재오픈)된다. 제출자와 확인자는 구분된다.
  - Given 확인 대기 중 문서가 다시 바뀌면, Then 최신 수정 버전을 재확인해야 한다.

### US-E2 [목업] 수정 초안은 명시적 반영 필요
**As a** 개발자(P2), **I want** AI가 만든 수정 초안이 별도 문서 생성만으로 원본 수정 요청을 해결하지 않게 하고 싶다, **so that** 원본 반영이 명시적 행동을 거친다.
- **관련**: FR-RR-3, FR-AI-4 / **AC**: AC-7
- **AC**
  - Given 열린 수정 요청이 있어도, Then 수정 초안 생성 실행은 시작할 수 있다(교착 방지).
  - Given 수정 초안이 생성돼도, Then 원본의 새 버전으로 반영하는 명시적 행동 전에는 수정 요청이 해결되지 않는다.

## EPIC-F. 게이트·단계 전환·구현 인계

### US-F1 [목업] 결과 설명형 단계 전환
**As a** 리더(P5), **I want** 문서 탐색 클릭과 실제 단계 전환이 구분되고 전환 버튼이 결과를 설명하게 하고 싶다, **so that** 실수로 단계가 바뀌지 않는다.
- **관련**: FR-STG-4 / **AC**: —
- **AC**
  - Given 문서 트리에서 다른 단계를 클릭해도, Then 실제 단계는 전환되지 않는다.
  - Given 전환 버튼(`Construction 설계 시작`·`설계 승인 완료`)을 누르면, Then 동일한 전환 조건이 검사된다(드래그 제공 시에도).

### US-F2 [목업] 세 게이트의 조건 확인
**As a** 리더(P5), **I want** AI 실행·문서 승인·다음 단계/인계 게이트가 각기 다른 필수 조건을 검사하게 하고 싶다, **so that** 미충족 상태로 넘어가지 않는다.
- **관련**: FR-GATE-1·2·3 / **AC**: —
- **AC**
  - Given 각 게이트에서, Then 해당 필수 조건(§9)이 충족돼야만 행동이 활성화되고, 미충족 조건이 표시된다.

### US-F3 [목업] Git/PR 없이 구현 대기 도달
**As a** 리더(P5), **I want** Construction의 적용 설계 산출물이 모두 승인되면 Git/PR 없이 '구현 대기'가 되게 하고 싶다, **so that** 설계 완료가 구현 인계로 이어진다.
- **관련**: FR-STG-1, FR-GATE-3, FR-HANDOFF-1·2 / **AC**: AC-11
- **AC**
  - Given 단계 필수 산출물이 유효 최신 승인 + 필수 결정 완료 + 차단 요청 없음일 때, When '설계 승인 완료'를 누르면, Then SR이 '구현 대기'로 전환된다(Git/PR 불필요).
  - Given '구현 대기'에서, Then 승인된 문서 버전 + 확정 답변 묶음(읽기전용)과 참고용 Code Generation Plan(구분 표시)을 열람할 수 있다.

### US-F4 [목업] 리더 예외 진행 기록
**As a** 리더(P5), **I want** 게이트 미충족 시 예외 진행 사유·실행자를 기록하고 `예외 진행`으로 표시하고 싶다, **so that** 감사 가능하되 미승인이 완료로 바뀌지 않는다.
- **관련**: FR-GATE-4 / **AC**: —
- **AC**
  - Given 필수 조건 미충족 상태에서 예외 진행하면, Then 미충족 조건·사유·실행자가 기록되고 `예외 진행` 배지가 붙으며 미결정/미승인은 완료로 바뀌지 않는다.

## EPIC-G. 역할·승인 정책

### US-G1 [목업] 역할로 보기 전환
**As a** 목업 평가자(P6), **I want** '역할로 보기' 전환기로 역할별 가능한 행동이 바뀌는 것을 보고 싶다, **so that** 인증 없이도 역할 구분을 체험한다.
- **관련**: FR-ROLE-1·2, NFR-A11Y-2 / **AC**: (§5 역할 구분)
- **AC**
  - Given 역할을 전환하면, Then 그 역할이 할 수 없는 행동 버튼은 비활성화되고 사유가 표시된다.
  - Given 제출자와 확인자, 결정권자와 리뷰어는, Then 서로 다른 역할로 구분 유지된다.

### US-G2 [목업] 승인 정책 선택과 기록
**As a** 리더(P5), **I want** 전원/과반수/리더 승인 정책을 선택하고 요청별로 기록하고 싶다, **so that** 정책 변경이 과거 승인을 뒤바꾸지 않는다.
- **관련**: FR-POL-1·2·3 / **AC**: —
- **AC**
  - Given 정책 선택기에서 정책을 고르면, Then 요청에 적용된 정책과 리뷰어 집합이 기록된다.
  - Given 정책을 바꿔도, Then 과거 승인은 원 정책 그대로 보존되고 자동 전환되지 않는다.

## EPIC-H. 정보 배치 비교 (평가 여정 · §13)

### US-H1 [목업] 4종 전환 비교
**As a** 목업 평가자(P6), **I want** 공유 셸은 고정한 채 SR 상세 중앙 검토 영역만 4가지로 전환하며 비교하고 싶다, **so that** 어떤 배치가 과업을 가장 빠르게 만드는지 판단한다.
- **관련**: MK-1·2, NFR-VIS-1, Q1=A / **AC**: (§13)
- **AC**
  - Given 인앱 전환기에서 4종을 토글하면, Then 셸(보드·내 검토함·상단 고정 영역)과 가을톤 비주얼은 그대로 유지되고 중앙 배치만 바뀐다.
  - Given 각 변형에서, Then 동일한 시드 데이터·동일한 과업을 수행할 수 있다.

### US-H2 [목업] 두 핵심 과업의 속도 비교
**As a** 목업 평가자(P6), **I want** 각 변형에서 "지금 답할 질문 찾기"와 "이전 검토 이후 바뀐 것 확인" 과업을 수행해 보고 싶다, **so that** 배치별 효율을 근거 있게 비교한다.
- **관련**: MK-1, FR-UI-DETAIL, FR-REV-1 / **AC**: (§13)
- **AC**
  - Given 어떤 변형에서든, Then 상단 고정 영역(현재 작업·지금 필요한 행동·차단 이유)은 즉시 보인다.
  - Given 변형별로, Then "답할 질문"과 "변경 검토" 정보가 서로 다른 배치(예: 단일 컬럼 / 2-pane 비교 / 3-pane 콕핏 / 점진 공개)로 제시된다.
  - Given 새로고침 시, Then 데모 상태 초기화가 화면에 표시된다(MK-6).

## EPIC-I. 상태 표시·접근성 (횡단 관심사)

### US-I1 [목업] 색에 의존하지 않는 상태 전달
**As a** 목업 평가자(P6), **I want** 모든 상태가 텍스트+아이콘+숫자로 전달되게 하고 싶다, **so that** 색만으로 구분하지 않는다.
- **관련**: NFR-A11Y-1·3, FR-UI-STATE / **AC**: —
- **AC**
  - Given 검토 상태·AI 실행 상태·저장 상태 표시에서, Then 색 외에 텍스트/아이콘/숫자가 함께 쓰인다.
  - Given 라벨 텍스트가 11px 미만이던 곳은, Then 읽기 가능한 하한(~12px)으로 상향된다.

### US-I2 [목업] 키보드·반응형·상태 정의
**As a** 개발자(P2), **I want** 키보드 초점 이동·라디오/체크박스 선택·비활성 사유·반응형 서랍과 저장/불러오기/빈/오류 상태가 정의되게 하고 싶다, **so that** 좁은 화면·키보드 사용자도 과업을 완수한다.
- **관련**: NFR-A11Y-2, NFR-RESP-1, FR-UI-STATE, FR-SV-3 / **AC**: —
- **AC**
  - Given 키보드만으로, Then 주요 요소에 초점 이동·선택이 가능하고 비활성 버튼은 사유를 노출한다.
  - Given 좁은 화면에서, Then 보조 패널이 서랍/순차 보기로 전환된다.
  - Given 저장/불러오기 상황에서, Then 자동 저장·저장 중·저장 실패·미저장·빈 상태·연결 오류가 각각 정의·표시된다.
