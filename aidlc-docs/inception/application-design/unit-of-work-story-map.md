# PlanRepo 개발 단위와 스토리 검증 책임

버전은 0.1이며 **사용자 승인 완료**입니다. 승인된 `aidlc-docs/inception/plans/unit-of-work-plan.md`의 배정을 유지합니다. 스토리 구현 상태는 모두 미착수입니다. 이 표의 배정은 테스트 통과를 뜻하지 않습니다.

단위 정의는 `aidlc-docs/inception/application-design/unit-of-work.md`, 의존 관계는 `aidlc-docs/inception/application-design/unit-of-work-dependency.md`입니다. 모든 경로는 프로젝트 루트 기준입니다.

## 1. 추적 기준과 완료 판정

각 행의 원문은 `aidlc-docs/inception/user-stories/stories.md` 0.1의 같은 US 제목 아래에 있습니다. C1·C2 등의 표기는 그 스토리 안의 개별 수용 기준을 정확히 가리킵니다. SC 식별자는 같은 원문에 정의된 공통 기준이며 행마다 지정된 기준을 모두 적용합니다. 본문을 다시 요약해 원 수용 기준을 줄이지 않습니다.

주 서비스는 승인된 `aidlc-docs/inception/application-design/application-design.md`의 스토리 매핑을 유지합니다. 메서드와 자료형은 `aidlc-docs/inception/application-design/component-methods.md`에 있습니다. C-02의 조정·C-03의 정책·C-04의 저장과 해당 UI를 함께 검증하며, 한 주 서비스에 배정됐다는 이유로 지원 모듈 검증을 생략하지 않습니다.

모든 스토리의 개발·완료 책임 단위는 UOW-01입니다. 최종 검증 묶음은 B-01부터 B-06까지 중 정확히 하나입니다. 실제 기능은 앞 묶음에서 구현될 수 있습니다. 시작 조건용 가상 상태와 실제 쓰기·검토·전환·인계 경로를 구분하고 전체 수용 기준이 통과할 때만 스토리를 완료 처리합니다.

테스트 adapter는 실패·경쟁·교체 계약을 재현하며 첫 실제 연결인 Claude를 대신하지 않습니다. 도움말·버전 조회만으로 AC-17을 통과하지 않습니다. 특정 model ID의 지원·인증·실행 효과가 확인되지 않으면 추정하지 않습니다. 두 번째 실제 provider나 설정 UI를 필수 완료 조건으로 추가하지 않습니다.

취소 확정과 실제 프로세스 종료 확인을 구분합니다. 늦은 결과·종료 관찰은 이미 확정된 terminal 상태를 바꾸지 못합니다. 생성 성공·현재 입력과의 일치·사람 적용·공식 승인도 각각 확인합니다. 실제 AI가 막히면 관련 기준과 UOW 완료를 보류하고 실패·미검증 사유를 남깁니다.

저장·무효화·요청 승계·활동은 실제 저장 경계에서 검사합니다. 반영 확인 대기를 포함한 미해결 차단 수정 요청은 해결 확인 전까지 게이트를 막습니다. 비차단 요청이나 단순 revision 증가를 새로운 게이트 차단 조건으로 확대하지 않습니다.

이번 검증은 스토리·서비스·묶음·수용 기준 참조의 연결과 문서 일치를 확인합니다. 스토리 34개·개별 기준 122개가 실제 앱에서 통과했다는 뜻이 아닙니다. 코드·실제 생성·앱 테스트는 아직 실행하지 않았습니다.

단위 산출물 세 개를 검토·승인받아 Construction의 Functional Design을 시작합니다. Security Baseline·Resiliency Baseline·PBT는 비활성 상태로 개별 규칙 N/A입니다. 기본 제품 NFR과 행동 변경의 TDD는 유지합니다.
