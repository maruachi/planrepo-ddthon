상태: 승인된 분해 계획에 따라 작성. Units Generation 산출물 Q1 A 승인 완료. 모든 구현·수용 기준 검증은 미수행이다.

근거: [원본 스토리와 수용 기준](../user-stories/stories.md), [페르소나](../user-stories/personas.md), [요구사항](../requirements/requirements.md), [단위 정의](unit-of-work.md), [의존성·인계](unit-of-work-dependency.md), [승인된 분해 계획](../plans/unit-of-work-plan.md).

## 전체 배정

주 담당은 수용 기준 추적과 최종 통합 확인을 책임진다. 선행 단위의 준비 데이터 검증과 후속 단위의 실제 기능 연결을 구분한다. U1의 기반 완료만으로 여러 단위에 걸친 스토리 전체를 완료 처리하지 않는다. P-01은 계획 작성자, P-02는 같은 로컬 사용자가 전환하는 리뷰어 역할이다.

## 수용 기준별 검증 책임

AC 번호는 원본 스토리의 수용 기준 번호다. 아래 기준은 원문을 유지하며 검증 시점/담당만 덧붙인다. 단위의 코드 생성 계획에서 이 ID와 증거를 추적하고, 실제 구현·검증 이후에만 완료를 표시한다. 아래 35개 기준은 현재 모두 미검증이다.

### US-01 — SR 직접 생성

- US-01-AC1 · 검증 담당/시점: U1. 주어진 상황: Git·Jira가 연결되지 않은 로컬 앱. 수행 행동: 제목·요구 설명을 입력하고 생성. 관찰 결과: SR이 자체 저장소에 저장되고 SR 목록에 카드로 표시된다.
- US-01-AC2 · 검증 담당/시점: U1. 주어진 상황: 제목 또는 요구 설명이 비어 있음. 수행 행동: SR 생성 시도. 관찰 결과: SR을 생성하지 않고 빠진 필수 입력의 이유를 표시한다.
- US-01-AC3 · 검증 담당/시점: U1. 주어진 상황: 유효한 필수 입력. 수행 행동: 마크다운을 첨부하거나 첨부 없이 각각 생성. 관찰 결과: 두 경우 모두 생성할 수 있고 첨부 내용은 해당 SR 상세에서 확인할 수 있다.

### US-02 — 칸반 단계와 회차 확인

- US-02-AC1 · 검증 담당/시점: U3 (U1 기반·U2 상태 포함). 주어진 상황: 저장된 SR이 있는 보드. 수행 행동: 칸반 조회. 관찰 결과: SR 목록·요구사항 분석·Inception·Construction·구현 대기·구현 완료의 고정 열과 SR의 위치를 확인한다.
- US-02-AC2 · 검증 담당/시점: U2. 주어진 상황: Inception 또는 Construction에 있는 SR. 수행 행동: 같은 단계 반복 진행 후 카드 조회. 관찰 결과: 해당 단계의 회차 변화를 확인하며 반복마다 열이 추가되지 않는다. 숫자는 하위 stage 완료 개수와 구분된다.
- US-02-AC3 · 검증 담당/시점: U3 (U1 상세·U2 상태 포함). 주어진 상황: SR 카드. 수행 행동: 카드 선택. 관찰 결과: 상세에서 초기 입력과 연결 문서를 열 수 있고 리뷰 상태는 계획 단계와 별도로 확인한다.

### US-03 — 실제 AI로 계획 문서 생성

- US-03-AC1 · 검증 담당/시점: U2. 주어진 상황: SR 입력·첨부·기존 문서·관련 결정과 실행 준비된 CLI. 수행 행동: 다음 단계 진행 요청. 관찰 결과: 서버가 macOS의 실제 Claude Code CLI를 기존 인증으로 실행하며 AI-DLC 규칙과 해당 SR 문맥을 전달한다. 실행 전과 생성 중 상태가 구분된다.
- US-03-AC2 · 검증 담당/시점: U2. 주어진 상황: 문서 생성 성공. 수행 행동: 결과 열람. 관찰 결과: SR에 연결된 계획 문서와 성공 상태를 UI에서 확인하고 AI 생성 이력을 보관한다.
- US-03-AC3 · 검증 담당/시점: U2. 주어진 상황: 문서 생성 요청. 수행 행동: 실행 범위와 결과 확인. 관찰 결과: 모의 데이터만으로 성공을 대체하지 않는다. 생성은 코드 구현 직전 계획을 대상으로 하며 코드 구현을 자동 실행하지 않는다.

### US-04 — 문서 생성 실패 인지

- US-04-AC1 · 검증 담당/시점: U2. 주어진 상황: 생성 중인 SR에서 CLI 실행 실패. 수행 행동: 진행 상태 조회. 관찰 결과: 생성 중과 구분되는 실패 상태를 표시한다.
- US-04-AC2 · 검증 담당/시점: U2. 주어진 상황: CLI 실행 실패 후. 수행 행동: 문서와 완료 상태 확인. 관찰 결과: 실패한 실행을 성공한 문서 생성이나 단계 완료로 표시하지 않는다.

### US-05 — 질문 응답과 계획 결정 기록

- US-05-AC1 · 검증 담당/시점: U2. 주어진 상황: 질문이 필요한 AI-DLC 단계. 수행 행동: UI에서 질문을 확인하고 응답. 관찰 결과: 응답을 해당 SR의 진행 문맥과 이력에 보관하고 후속 진행에서 참조한다.
- US-05-AC2 · 검증 담당/시점: U2. 주어진 상황: 생성 문서가 있음. 수행 행동: 승인 또는 수정 요청 기록. 관찰 결과: 결정 종류·내용과 대상 문서 버전을 이력에서 식별한다.
- US-05-AC3 · 검증 담당/시점: U2. 주어진 상황: 문서 본문을 변경하지 않음. 수행 행동: 결정만 기록. 관찰 결과: 본문 변경이 없어도 결정 사건을 누락하지 않는다.
- US-05-AC4 · 검증 담당/시점: U3. 주어진 상황: AI-DLC 자체 승인이 필요한 단계와 별도 리뷰. 수행 행동: 피어 리뷰 결과 조회. 관찰 결과: 리뷰 결과와 단계 승인을 구분하며 피어 리뷰 완료만으로 AI-DLC 승인을 대신했다고 표시하지 않는다.

### US-06 — 저장 문서 다시 열기

- US-06-AC1 · 검증 담당/시점: U2·U3 연결 후 U1 확인. 주어진 상황: SR과 문서를 저장한 로컬 앱. 수행 행동: 다른 화면을 거쳐 해당 SR 다시 열기. 관찰 결과: 저장된 입력과 계획 문서를 다시 읽을 수 있다.
- US-06-AC2 · 검증 담당/시점: U2·U3 연결 후 U1 확인. 주어진 상황: Git을 연결하지 않음. 수행 행동: 저장 문서와 이력 조회. 관찰 결과: Git 연결이나 커밋 요구 없이 조회할 수 있다.

### US-07 — 계획 문서 편집

- US-07-AC1 · 검증 담당/시점: U1; U2 늦은 결과 추가 확인. 주어진 상황: 저장된 문서. 수행 행동: UI에서 내용을 수정하고 저장. 관찰 결과: 수정된 내용을 열람하고 사람의 수정 이력과 새 버전을 식별한다.
- US-07-AC2 · 검증 담당/시점: U1; U2 늦은 결과 추가 확인. 주어진 상황: 수정 전후 내용이 다른 문서. 수행 행동: 이전 버전 조회. 관찰 결과: 수정 전 내용도 유지되어 열람할 수 있다.

### US-08 — 문서와 결정의 이력 조회

- US-08-AC1 · 검증 담당/시점: U3 연결 후 U1 확인. 주어진 상황: AI 생성·진행, 사람 편집, 결정·수정 요청이 있는 SR. 수행 행동: 이력 조회. 관찰 결과: 모든 해당 사건이 남고 사건 종류와 관련 문서 버전을 구분한다.
- US-08-AC2 · 검증 담당/시점: U1. 주어진 상황: 여러 버전이 있는 문서. 수행 행동: 과거 버전 선택. 관찰 결과: 선택한 버전 내용을 볼 수 있다.
- US-08-AC3 · 검증 담당/시점: U2 연결 후 U1 확인. 주어진 상황: 본문 변화 없는 결정 또는 수정 요청. 수행 행동: 해당 사건 열람. 관찰 결과: 결정·요청 내용과 대상 문서 버전을 확인한다.

### US-09 — 두 문서 버전 비교

- US-09-AC1 · 검증 담당/시점: U1; U3 역할 연결 확인. 주어진 상황: 내용이 다른 두 버전. 수행 행동: 비교할 두 버전 선택. 관찰 결과: 선택한 버전의 식별 정보와 변경 내용을 확인할 수 있다.
- US-09-AC2 · 검증 담당/시점: U1; U3 역할 연결 확인. 주어진 상황: 문서 버전 이력이 있음. 수행 행동: 비교 후 원본과 이력 조회. 관찰 결과: 비교 동작이 원본 내용이나 저장된 이력을 바꾸지 않는다.

### US-10 — 과거 문서 내용 복원

- US-10-AC1 · 검증 담당/시점: U1. 주어진 상황: 현재와 내용이 다른 과거 버전. 수행 행동: 과거 버전 복원. 관찰 결과: 복원된 내용이 최신 문서에서 보인다.
- US-10-AC2 · 검증 담당/시점: U1. 주어진 상황: 복원을 수행한 문서. 수행 행동: 이력과 이전 버전 열람. 관찰 결과: 복원을 새 버전으로 기록하고 복원 전 최신 버전과 선택한 과거 버전도 유지한다.

### US-11 — 진행을 유지하며 리뷰 요청

- US-11-AC1 · 검증 담당/시점: U3. 주어진 상황: Inception 또는 Construction의 SR과 문서 버전. 수행 행동: 리뷰 요청. 관찰 결과: 카드는 기존 열에 남고 리뷰 상태 및 대상 버전을 별도로 확인한다.
- US-11-AC2 · 검증 담당/시점: U3. 주어진 상황: 리뷰가 미완료이고 AI-DLC 자체 진행 조건은 충족한 SR. 수행 행동: 다음 단계 진행. 관찰 결과: 리뷰 미완료만을 이유로 진행을 막지 않으며 리뷰 대상은 원래 버전으로 유지한다.

### US-12 — 대상 버전 검토 결과 기록

- US-12-AC1 · 검증 담당/시점: U3. 주어진 상황: 리뷰 요청이 있는 로컬 앱. 수행 행동: 리뷰어 역할로 전환해 대상 열람. 관찰 결과: 별도 로그인 없이 요청된 문서 버전을 읽고 검토할 수 있다.
- US-12-AC2 · 검증 담당/시점: U3. 주어진 상황: 대상 버전을 검토함. 수행 행동: 검토 결과 또는 수정 요청 기록. 관찰 결과: 내용과 대상 버전이 이력에 남고 작성자 역할에서 확인할 수 있다.
- US-12-AC3 · 검증 담당/시점: U3. 주어진 상황: 검토 대상 이후 새 문서 버전이 생성됨. 수행 행동: 기존 검토 결과 조회. 관찰 결과: 결과는 원래 버전에 연결되고 새 버전까지 검토·승인한 것으로 표시되지 않는다.

### US-13 — 계획을 구현 대기로 정리

- US-13-AC1 · 검증 담당/시점: U2; U3 완료 연결 확인. 주어진 상황: 코드 구현 직전 계획을 마친 SR. 수행 행동: 계획 종료 후 구현 대기로 이동. 관찰 결과: 구현 대기 열에 표시되고 준비한 계획 문서를 계속 열람할 수 있다.
- US-13-AC2 · 검증 담당/시점: U2; U3 완료 연결 확인. 주어진 상황: 구현 대기 전환 요청. 수행 행동: 전환 결과 확인. 관찰 결과: PlanRepo가 코드 구현·빌드·커밋·PR 생성을 자동 시작하지 않는다.

### US-14 — 외부 구현 완료를 수동 표시

- US-14-AC1 · 검증 담당/시점: U3. 주어진 상황: 구현 대기 상태의 SR. 수행 행동: 사용자가 구현 완료 처리. 관찰 결과: 카드가 구현 완료 열에 표시된다.
- US-14-AC2 · 검증 담당/시점: U3. 주어진 상황: Git·Jira·빌드 결과를 연결하지 않음. 수행 행동: 구현 완료 처리 결과 확인. 관찰 결과: 수동 전환이 가능하며 사용자의 선언으로 구분하고 자동 검증된 빌드 성공을 뜻하지 않는다.

## 통합 인수 순서와 완료 해석

1. US-01·US-02: SR 생성, 필수값/첨부, 보드·상세 확인.
2. US-03·US-05·US-02: 실제 CLI 계획 생성, 질문 응답·승인/수정 요청, 단계와 반복 회차 확인.
3. US-06–US-10: 저장 문서 재열람, 편집·사건·과거 버전·비교·새 버전 복원 확인. 본문 변화 없는 결정도 포함.
4. US-11·US-12·US-05: 리뷰 중 다음 계획 진행, 역할 전환, 원래 버전 결과, 이후 버전과 자체 승인 구분.
5. US-13·US-14: 계획 종료로 구현 대기, 외부 구현을 마쳤다는 수동 완료, 저장 내용 재열람 및 키보드 조작.
6. US-04: 별도 실제 CLI 실패 경로에서 성공/단계 완료로 오인하지 않는지 확인.

최종 Build and Test는 승인된 핵심 통합 흐름 하나와 CLI 실패를 확인한다. 위 수용 기준 배정은 모든 흐름의 자동화를 요구하지 않는다. 저장·버전·결정·실패처럼 오류 영향이 큰 계약은 단위 구현 때 필요한 집중 검증을 수행한다. 실제 CLI를 모의 결과만으로 대체하지 않는다.
