# PlanRepo 서비스와 처리 경계

버전은 0.1이며 **사용자 승인 완료**입니다. 서비스는 C-02 ApplicationServices 안의 논리 유스케이스입니다. 메서드와 자료형은 `aidlc-docs/inception/application-design/component-methods.md`, 구성요소는 `aidlc-docs/inception/application-design/components.md`, 전체 설계는 `aidlc-docs/inception/application-design/application-design.md`에서 확인합니다.

## 1. 공통 변경 처리

현재 가상 사용자·SR 배정과 명령 입력을 확인합니다. C-04의 변경 경계에서 현재 저장 상태를 읽고 WriteGuard를 검사합니다. C-03의 같은 정책으로 권한·업무 조건·검토 영향을 판단한 뒤 업무 변경, 불변 버전 추가, 현재 검토 참조, 미해결 요청 승계, 활동과 receipt를 함께 확정합니다.

이 흐름은 사용자 편집·질문 해결·결정 확정·AI 초안 적용·검토자 변경 등 모든 승인 기준 변경 경로에서 공유합니다. 저장한 뒤 나중에 승인 무효화를 전달하는 비동기 이벤트만으로 정합성을 보장하지 않습니다. 외부 AI·Mock 호출은 이 경계를 점유하지 않습니다.

새 요청과 동일 요청 재전송을 구분합니다. 같은 식별자에 다른 입력이면 충돌입니다. 과거 성공 receipt를 돌려줄 때도 현재 권한·기준·유효성을 표시합니다. 이미 무효한 게이트에서 현재용 전환·인계를 성공으로 표시하지 않습니다. 실패 시 일부 변경·무효화·활동만 남지 않도록 보장합니다. 구체적인 저장 기술·잠금·재시도 순서는 NFR Design에서 정합니다.

## 2. 서비스별 흐름

### S-01 WorkspaceService

**책임**: 한 팀·프로젝트와 가상 사용자 선택을 제공합니다.

**처리 흐름**: 조회 시 현재 프로젝트와 가상 사용자·연결 상태를 반환합니다. 사용자 선택값은 고정된 데모 사용자 목록에서 해석하고 역할은 서버의 현재 배정에서 읽습니다. 클라이언트가 만든 role·isAdmin 값을 채택하지 않습니다. 실제 조직 인증을 설계한 것으로 표현하지 않습니다.

**저장·정합성 경계**: 가상 사용자 선택의 보관 방식은 NFR Design에서 정합니다. 선택이 바뀌어도 과거 행동의 행위자를 바꾸지 않습니다.

**의존 구성요소**: C-03, C-04, C-09입니다.

**메서드**: M-001, M-002입니다.

### S-02 SRContextService

**책임**: SR 등록·가상 가져오기·원 설명·근거 확인을 관리합니다.

**처리 흐름**: 등록·Mock 가져오기는 필수 정보를 검증하고 최초 설명을 보존합니다. 동일 Jira 키의 재가져오기는 기존 SR을 안내합니다. 근거는 전달된 내용·링크·확인 여부를 저장하며 링크를 읽지 않고 내용을 추정하지 않습니다.

**저장·정합성 경계**: SR·근거 변경과 승인 기준에 대한 영향·활동·receipt를 같이 저장합니다. Mock 조회는 저장 경계 밖에서 끝내고 확정 시 중복 키와 현재 상태를 다시 확인합니다.

**의존 구성요소**: C-03, C-04, C-07, C-09입니다.

**메서드**: M-003, M-004, M-005, M-006, M-007입니다.

### S-03 QuestionDecisionService

**책임**: 답변·해결·후속 질문·결정 전환·확정·범위 분류를 분리합니다.

**처리 흐름**: 답변됨과 해결됨, 질문과 결정, 분류안과 지정 결정권자의 확정을 구분합니다. 후속 질문·결정 전환은 원 질문 연결을 유지합니다. 해결에는 근거·일관성·문서 반영 또는 변경 불필요 이유가 필요합니다. 현재 필수 사항을 후속 범위로 옮기려면 현재 구현 범위·완료 기준 변경과 필요한 재승인을 동반합니다. 이미 현재 범위 밖인 선택 항목의 분류까지 범위 변경으로 간주하지 않습니다.

**저장·정합성 경계**: 질문·결정 버전·범위 분류와 검토 영향·차단·활동을 함께 확정합니다. 전환된 문제는 중복 집계하지 않습니다. 다른 서비스의 적용 흐름에서 이 규칙을 사용할 때도 같은 트랜잭션을 공유합니다.

**의존 구성요소**: C-03, C-04, C-09입니다.

**메서드**: M-008, M-009, M-010, M-011, M-012, M-013, M-014입니다.

### S-04 ArtifactService

**책임**: 문서·계획과 버전·비교·AI 초안의 사람 적용을 관리합니다.

**처리 흐름**: 편집과 사람의 초안 적용은 새 문서 버전을 만듭니다. 계획에는 요구사항·완료 기준·작업·검증 방법의 연결을 보존합니다. AI 초안은 적용 직전 입력 fingerprint와 대상 버전을 검사합니다. 질문·결정 초안을 적용하면 미확정 항목으로 저장하고 S-03의 동일한 규칙을 사용합니다.

**저장·정합성 경계**: 새 내용·현재 참조·ReviewImpact·미해결 요청 연결·활동·적용 이력을 원자적으로 저장합니다. 오래된 결과는 재생성하거나 사람이 현재 입력과 비교한 새 초안으로 만들며 원래 실행 이력은 유지합니다.

**의존 구성요소**: C-03, C-04, C-08, C-09입니다.

**메서드**: M-015, M-016, M-017, M-018, M-019입니다.

### S-05 ReviewWorkflowService

**책임**: 공식 묶음·개별 승인·수정 확인·게이트·재검토를 관리합니다.

**처리 흐름**: requestReview는 불변 ReviewBundle을 만들고 현재 공식 검토로 지정하는 하나의 공개 행동입니다. 개별 승인에는 현재 묶음·지정 검토자·체크리스트가 필요합니다. 개별 승인은 단계 전환을 실행하지 않습니다. 수정 반영과 요청자·지정 검토자의 해결 확인도 별도입니다.

**저장·정합성 경계**: 묶음·현재 검토 참조·이전 검토 이력·현재 요청·미해결 차단 요청 승계를 함께 갱신합니다. transitionStage는 같은 저장 경계에서 현재 권한·버전·문서·질문·결정·수정 확인·전원 승인을 다시 검사합니다.

**의존 구성요소**: C-03, C-04, C-09입니다.

**메서드**: M-020, M-021, M-022, M-023, M-024, M-025, M-026, M-027, M-028입니다.

### S-06 ReviewPolicyService

**책임**: 정책 버전·SR 명시 적용·검토자 배정을 관리합니다.

**처리 흐름**: 새 팀 정책 생성과 기존 SR 명시 적용을 별도 명령으로 둡니다. 검토자 미지정 상태의 최초 배정을 지원합니다. 필수 검토자·적용 정책이 바뀌면 현재 묶음과 새 검토를 만듭니다. 팀 정책만 바뀌면 기존 SR에 소급하지 않습니다.

**저장·정합성 경계**: SR의 정책·배정·새 검토 기준·ReviewImpact·현재 요청·과거 이력 보존을 함께 확정합니다. G1 영향은 종속 G2까지, G2 전용 영향은 G2에만 적용합니다.

**의존 구성요소**: C-03, C-04, C-09입니다.

**메서드**: M-029, M-030, M-031입니다.

### S-07 GenerationService

**책임**: 고정 입력·생성 작업·결과 검사·취소·재시도와 초안을 관리합니다.

**처리 흐름**: 사용자 요청은 현재 입력과 ProviderSelection을 고정해 영속 대기 작업을 만듭니다. C-05가 내부 계약으로 작업을 인수하고 C-06을 호출합니다. 완료 시 작업 소유권·상태·출력 형식·참조를 검사해 초안을 저장합니다. 성공은 초안 생성 성공이며 적용·결정 확정·승인이 아닙니다.

**저장·정합성 경계**: 요청·인수·완료·실패·취소는 각각 짧은 저장 경계에서 확정합니다. 실제 외부 호출은 그 밖에서 실행합니다. 취소와 성공이 경합하면 먼저 확정된 terminal 상태를 뒤늦은 결과로 뒤집지 않습니다.

**의존 구성요소**: C-03, C-04, C-09입니다.

**메서드**: M-032, M-033, M-034, M-035, M-036, M-037, M-038, M-039, M-049, M-050입니다.

### S-08 HandoffImplementationService

**책임**: 유효 기준본 생성·내보내기와 외부 구현 사실을 관리합니다.

**처리 흐름**: createHandoff는 현재 G1·G2와 정확한 기준 참조를 읽고 고정된 인계 내용·Markdown을 만듭니다. previewHandoff는 그 기준과 현재 유효성을 보여줍니다. exportCurrentHandoff는 확정 시점에 현재 유효성을 재검사합니다. 외부 시작·완료는 요약·근거를 가진 수동 사실 기록입니다.

**저장·정합성 경계**: 인계 생성과 기준 고정·활동·receipt는 함께 확정합니다. 현재용 내보내기는 고정된 내용을 대상으로 유효성 검사·내보내기 확정을 같은 경계에서 처리합니다. 재검토 중 외부 완료 기록이 G1·G2를 복구하지 않습니다.

**의존 구성요소**: C-03, C-04, C-07, C-08, C-09입니다.

**메서드**: M-040, M-041, M-042, M-043, M-044입니다.

### S-09 WorkspaceQueryService

**책임**: 보드·검토함·상세·변경점·현재 기준과 과거 이력을 조회합니다.

**처리 흐름**: 보드·검토함·상세·활동은 C-04의 확정된 상태를 기준으로 읽습니다. 한 응답에 사용한 revision과 현재 검토 대상 참조를 반환합니다. 현재 할 일은 최신 묶음·배정·해결 상태로 구성하며 이전 요청은 이력으로만 보존합니다.

**저장·정합성 경계**: 초기 구성은 별도 비동기 검색 인덱스나 eventual-consistency projection을 필수로 두지 않습니다. 서로 다른 시점의 화면에는 revision을 표시하고 처리 뒤 같은 확정 상태를 다시 조회합니다. 과거 조회는 최신 승인·인계의 자격을 부여하지 않습니다.

**의존 구성요소**: C-03, C-04, C-08, C-09입니다.

**메서드**: M-045, M-046, M-047, M-048입니다.

## 3. 게이트와 재검토의 공통 계약

G1·G2 각 게이트에는 지정 검토자 전원의 현재 묶음 승인이 필요하고 담당자 외 동료가 최소 한 명 있어야 합니다. 검토자 부재를 완료로 표시하지 않습니다. 담당자가 지정 검토자이면 자신의 개별 승인을 기록할 수 있으며, 그것만으로 게이트를 통과하지 못합니다.

G2는 입력으로 사용한 승인 G1의 ID·버전을 고정합니다. G1 변경은 G1·종속 G2·신규 인계에 영향을 줍니다. G2 전용 변경은 G1을 유지합니다. 새 차단 문제나 필수 검토자·정책 적용 변경은 새 묶음·재승인을 요구합니다. 문제 해결이나 G1 재승인만으로 과거 G2 승인을 복구하지 않습니다.

미해결 수정 요청은 지속적인 ID를 유지합니다. 원 대상과 현재 연결 대상을 구분하고 새 문서·묶음으로 이어갑니다. 섹션 삭제 시 별도 목록에 남깁니다. 모든 미해결 요청을 보존하되 실제 차단 여부는 그 요청의 차단 속성으로 판단합니다. 비차단 요청을 섹션 삭제만으로 차단 요청으로 바꾸지 않습니다.

이미 해당 게이트를 통과한 SR만 그 검토 단계로 복귀합니다. 아직 통과하지 않은 SR은 현재 검토를 갱신합니다. 과거 승인·인계·외부 구현 사실은 계속 조회합니다. 상세 상태표와 각 변경 유형의 전이는 Functional Design에서 확정합니다.

## 4. 생성 작업의 실행과 격리

1. S-07은 현재 SR의 문서·질문·답변·결정·근거와 필요한 로컬 규칙을 각 상태·버전 그대로 명시적 입력으로 고정합니다. 미승인·미확정 자료도 생성 입력으로 사용할 수 있으며 승인·확인된 사실로 바꾸지 않습니다.
2. 요청 스냅샷·ProviderSelection·대기 작업·활동·receipt를 먼저 영속 저장합니다. 이후 설정 변경은 새 요청에만 적용합니다. C-02가 C-05를 직접 호출하지 않아도 C-05가 대기 작업을 찾아 실행할 수 있어야 합니다.
3. C-05는 S-07의 내부 claimRun 계약으로 실행 소유권을 얻습니다. ClaimedRun에 저장된 입력·provider·model 선택과 제한 실행 정책을 C-06에 전달합니다.
4. C-06은 provider 전용 출력·오류를 정규화합니다. S-07은 구조·작업 유형·필수 필드·참조 범위와 해당 실행 소유권을 검사합니다.
5. 정상 완료는 초안을 저장합니다. 현재 입력이 바뀌었다면 stale 속성을 표시하며 자동 적용하지 않습니다.
6. 사람의 적용은 S-04의 명령입니다. 현재 입력·권한·대상 버전을 다시 확인하고 업무 변경·필요한 무효화를 함께 저장합니다.

C-05는 실행 중 S-07의 readRunControl을 실행 소유권으로 조회하고 취소가 확정되면 해당 ExecutionControl에 신호를 전달합니다. 실제 종료를 확인한 뒤 recordExecutionTermination으로 관찰 정보를 남깁니다. terminal 상태에서도 같은 실행의 종료 관찰은 기록할 수 있으나 상태를 다시 변경하지 않습니다. 취소 상태의 확정과 프로세스 종료 확인은 별도 정보입니다. 취소를 확정한 실행은 늦은 성공 결과로 되살리지 않습니다. 성공이 먼저 확정된 실행에 취소를 요청하면 이미 종료된 현재 상태를 반환하며 새로 취소됐다고 표시하지 않습니다. 실행 중인 프로세스 종료·출력 상한·시간 제한·재시작 후 복구의 실제 방법과 수치는 NFR·Infrastructure Design에서 정합니다.

재시도는 현재 입력으로 새 runId를 만들고 이전 시도를 연결합니다. 앱이 재시작되어도 대기·진행 이력이 사라지거나 완료되지 않은 작업을 영구 실행 중으로 두지 않도록 복구 계약을 구현합니다. 복구를 구현했다는 주장은 실제 재시작 테스트 이후에만 합니다.

## 5. Claude 연결에서 확인한 사실과 검증할 사항

읽기 전용 `claude --help`에서 다음 의미를 확인했습니다. 실제 조합·인증·생성·차단 효과는 아직 실행하지 않았습니다.

| 도움말에서 확인한 옵션 | 설계에 적용할 구분 |
|---|---|
| --print, --output-format, --json-schema | 비대화식·구조화 출력의 후보입니다. 실제 출력 포장과 제품 스키마 검사는 별도로 검증합니다. |
| --model | 요청 model 설정 전달의 후보입니다. 기본 설정과 명시 ID를 구분하며 실제 model은 확인 가능한 정보만 기록합니다. |
| --tools "" | built-in 도구 제한입니다. MCP까지 차단했다고 간주하지 않습니다. |
| --strict-mcp-config | 다른 MCP 구성을 배제하는 후보입니다. 명시적으로 사용할 빈 구성의 유효성과 실제 미로딩을 검증합니다. |
| --no-session-persistence | Claude 세션 저장 제한의 후보입니다. 제품의 GenerationRun·적용·오류 이력 저장을 대신하지 않습니다. |
| --safe-mode, --restricted | 도구·설정·managed settings의 적용 범위를 별도로 확인해야 합니다. 단독으로 완전한 실행 격리를 보장한다고 표시하지 않습니다. |
| --bare | 도움말상 OAuth·keychain 사용이 달라집니다. 기존 설치 인증을 그대로 쓸 수 있다고 가정해 기본값으로 선택하지 않습니다. |

실행 파일은 PATH에서 찾고 사용자 입력으로 임의 실행 파일을 고르지 못하게 합니다. 본문은 stdin 등 명령으로 해석하지 않는 통로로 전달합니다. resume·continue로 다른 SR의 세션을 이어받지 않습니다. 실행마다 제품이 관리하는 별도 작업 문맥을 사용하며 주변 파일·개인 프로젝트 설정을 입력으로 자동 수집하지 않도록 설계합니다.

도구 제한, MCP 제한, 설정·hook·plugin 제한, 작업 폴더·세션·환경 구분을 각각 검증합니다. 도움말만으로 managed settings의 영향이나 옵션 적용을 증명하지 않습니다. 특정 옵션이 기존 인증을 바꾸거나 필요한 제한을 충족하지 못하면 우회·권한 확대를 기본 해결책으로 쓰지 않고 NFR·Infrastructure Design에서 지원 가능한 실행 정책을 정합니다.

인증 값을 읽어 문서·로그에 복사하거나 전역 설정을 변경하지 않습니다. 실제 실행 검증은 가상 자료만 사용하고 실행 정보·실패·제한의 근거를 남깁니다. 제한을 충족하지 못한 실행을 성공 경로로 열거나 Mock으로 숨기지 않습니다.

## 6. 인계의 확정 시점과 외부 사실

Handoff 생성 시 문서·결정·질문 결과·승인 참조와 검증 기준·후속 범위·workflowVersion을 고정합니다. 미리보기와 Markdown은 같은 인계 ID의 고정 본문을 사용합니다. 현재용 내보내기의 확정 경계에서 게이트와 참조 버전을 다시 검사합니다.

그 경계 전에 무효화가 확정됐으면 거절합니다. 이미 유효하게 확정해 전달한 바이트를 나중의 변경으로 회수한다고 보장하지 않습니다. 과거 인계는 이력으로 조회하고 현재 유효한 기준과 구분합니다. 외부 CLI·저장소·다운로드 파일을 자동 통제하지 않습니다.

외부 구현 시작에는 유효한 Handoff가 필요합니다. 완료 요약·PR 링크 또는 검증 결과 요약 등 외부 근거가 있으면 수동 사실을 기록합니다. 재검토 중에도 외부 완료 사실은 보존하며 정상 단계 완료와 현재 게이트 유효성을 혼동하지 않습니다. PlanRepo가 외부 테스트·배포를 자동 검증한 것으로 표시하지 않습니다.

## 7. 검증 배정

단위·계약 테스트는 같은 명령의 역할별 정상·거절, 버전 충돌·중복·저장 실패, 변경과 무효화의 원자성, 현재 검토 요청 승계를 확인합니다. 생성 계약은 테스트 adapter로 실패·취소·형식 오류·오래된 입력을 재현하고 실제 Claude 실행을 별도로 확인합니다. 최종 통합은 네 개 가상 SR의 전체 흐름으로 검증합니다.

프레임워크·DB 제품·실제 CLI 옵션 조합·제한 수치는 아직 확정하지 않았습니다. Security Baseline·Resiliency Baseline·PBT는 비활성 상태로 N/A이며 기본 NFR·TDD는 유지합니다.
